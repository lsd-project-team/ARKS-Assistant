# 点胶系统（`AKRS.ZX2200/DispenseSystem`）

> 点胶域（内部称「系统1 / System1」）：把胶水按配方图形点到/画到基岛焊点上，含点胶头运动、出胶控制、测高、胶量检测与画胶图形编辑器。
> 代码规模：62 个文件 / 13,395 行（不含 `*.Designer.cs`；另有 13 个 `*.Designer.cs` / 5,488 行、13 个 `.resx` / 1,801 行）

## 1. 模块定位

本模块是整机的**系统1（点胶平台）**实现。同一台机器上系统2 是固晶（`BondSystem/`）。两者通过 `MachineStateModel.CurrentMachineSystem`、`CurrentMachineSystemEnum.System1/System2` 区分（`Models/System1Domain.cs:49` 与 `BondSystem/` 下的 `System2Domain` 是并行结构）。

**职责边界**

| 本模块负责 | 不负责 |
|---|---|
| 点胶线程与动作节点链（定位→测高→点胶→胶量检测） | 产品/配方/工艺步骤配置（`ProductConfiguration`、`ProcessDomain` + `SingleProcessStep`） |
| 点胶头 XYZ/蘸胶 T 轴运动、ETEL/固高插补调用 | 轴驱动与运动控制卡（平台 `AKRS.Galaxy2.Drive.*`） |
| 点胶阀 IO 开关、武藏点胶器压力/真空设定 | 硬件抽象与寻址（`HardwareRepositoryService`） |
| 测量高度（探针/IO/激光三种） | 视觉算法与 PR 模板（`AKRS.Galaxy2.PR`、`VisionService`） |
| 画胶图形（胶路点集）的生成与持久化 | 视觉缺陷判定算法（`PostBondInspection.PostBondEpoxyCheck`，在 `BondSystem/`） |
| 预点胶（挤胶/擦胶/预点胶板打点） | 流道/载具搬运（`TransportSystem/`、`TransportUnitSystem/`） |

### 4.3 `InterpolationApplication` 内部（核心）

`Controllers/DispenseController.cs:300`。按代码顺序：

1. **点位换算**（`:314-333`）
   - `ConvertG0ToMachinePos(point)` → 机械坐标（`:314`）
   - `GetG0DispensePos(...)` → 相机位减针头偏移加 `DistanceInSensor`（`:317`，实现见 `:284`）
   - `DispenserMoveHelper.EpoxyPretreatment(epoxy, pos, angle)` → 归一化+旋转+平移（`:320`，实现见 `:327`）
   - Z 补偿：预点胶用 `PrePlantOffSetZ`，正常用 `OffsetZ`（`:323-330`）
   - `preDispenseHeight = Z + SecurityHeightForEpoxyApplication`（`:333`）

2. **每条胶路循环**（`:337`，`DispensePatternParas.Count` 条）

   3. **蘸胶前置**：`PrintEpoxy(epoxy)`（`:339` → `:675`），仅当 `IsSystem1ConfigPrintingTool && DispenserType==PrintingTool`

   4. **首条胶路 / 蘸胶头**（`:340`）：异步 `Task` 设定胶压（`:354-367`，`SetDispensePressure(DispensePressure, Vacuum)`，空跑模式跳过）→ `WaitSingleStep()` → `MoveToG0Pos3D(preDispensePos)` → `task.Wait()`
      非首条：`AxisZAbsoluteMove(preDispenseHeight)` + `AxisXYAbsoluteMove(第 0 点)`（`:393-399`）

   5. **提前开胶**（`:412`，条件 `AdvanceOpenDistanceNew != 0`）
      - `MoveAxisZToPositionWithoutDelay(interpolationPos.Z, SlowTravelSpeedBeforeDispensing)`（`:420`）
      - `while(true)` 轮询 `GetAxisPos().Z <= Z + AdvanceOpenDistanceNew` → `OpenDispensingElectric()`（`:426-437`，轮询间隔 `Thread.Sleep(1)`）
      - 否则直接 `AxisZAbsoluteMove(interpolationPos.Z, SlowTravelSpeedBeforeDispensing)`（`:445`）

   6. **到位等待/滞后开胶**（`:459`，条件 `DispenserLeadTime > 0`）
      - `IsDispenserLeadTimeOpen` 决定先开阀还是先关阀，然后 `Thread.Sleep(DispenserLeadTime)`（`:472`）

   7. **分流：单点 vs 插补**（`:480`）

### 5.7 算法与数据结构

- 胶路表示：`List<EpoxyApplicationLocation[]>`，**外层 List = 一条连续胶路（曲线），内层数组 = 该胶路上的点**。内层数组第 j 个点的 `Speed/Acc/Dec/OpenGlueFlag` 描述的是「第 j 点 → 第 j+1 点」这一段（见 `DispenseController.cs:563-571` 取 `[j-1]` 与 `:574` 取 `[j]`）

### 8.6 明确可判定的缺陷

1. **`DispenseMeasureHeightController.cs:102` 用错属性**：
   `if ((DateTime.Now - dateTime).Milliseconds > delay)` —— `TimeSpan.Milliseconds` 是**毫秒分量（0-999）**，不是总毫秒。`CylinderDelay` 默认 500，此判断会在耗时进入任意一秒的后半段（分量 > 500）时误判为"气缸打开失败"并弹报警。紧邻的关闭逻辑 `:141` 用的是正确的 `TotalMilliseconds`。**打开气缸的超时判断是坏的**。

2. **`System1Domain.cs:106-110` 屏蔽逻辑与调用方不一致**：`System1MatterVision` 里屏蔽判断的注释是「被屏蔽则不做」，但 `byMapping` 的语义（`:96` 参数说明「是否根据 Mapping 走」）与 `:106` 的使用对不上，调用方有的传 `false`（`UcEpoxyApplication.cs:847/859/872`）、有的用默认 `true`（`S1DispenseCorrectionActionNode.cs:73`），行为差异无文档。

3. **`DispenseWorkTask.cs:129-165` 的 `goto Finish` 跳转**：`IsDoWork()` 返回 `false` 时跳到 `Finish:` 标号（`:164`）执行 `FinishCurrentActionNode()`；而 `DoWork()` 返回 `Retry` 时走 `continue`（`:153`）**不**推进索引。这是"动作重入"的实现方式，但 `goto` 与 `continue` 混用，容易在改动时破坏重入语义。

4. **`DispenseController.cs:667` 异常返回 `ExcuteResult.Fail`**：`InterpolationApplication` 的 `catch` 把异常压成 `Fail`。调用方 `S1DispenseActionNode.cs:106` 收到非 `Success` 就返回 `Alarm`，最终 `DispenseWorkTask.cs:159` 触发 `Machine.Stop()`。异常信息只进了弹框，**未写日志**（对比 `DispenserMoveHelper` 注释掉的旧实现里有 `LogHelper.Post(Level.Error, ...)`，`DispenserMoveHelper.cs:304`）。
