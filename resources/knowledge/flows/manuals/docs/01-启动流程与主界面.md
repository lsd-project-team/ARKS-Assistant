# 启动流程与主界面（`AKRS.ZX2200/Program.cs`、`Main/Controls/`、`Localization/`）

> 软件入口、主窗体骨架、状态栏/功能区 UI 状态机，以及一套「基本处于半失效状态」的多语言机制。
> 代码规模：32 个文件 / 9,404 行（不含 `*.Designer.cs`）；含 Designer 为 47 个文件 / 17,716 行。另有 4 个翻译 JSON（177 行）。

## 1. 模块定位

本模块回答「软件从 exe 启动到主界面可用，中间做了什么」。

- **上游**：Windows / DevExpress / 加密狗 DLL（`SoftkeyManager`，位于 `libs/`）。
- **下游（被调用方）**：`Main/Machine/`（机器模型 `Machine`、`MachineStateModel`）、`Infrastructure/Controls/Currency/BaseControl`、各业务子系统的 `Controls`/`Controllers`。
- **职责边界**：
  - `Program.cs`：互斥体、DevExpress 皮肤/字体、未处理异常、加密狗、硬件初始化、Harmony 补丁、启动 `MainForm`。
  - `Main/Controls/`：主窗体 `MainForm`、主系统控件 `UcMainSystem`（11 个 partial 文件）、模组总览 `UcModule`、快捷菜单 `UcShortcutMenu`、若干小窗体。
  - `Localization/`：JSON 驱动的窗体控件文本翻译（**仅 4 个窗体接了翻译**，见第 8 节）。
  - `Main/VisionControl/`：软件版本号与版本更新公告（与视觉无关，仅命名空间叫 VisionControl）。

**不在本模块内**：机器状态机与流程调度在 `Main/Machine/`（见 `02-机器模型与流程调度.md`），本模块只是**消费** `Machine` / `MachineStateModel` 的公开成员。

## 5. 关键实现细节

### 5.1 `Program.cs` 里值得单独记的三件事

1. **Harmony 补丁**（`Program.cs:242-247`）：反射取 `Application` 的私有嵌套类型 `MarshalingControl` 的**无参私有构造函数**，用 prefix `HookMarshalingControl.OnActionExecuting` 拦截。`OnActionExecuting`（`:333`）判断 `ManagedThreadId != 1` 就写日志（原本的弹框报警被注释掉了，`:347-352`）。整段没有 try/catch，若该私有类型/构造函数不存在（.NET Framework 版本差异）会**在启动时抛 NRE 且不会被 4.1 里的异常处理器捕获**（此时 `Application.Run` 还没调用）。
2. **自动关闭 DevExpress 关于框**（`Program.cs:311-321`）：静态字段 `m_nWaitTime`(`:309`) 当计数器，`while (handle == IntPtr.Zero && m_nWaitTime <= 5000) { Thread.Sleep(1); ... }`(`:314-319`)，即最多约 5 秒。循环退出后**无条件**调用 `PostMessage(handle, WM_CLOSE, 0, 0)`(`:320`)——若窗口自始至终没出现，`handle` 仍是 `IntPtr.Zero`，等于向 0 号窗口投消息。两个小瑕疵：字段名 `m_nWaitTime` 装的是「轮询次数」而不是时间；`PostMessage` 的 P/Invoke 声明写成 `private static extern void PostMessage(...)`(`:307`)，user32 实际返回 `BOOL`。
3. **`SoftkeyManager.LockWorkStation` 的 DllImport 名字带尾随空格**：`[DllImport("user32 ")]`（`UcMainSystem.cs:1848`，注意 `user32` 后有一个空格）。两处锁屏按钮（`:1856`、`:2162`）都依赖它。

### 5.2 `UcMainSystem` 的跨线程模型

`UcMainSystem` 把「别的模块要操作主界面」这件事，统一做成**静态委托字段**（`UcmainSystem.Action.cs:91-161`）：`VmVisionShow`、`ChangeCameraVision`、`VisionAlarmFunc`、`ActiveReadBondForce`、`SensorAlarmAction`、`ReFreshSystem1TuAction`、`InputDebugAction`、`ShowForceRealTimeCurve` 等 15 个。

- 在 `InitAction()`（`:31`）里与实例方法挂钩；调用方直接 `UcMainSystem.VmVisionShow()`（如 `UcMainSystem.cs:568`、`UcShortcutMenu.cs:1151`、`:1190`、`:1208`）。
- 这些字段是 `static`，**多个 `UcMainSystem` 实例会互相覆盖**（`MainForm` 目前只创建 1 个，见 `MainForm.designer.cs:154-155`）。
- 方法体内普遍用 `this.Invoke(...)`（同步等待 UI 线程），只有 `ChangeCameraVisionByName` 用 `BeginInvoke`（`:324`）。因此**从工作线程调 `VmVisionShow()` 会阻塞到 UI 线程处理完**；若 UI 线程正好在等该工作线程，就会死锁。
- `VisionAlarm`（`:234` / `:273`）额外套了 `lock (AKRSMessageBoxExt.UiLock)`，并写 `AlarmLogEntity` 到数据库（`:258`、`:297`）。

### 5.3 DockPanel 管理

`UcMainSystem.ShowPanel(name, factory)`（`:431`）按控件名查找已有 `DockPanel`，找到就 `BringToFront` + 把宿主 `Form` 置前（`:437-448`），找不到才 `dockManager.AddPanel(...)`（`:453`）。
`UcModule.ShowPanel(name, factory, dockingStyle)`（`UcModule.cs:408`）是另一份**几乎同名但语义相反**的实现：已存在 `DockPanel` 时**什么都不做**（`:412-427` 的整个 `if` 分支体被注释掉，只剩空块），只有新建时才 `this.dockManager.AddPanel(...)` 并设 `dockPanel.Dock = dockingStyle`（`:432-435`）。两处 `GetDockPanel` 是逐字重复的代码（`UcMainSystem.cs:408` / `UcModule.cs:444`）——`UcModule.cs:403` 的注释 `todo:要不要放到公共类里面？` 正是这个问题的自认。同文件 `PeBondModule_DoubleClick`（`:390-399`）整个方法体被注释（原本要弹 `UcBondModuelSetting`），该入口实际已被 `GpBondModule_DoubleClick`（`:502-510`，仅在 `CurrentRole == RoleEnum.Admin` 时用 `FrmBear` 承载）取代。

### 5.7 版本公告

`VersionUpdateAnnouncement.VersionInfos`（`Main/VisionControl/VersionUpdateAnnouncement.cs:65-120`）是**硬编码列表**，最新一条 `1.4.0.0 / 2026-08-12`。`CheckVersionUpdate()`（`:33`）逻辑：

1. 读 `MachineSoftwareConfiguration.CurrentVersionNumber`；
2. 断言它必须等于 `Assembly.GetExecutingAssembly().GetName().Version`，否则弹「当前版本号与内置版本号不相同」（`:41-45`）——`Properties/AssemblyInfo.cs:31-32` 当前为 `1.4.0.0`，与列表最大值一致；
3. 若内置版本 > 设备记录版本，则刷新 `CurrentVersionNumber` / `LastVersionNumber` / `LastVersionUpdataTime` 并 `Save()`，再弹 `FrmVersionInfo`（`:50-59`）。

`VersionInfos` 里的日期（`2026,1,1` … `2026,8,12`）全部是**未来日期**，说明这是当前在用的版本序列。

## 8. 注意事项与风险

### 8.1 多语言机制：接线完整，但**实际上只覆盖 4 个窗体，且 Release 下整体失效**

核实结论（每条都在本项目内验证）：

1. **JSON 不在 csproj 中**。`AKRS.ZX2200.csproj` 里只有 `<Folder Include="Localization\Data\Common\" />`（`:3902`）和 `<Folder Include="Localization\Data\Forms\" />`（`:3903`），**没有任何 `Content`/`None` 项指向这些 `.json`**；也没有 PostBuildEvent 拷贝（全文 grep `PostBuildEvent`/`Copy` 无命中）。已核对 `bin/Debug/` 下确实没有 `Localization` 目录。
   → 运行时 `LocalizationCache.GetProjectRootPath()`（`LocalizationCache.cs:228`）从 `Application.StartupPath` 向上找 `*.csproj`/`*.sln`：**开发机**（`bin/Debug` 在工程目录下）能找到工程根，走源码路径 `Localization/Data`（`:212-218`）；**装机现场**找不到，只用 `Application.StartupPath/Localization/Data`（`:220-222`），而该目录不存在 → `HasFormTranslation` 恒返回 `false`（`:84-107`）→ `LocalizeForm` 直接 return（`FormLocalizer.cs:78-82`）→ **翻译静默失效**。
2. **`Localization/Data/Common/` 是空目录**，而 `LoadCommonTranslations`（`LocalizationCache.cs:342-370`）要找 `Common_UI.json` / `Common_Messages.json` → 永远只走 `Debug.WriteLine` 分支。`_commonCache` 在本仓库中恒为空。`GetCommonTranslation`（`:131`）因此从未返回过非 null。
3. **只有 4 处调用 `FormLocalizer.LocalizeForm`**：`UcMainSystem.cs:197`（构造）、`UcMainSystem.cs:1986/1989`（切语言时遍历）、`BondSystem/Controls/Manual/UcVacuum.cs:35`、`WaferSubSystem/Controls/Manual/UcComponentHandling.cs:84`、`Experiment/Test/FrmBaseTest.cs:115`。对应 4 个 JSON 文件，一一对应。**其余约千个窗体完全没有翻译**——但 Ribbon 的语言下拉框（`LueLanguage`）对所有用户可见并可切换。
4. 实现 `ILanguage`（`LocalizationManager.cs:167-170`）的也只有 `UcVacuum` 与 `UcComponentHandling` 两个（各自实现 `void GetUI()`）。
5. `LocalizationCache._translationBasePath` 在**单例构造时算一次**（`:39`），之后不再刷新；`LocalizationManager.Initialize(params string[])` 从没有调用方传过窗体名（只有 `EnsureInitialized()` 无参调用，`LocalizationManager.cs:41-47`）。
6. `FormLocalizer.LocalizeControlByTranslationKeys`（`FormLocalizer.cs:385-408`）是 **private 且无调用者**的死代码。
7. 切语言时只**覆盖**不**还原**：`ApplyTranslationToComponent` 直接 `property.SetValue`（`:338-358`），从 English 切回 Chinese 依赖 JSON 里同时有 `Chinese` 值（本项目 4 个 JSON 都双份，暂无问题）。异常全部被 `Debug.WriteLine` 吞掉（`:266-269`、`:354-358`），现场排查困难。

### 8.5 其他可疑点

- `MainForm.WindowsUIView_QueryControl`（`MainForm.cs:82-83`）用 `e.Document.ControlTypeName` 字符串反射建实例，无 try/catch；`UcHardareEditorDocument.ControlName` 拼写为 `UcHardareEditor`（`MainForm.designer.cs:168`，少一个 `w`），与 `ControlTypeName` 的 `UcHardwareEditor` 不一致。

- `MainForm.MainForm_Load` 在 `!AllAxisReset && !IsOffLineWork` 时直接把 `UcMainSystemTile.Enabled = false` 并 `return`（`:234-238`）——**在启动画面关闭之前**（`SplashScreenManager.ShowForm` 在 `:240`，即 return 分支不会显示启动画面），此时软件进入「主界面可用但硬件没初始化」的状态，无任何提示。
