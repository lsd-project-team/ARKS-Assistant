# 晶圆系统数据模型（`AKRS.ZX2200/WaferSubSystem/Models/`）

> 晶圆/华夫盒/料片/顶针/翻转工具的全部配置 DTO、晶圆图（WaferMap）的内存模型与磁盘格式约定。
> 代码规模：57 个文件 / 11,655 行（本目录无 `*.Designer.cs`）

## 1. 模块定位

本目录是**纯数据层**：只放类型定义、序列化容器与文件路径约定，不含流程调度、不含硬件动作、不含界面。它是 `Controllers/`、`Tasks/`、`Modules/`、`Controls/` 四层的共同数据基座。

按数据性质分四类，理解这四类是读懂本目录的前提：

| 类别 | 代表类型 | 生命周期 | 落盘方式 |
|---|---|---|---|
| **设备参数**（DeviceParam） | `WaferSubDevicePara`、`WaferTableDevicePara`、`EjectDevicePara` | 全局唯一，整机一份 | 单个 JSON，`SingletonJson<T>` |
| **配方数据集**（Repository） | `BaseCarrierConfig` 系、`EjectionConfig`、`FlipTool`、`AdapterConfig` | 命名实体列表，可增删 | 一个 JSON 存一个 `List<T>`，`BaseSettingRepository<T>` |
| **程式**（Program） | `WaferSystemProgram`、`MagazineBoxProgram`、`EjectionBankProgram` | 全局唯一，引用上面的具名实体 | 单个 JSON，`Singleton<T>` |
| **运行时内存模型** | `Block`、`WaferMapDataConfig`、`NineDie`、`Tablet` 系 | 随机台运行状态变化 | 部分随设备参数一起存，部分只存内存 |

**不存在数据库表**。全目录 57 个文件对 `DBService`/`SqlSugar` 的引用数为 **0**（grep 全目录无命中）。详见第 7 节。

上游：`BondSystem` 的取料/固晶流程消费 `BaseCarrierConfig`；`WaferSubSystem/Controllers` 消费 `WaferSubDevicePara`。
下游：本目录不主动调用任何控制器，仅 `WaferSystemDomain`（`WaferSystemDomain.cs:66`）例外——它是聚合门面，会调用控制器做初始化（`WaferSystemDomain.cs:112-136`）。

## 5. 关键实现细节

### 5.1 WaferMap 文件格式（★ 本篇核心结论）

解析代码**不在本项目源码中**，但磁盘上存有实际样本、解析日志和 DLL 的 XML 文档，三者可互相印证，格式已可完全确定。

**格式：纯文本 + `Key : Value` 头部 + 字符网格体**，CRLF 换行。实测样本 `WaferSubSystem/WaferMapFiles/Updates/2024-03-12/test1Map.AKRS`：

```
Wafer_ID :
Flat_Notch : Unknown
Bin Type : Char
Null Bin : .
Void Bin :  
                                     ← 空行分隔
.........11111.........
.......222222222.......
.....1111111111111.....
....222222222222222....
```

- 头部字段由 `AKRS.WM.WaferMapFileHead` 承载，其属性为 `WaferID` / `FlatNotch` / `BinType` / `NullChipType` / `Degree`（来源：`libs/AKRS.WM.WaferMap.xml` 的 `P:AKRS.WM.WaferMapFileHead.*`）。
- 网格每个字符 = 一颗 Die 的 Bin（等级）。`. ` = `Null Bin`（无芯片），空格 = `Void Bin`（空白/空洞），`1`/`2` = 实际 Bin 等级。
- 网格尺寸由 `WaferMap.RowCount` / `ColumnCount` 给出，数据存于 `Chip[,]`（`WaferMap` 的 `get_Item(Position)`、`Matrix`、`GetChip(int,int)`）。
- `BinType` 有四种取值，决定 Bin 的编码：`Char` / `Int16` / `Int16_Hex` / `Char_Int_Hex`（`libs/AKRS.WM.WaferMap.xml`，`F:AKRS.WM.BinType.*`）。**同一个「一行字符」的网格，Bin 实际是几字节取决于表头 `Bin Type`**。
- `Degree` 与 `WaferMapFileHead.FlatNotch` 描述晶圆旋转/缺口朝向；`WaferMapData.LoadWaferMapFile(path, RotationType, bool, bool)` 与 `WaferMap.Rotate(...)` 支持加载时旋转。

**本项目内可核实的解析契约**（`libs/AKRS.WM.WaferMap.xml`）：
- `AKRS.WM.WaferMap.WaferMapLoader.LoadFile(string)`、`ParseKeyValue(string, char, out string, out string)`、`Write(WaferMap, string)` —— 头部即 `Key : Value` 解析。
- `WaferMap.Save(string)` / `Save()` —— 回写同一格式。
- 异常类型 `AKRS.WM.NotStandardSyntaxWaferMapFile`（表头/网格不合语法）、`AKRS.WM.Parser.FileExtensionException`（扩展名不符）。

**扩展名与多格式导入链**（`WaferSubSystem/WaferMapFileParser/parser.log`，2021-04-28 ~ 2024-10-21 的真实运行日志）：

- 正式产物扩展名为 **`.AKRS`**（仓库内 6 个样本：`WaferMapFiles/Updates/2023-12-14/CPmap_topwafer.AKRS`、`2024-03-05/123.AKRS`、`2024-03-12/{CPmap_topwafer,test1Map,test2Map,test3Map,test4Map}.AKRS`）。
- 客户原始文件**无扩展名**，放在 `WaferMapFiles/Downloads/<日期>/<载具名>`（8 个样本）。原始文件表头是**另一套字段名**，实测 `Downloads/2024-03-05/123`：
  ```
  Lot ID : 202211111619
  Wafer ID : 1
  ProductID : T326
  Customer code :
  Mapping file : 202211111619-01
  Notch Side : Down
  ```
  与 `.AKRS` 的 `Wafer_ID / Flat_Notch / ...` 是**同构不同名**的两套方言，说明导入时存在一次**头部字段映射转换**。
- 解析器是**插件式、按序号版本化的 DLL 集合**：`WaferMapFileParser/` 下有 `AKRS.WM.FileParser.dll` 及 `AKRS.WM.FileParser1..74`、`93`、`94` 共 **80 个** `AKRS.WM.FileParser*.dll`。日志中的 `[Create Instance] AKRS.WM.FileParser9.dll` 字样表明**按序逐个反射实例化试探**，失败即换下一个。
- 依赖 **`Spire.XLS` / `Spire.Pdf`**（同目录）→ **Excel（.xls/.xlsx）与 PDF 格式的晶圆图也在支持范围内**；`AKRS.PDFConsumer.dll` 佐证 PDF 消费路径。
- 日志尾部（2024-10-21）大量 `invalid line which contains no separator` → 多数解析器是**按分隔符切行的文本解析**；`FileParser61` 抛 `FileExtensionException`。

**内存模型落点**：`AKRS.WM.WaferMap`（二维 `Chip[,]` + `WaferMapFileHead`）、`AKRS.WM.Chip`（一个 `ChipType`）、`AKRS.WM.ChipType`（`CharValue`/`IntValue`/`Value`）、`AKRS.WM.WaferMapData`（图 + 策略 + 参考点 + 颜色配置的聚合根）。

### 5.2 坐标系与单位：**mm / μm 双单位混用**（★ 高风险）

同一份数据在不同层用不同单位，换算点分散：

| 单位 | 用在哪 | 证据 |
|---|---|---|
| **mm** | 配方/设备参数 JSON（`AKRSPoint3D`）、`TreeProgramListArgs` 标注、`WaferMapDataConfig.StepPosition` 之类业务配置 | `UnitHelper.cs:11` 定义 `mm`；`CarrierWithWaferConfig.cs` 的 `WaferCenter`(mm)、`CarrierRowSpacing`(mm)、`CarrierColSpacing`(mm) 均标 `UnitHelper.mm` |
| **μm** | `AKRS.WM` 图模型内的 `Point` / `PhysicalCoordinates` / `ReferencePoint` 坐标 | `WaferSubModule.cs:51-58`：`PointConvertAkrsPoint3D` 做 `/1000`；`:64-67`：`AkrsPoint3DConvertPoint` 做 `*1000` |

本项目内的显式换算点：

- `Entities/SearchChip/Block.SearchMapping.cs:551-556` `SetWaferMapSpacing()`：
  ```csharp
  dieRowSize = new AKRSPoint3D { X = -CarrierRowSpacing.X * 1000, Y = -CarrierRowSpacing.Y * 1000 };
  dieColSize = new AKRSPoint3D { X = -CarrierColSpacing.X * 1000, Y = -CarrierColSpacing.Y * 1000 };
  WaferMapII.ChipOffset = new PhysicalChipOffset(dieColSize.ToPoint(), dieRowSize.ToPoint());
  ```
  **mm→μm（×1000）在此处发生，且同时取了负号。** 注意 `PhysicalChipOffset` 构造参数顺序是 **(colSize, rowSize)**，与阅读直觉相反。
- `Block.SearchMapping.cs:235`（参考点1）、`:333-334`、`:342-343`、`:437-438`：写回 DLL 前一律 `*= 1000`。
- `UnitHelper.cs:11` 有 `mm`，`:16` 有 `μm`，但**全目录的 `TreeProgramListArgs` 标注几乎只用 `mm`**——即参数界面显示的是 mm，图内部是 μm，两者靠上面几处手写 ×1000 衔接。

**结论：存在 mm 与 μm 两种单位混用，无统一单位抽象**。任何新增的坐标字段都必须先确认它落在哪一侧。未发现 pulse / encoder count 作为数据模型单位出现（脉冲量在驱动层，不在本目录）。

### 5.3 行列与 X/Y 轴的对应关系（★ 含一个反直觉约定）

两条独立证据都指向同一个结论：**Row/Column 索引增大，对应物理坐标减小**。

1. `Entities/AdapterSlotEntity.cs:43`（华夫盘槽位坐标）：
   ```csharp
   SlotPosition = FirstPosition
                - CarrierWithWaffleConfig.CarrierColSpacing * j   // j = 列索引
                - CarrierWithWaffleConfig.CarrierRowSpacing * i;  // i = 行索引
   ```
   行列索引增大 → 坐标**递减**。

2. `Entities/SearchChip/Block.SearchNine.cs:551-598`（九宫格相对偏移，以中心为原点）：
   - `UpDie` = center **+ `CarrierRowSpacing`**（`:559-560`）
   - `LeftCenterDie` = center **+ `CarrierColSpacing`**（`:571-572`）
   - `DownDie` = center **− `CarrierRowSpacing`**（`:589-590`）
   - `RightCenterDie` = center **− `CarrierColSpacing`**（`:577-578`）

   即命名上 **「上」= +行间距、「左」= +列间距**。配合 5.1 节「网格第 0 行在文件顶部」，可推出：**行索引沿 +Y 递减方向排列（第 0 行在最上），列索引沿 +X 递减方向排列（第 0 列在最右）**。

这与 `SetWaferMapSpacing()` 里给 `ChipOffset` 取负号（5.2 节）在符号上自洽。

**同时，`SingleSearchDirection` 的枚举描述（`Enums/EnumWaferSubSystem.cs:34-82`）给出的是「先走哪个轴」而非物理轴向**：
- `ToRightDown = 0` → 描述「从左往右，从上往下」（先列后行）
- `ToDownRight = 4` → 描述「从上往下，从左往右」（先行后列）

`ToRightDown` 与 `ToDownRight` 是**两个不同的枚举值但物理终点相同**，只差遍历次序。选错不会报错，只会改变取片路径。

> ⚠️ 上述「第 0 列在最右」是从两处代码符号推出的，没有找到直接的注释或文档确认。升级/换机型时**必须实机验证**，见第 8 节。

## 8. 注意事项与风险

### 8.1 【高】mm / μm 双单位混用，换算点分散且靠手写 ×1000

`Block.SearchMapping.cs:553-555` 一处、`:235`、`:333-334`、`:342-343`、`:437-438` 各一处，全部是裸 `* 1000` / `/ 1000`（`WaferSubModule.cs:51-67`）。没有单位类型、没有注释说明，新增坐标字段极易漏乘或多乘。`UnitHelper.cs:11,16` 同时定义了 `mm` 与 `μm`，但属性标注几乎清一色用 `mm`（显示层）——**标注与实际存储单位并不总是一致**。

### 8.2 【高】行列与 X/Y 的符号方向无文档，且命名易误导

- `Block.SearchNine.cs:559-578` 中「上」用 `+RowSpacing`、「左」用 `+ColSpacing`，与 `AdapterSlotEntity.cs:43` 的「索引增 → 坐标减」是同一约定的两种表述，但**代码里没有任何注释点明**。
- `SingleSearchDirection` 的 `ToRightDown`(0) 与 `ToDownRight`(4) 终点相同、次序不同（`Enums/EnumWaferSubSystem.cs:34-82`），选错不报错。
- 我在 5.3 节推出的「第 0 列在最右」是由两处符号**推导**得出，未见直接文档。**换机型或换相机朝向时必须实机验证。**

### 8.3 【高】Map 文件由闭源 DLL 解析，本项目无法自证格式

`WaferMapII.OpenFile`（`Block.cs:1244`）之后的一切都在 `AKRS.WM.WaferMapForm.dll` / `AKRS.WM.WaferMap.dll` 内。本项目**没有**该解析器的源码；`AKRS.ZX2200/libs/` 下 `AKRS.WM.WaferMap.pdb` 存在，可用单步调试观察。格式结论（第 5.1 节）来自样本文件 + `parser.log` + `AKRS.WM.WaferMap.xml` 三方印证，未通过实际运行验证。

### 8.4 【中】80 个版本化解析器 DLL，加载方式为逐个试探

`WaferSubSystem/WaferMapFileParser/` 有 `AKRS.WM.FileParser.dll` + `FileParser1..74`+`93`+`94`。`parser.log` 显示 `[Create Instance] ...` 后接异常——**逐版本反射实例化、失败即换下一个**。风险：(1) 每个失败的构造都会在日志里留一条完整 `FileNotFoundException` + 程序集绑定日志，日志膨胀（该文件已 254 KB）；(2) 新增客户格式必须**追加一个新序号 DLL**，编号语义（为什么是 93、94？是否与客户一一对应？）在本项目内无法确定；(3) 80 个 DLL 全部随包分发。
