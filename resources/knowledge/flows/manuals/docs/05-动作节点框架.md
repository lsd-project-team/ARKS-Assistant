# 动作节点框架（BondSystem/Models/ActionNodes）

> 固晶业务的骨架：每个工位动作被封装成 `ActionNode`，由 `BondTask` 线程按「展开后的消息列表」顺序逐个 `DoWork()`。
> 代码规模：37 个文件 / 13,427 行（范围 `AKRS.ZX2200/BondSystem/Models/ActionNodes/` 全部）
> 基类 `ActionNode` 本身不在本范围内，位于 `AKRS.ZX2200/Infrastructure/Models/CommonModels/ActionNode.cs`

## 1. 模块定位

本模块是**固晶区（System2）自动流程的唯一执行单元集合**。`BondTask` 工作线程（`AKRS.ZX2200/BondSystem/Tasks/BondTask.cs`）本身不做任何工艺动作，它只做四件事：等流道信号、从调度器取下一个节点、调用节点、把结果翻译成设备停止/重试。所有取片、点胶、蘸胶、上视纠偏、中转台纠偏、固晶、测高、身份识别、定位、焊后检测的**实际逻辑**都在本模块的节点类里。

- **上游**：`S2ActionNodeController`（`AKRS.ZX2200/Main/Machine/Process/S2ActionNodeController.cs`）负责把 `ActionNode` 展开成一层扁平的 `ActionNodeMessage` 列表并排序；`BondTask` 负责驱动。
- **下游**：`System2Domain` 下的各 `Controller`（`BondHeadController` / `BondModuleController` / `System2Controller` / `UpLookController` / `SlideFluxerController` / `IPTController`）、`BondModule`（`AKRS.ZX2200/BondSystem/Modules/BondModule.cs`）、`PickActionService` / `BondActionService` / `DipActionService`（参数装配）。
- **与硬件的关系**：节点不直接持有硬件对象，而是通过 `Controller` → `BondModule` → `HardwareRepositoryService.GetHardware<T>("名字")` 这条链路取轴/相机/IO。

## 4. 核心流程

### 4.1 一次固晶循环（BondTask 驱动）

```
BondTask.DoWork()                                 Tasks/BondTask.cs:100（工作线程体）
  → 等流道来料 GetIncomingSignal()                 Tasks/BondTask.cs:154
  → 温漂补偿 TpMarkCompensate / System2TemperatureCompensation / RealTimeCorrection
  → 注入制程 ActionNodesService.InjectSteps(...)   Tasks/BondTask.cs:193
  ┌─ while (Signal.WaitStart())                    Tasks/BondTask.cs:214   ← 循环条件即「停止/暂停」判据
  │   → GetNextActionNode()                        Tasks/BondTask.cs:216
  │   → if (actionNode.IsDoWork())                 Tasks/BondTask.cs:226
  │       → CloseDispenseCylinder(actionNode)      Tasks/BondTask.cs:230 → :495
  │       → actionNode.DoWork()                    Tasks/BondTask.cs:232
  │       → switch (ExcuteResult)                  Tasks/BondTask.cs:234-315
  │   → FinishCurrentActionNode()                  Tasks/BondTask.cs:319
  └─ 全部节点做完（GetNextActionNode 返回 null）→ break  Tasks/BondTask.cs:219-222
  → MoveToSafePos / Finish / NormalizationOffset / SendAway
```

`ExcuteResult` 的分支语义（`Tasks/BondTask.cs:234-315`）：

| 返回值 | 处理 |
|---|---|
| `Success` | 继续下一个节点 |
| `Abort` | `Machine.Stop()` + 焊头回安全高度 + 刮胶盘缩回 + `return`（退出工作线程） |
| `Retry` | `continue`——**不结束当前节点**，回到 `RetryCommand` 重新 `DoWork()` |
| `Exception` | 同 `Abort` |
| `Alarm` | 弹框：终止→`Stop()`+返回；重试→`goto RetryCommand`；忽略→继续 |

> `ExcuteResult` 与 `RunStateEnum` 定义在 `libs/AKRS.Galaxy2.Infrastructure.dll`（`AKRS.ZX2200.csproj:258`），源码不在本仓库，枚举数值无法从源码核实。

### 4.2 节点序列是怎么"拼"出来的（组合关系）

**没有 Composite 树、没有链表 `Next`、没有并行/条件/循环容器。** 组合方式是**一次性扁平化 + 顺序游标**：

```
① S2ActionNodeController 按工艺步骤构建消息序列
   S2ActionNodeController.GetActionNodeMessageByProcess()   Main/Machine/Process/S2ActionNodeController.cs:715
   → 按 BaseCarrierConfig.IsUseFlipTable × DipMode 选取节点名，逐个 new ActionNodeMessage(...)
     · IsUseFlipTable=true,  DipMode=AfterAccuracyMode  → Pick → UpLook → DipFlux → SubstrateCamera → Bond   (:731-765)
     · IsUseFlipTable=true,  DipMode=Off                 → Pick → UpLook → SubstrateCamera → Bond           (:766-792)
     · IsUseFlipTable=true,  DipMode=BeforeAccuracyMode  → Pick → DipFlux → UpLook → SubstrateCamera → Bond  (:793-826)
     · IsUseFlipTable=false                              → Pick → UpLook → SubstrateCamera → Bond           (:828-853)
     · DefectName != "Null"                              → 只加 AfterBondCheckActionNode                    (:855-863)
     · EpoxyNameApplicationName != "Null"                → 只加 S2DispenseActionNode                        (:864-871)
② 再按层级排序，插入定位/测高/身份识别
   ActionNodesSortService.SortBondPositionActionNode()   Infrastructure/Service/ActionNodesSortService.cs:25
   ActionNodesSortService.SortS2OtherActionNode()        Infrastructure/Service/ActionNodesSortService.cs:286
③ 运行期游标
   S2ActionNodeController.GetNextActionNode()            Main/Machine/Process/S2ActionNodeController.cs:1042
     → 遍历 WorkMessages，取第一个 !Finished 的
     → ChangeNameToActionNode(message)                   :1082  ← this.ActionNodes.Find(it => it.Name == name.ActionNodeName)
   S2ActionNodeController.FinishCurrentActionNode()      :1033  → CurrentBondActionNode.Finished = true
```

**所以"下一个节点"是「消息列表里第一个 `Finished==false` 的项」，节点对象本身是无状态的单例。**
`BondActionNodeRepository.ActionNodes`（`:34`）只是**名字到对象的字典**，顺序由消息列表决定。

### 4.3 回退/重做（唯一的「控制流」机制）

节点通过 `S2ActionNodeController.SetActionNodeReWork(List<ActionNode>)`（`:1099`）把**已经做完的节点消息重新置回 `Finished=false`**，从而让它们再次被执行。调用点（本项目内）：

| 触发场景 | 位置 | 重置的节点序列 |
|---|---|---|
| 固晶后吸嘴仍带料，「重新取贴」 | `BondActionNode.cs:273-288` | Pick → (UpLook 或 SubstrateCamera) → Bond |
| 中转台取片失败、抛料后 | `SubstrateCameraCorrectionActionNode.cs:476-479`、`:670-674` | Pick → SubstrateCamera（`DownLookVision` 那处还含 UpLook） |
| 上视定位失败（自动抛料 / 手动重取） | `UpLookCorrectionActionNode.cs:1453-1473`、`:1563-1583` | Pick → [DipFlux] → UpLook（按 `DipMode`） |
| 蘸胶后漏晶、抛料重取 | `DipFluxActionNode.cs:253-258` | Pick → UpLook |

配合 `System2RunTimeProvider.IsRepickComponent = true` 让下一次移动走"安全绝对运动"分支（`PickActionNode.MoveHelper.cs:380-386`）。

## 5. 关键实现细节

### 5.1 节点如何拿到硬件与 `Machine` 实例

节点**不接受任何构造参数**（`ActionNode` 只有 `protected ActionNode()`，`ActionNode.cs:19`），全部靠**属性表达式即取即用**的单例门面：

```
节点
 ├─ System2Domain.GetInstance()            → BondSystem/Models/System2Domain.cs
 │    ├─ .ActionNodesService    : S2ActionNodeController      （当前芯片/焊点/基岛/制程名）
 │    ├─ .BondHeadController    /  .BondModuleController  /  .System2Controller
 │    └─ .UpLookController / .SlideFluxerController / .IPTController / .S2DispenseController
 ├─ System2Module.GetInstance().BondModule.BondHead.AxisZ.AxisDrive is ETELAxis     ← 运控厂商判据
 ├─ BondDevicePara.GetInstance() / WaferSubDevicePara.GetInstance() / BondProgram.GetInstance()
 └─ Machine.GetInstance().IsStop() / .Stop() / .Pause()        Main/Machine/MachineSupport/
```

`Machine` 是 `partial class Machine`（`AKRS.ZX2200/Main/Machine/MachineSupport/Machine.cs`，状态相关实现在 `Machine.StateRelated.cs`），`IsStop()` 就是 `MachineStateModel.GetInstance().MachineState == MachineStateEnum.Stop`（`Machine.StateRelated.cs:34-37`）。

`BondModule`（`BondSystem/Modules/BondModule.cs:36`）是**硬件名的集中地**，成员本身是 `HardwareRepositoryService.GetHardware<T>("名字")` 的惰性属性，例如 `BondAxisX => GetHardware<Axis>("BondX")`（`:42`）、`BondCamera => GetHardware<AKRSCamera>("BOND相机")`（`:104`）。所以节点里写 `new BondModule()`（`UpLookCorrectionActionNode.cs:129`、`BondActionNode.MoveHelper.cs:42`、`SubstrateCameraCorrectionActionNode.MoveHelper.cs:43`）**不会**复制硬件，只是拿一个转发门面。

本范围内**唯一**直接访问硬件仓库的地方是 Jump（插补）运动前找插补卡：

```csharp

    card => card.AxisList.Select(axis => axis.AxisDrive).Exists(
```

### 5.2 节点名是字符串契约

`Name` 既是调度键也是重置键：

- 对象注册：`BondActionNodeRepository.cs:59-250` 里硬编码 `Name = "PickActionNode"` / `"UpLookCorrectionActionNode"` / `"SubstrateCameraCorrectionActionNode"` / `"BondActionNode"` / `"DipFluxActionNode"` / `"AfterBondCheckActionNode"`（注意这里的 `Name` 是 `"PostBondInspection"`，`:107`，与其他节点命名风格不一致）/ `"BondCarrierVision"`（`:112`）/ `"BondSubstrateVision"`（`:117`）/ `"BondIslandVision"`（`:122`）/ `"S2DispenseActionNode"` / `"S2PreDispenseActionNode"` / `"S2XxxMeasureHeightActionNode"` / `"S2XxxIdentityActionNode"` / `"CheckInkDotActionNode"`。
- 名字查找：`S2ActionNodeController.cs:1084` `this.ActionNodes.Find(it => it.Name == name.ActionNodeName)`，**找不到返回 `null`**，随后 `DoWork()` 会直接 `NullReferenceException`。
- 名字硬编码比较：`S2ActionNodeController.cs:1056` 对 `"UpLookCorrectionActionNode"` / `"SubstrateCameraCorrectionActionNode"` 做重复检测并抛 `Exception("……重复")`。
- 重置时若消息不存在：`S2ActionNodeController.cs:1111` 抛 `Exception("ActionNode Sort Error")`。

### 5.3 节点的「参数」定义与持久化

**节点对象本身几乎不带可调参数。** 持久化在节点上的只有三项，且都是**代码里写死的**：

| 属性 | 谁写 | 是否持久化 |
|---|---|---|
| `Name` | `BondActionNodeRepository.cs:59-250` 硬编码 | 否 |
| `ActionLevel` | 同上 | 否 |
| `IsCloseCylinder` | 同上（9 个节点设为 `true`，`:140/158/169/180/191/204/215/226/237`） | 否 |

`BondActionNodeRepository` 在 `System2Domain` 里是 `[JsonIgnore]` 属性，直接 `new` 出来（`BondSystem/Models/System2Domain.cs:142-143`），**不落盘、不从 JSON 读**；构造函数参数 `List<string> processStepNames`（`BondActionNodeRepository.cs:26`）在函数体内**完全未被使用**，实际调用处传的是空列表（`System2Domain.cs:143`）。

### 5.4 停止语义（本项目实际判据）

**本项目不用 `CancellationToken`、不用 `IStatus.IsStop()` 接口轮询。** 实际有**两种**机制：

**(a) `Signal.WaitStart()` —— 静态方法，读全局状态机**

```csharp
// AKRS.Galaxy2.Machine/Models/Signal.cs:202
public static bool WaitStart()
{
    if (MachineStateModel.GetInstance().MachineState == MachineStateEnum.Stop)  return false;   // :211-214
    while (MachineStateModel.GetInstance().MachineState == MachineStateEnum.Pause)              // :217
    {
        if (MachineStateModel.GetInstance().MachineState == MachineStateEnum.Stop) return false; // :219-222
        Thread.Sleep(20);                                                                        // :224
    }
    return true;
}
```
语义：**`Stop` 返回 false，`Pause` 原地阻塞 20ms 轮询直到恢复或转 `Stop`**。

调用点（本范围内）：

| 位置 | 用途 |
|---|---|
| `Tasks/BondTask.cs:214` | 整个节点循环的条件 `while (Signal.WaitStart())`——**最外层停止/暂停闸门** |
| `PickActionNode.cs:470` | 「这里阻塞是为了防止点暂停的时候晶圆台移动」（注释原文） |
| `PickActionNode.MoveHelper.cs:862` | 空跑模式下同样的闸门 |
| `S2DispenseActionNode.cs:66`、`:77` | 点胶前、预点胶后各判一次，返回 `ExcuteResult.Fail` |

**(b) `Machine.GetInstance().IsStop()` —— 单点检查**

```csharp
// AKRS.ZX2200/Main/Machine/MachineSupport/Machine.StateRelated.cs:34
public bool IsStop() { return MachineStateModel.GetInstance().MachineState == MachineStateEnum.Stop; }
```
调用点（本范围内，共 5 处）：

| 位置 | 说明 |
|---|---|
| `SubstrateCameraCorrectionActionNode.cs:209` | 去中转台完成后 |
| `SubstrateCameraCorrectionActionNode.cs:232` | 放片后 |
| `SubstrateCameraCorrectionActionNode.cs:257` | 去下视拍照位后 |

节奏是**「每完成一个耗时段落就查一次」**，不覆盖运动过程本身。长的循环等待用 `Thread.Sleep` 轮询 `MachineStateEnum`，例如 `PickActionNode.Provider.cs:584-591`（给翻转台发信号，`Pause` 时重置计时、`Sleep(20)`）、`PickActionNode.MoveHelper.cs:910-917`。

### 5.5 超时与异常处理

**超时**：只有「等 Z 轴到安全高度」「等 XY 接近目标位」这类**轮询等待循环**有超时，统一是 `Stopwatch.Elapsed.TotalSeconds > 10` → `return ExcuteResult.Exception`：

| 位置 | 等待什么 | 阈值 |
|---|---|---|
| `UpLookCorrectionActionNode.cs:1900`、`:1933`、`:1955` | Z 到目标高度 / Z 到安全高度 / XY 接近目标位 | 10 s |
| `PickActionNode.MoveHelper.cs:716`、`:740` | Z 到安全高度 / XY 接近目标位 | 10 s |
| `BondActionNode.MoveHelper.cs:99`、`:130` | 同上 | 10 s |
| `PickActionNode.Provider.cs:919` | 给翻转台发信号（`DateTime.Now - startTime > TimeSpan.FromSeconds(10)`） | 10 s |

运动本身（`MotionService.WaitAxesArrival(...)`，如 `UpLookCorrectionActionNode.cs:1964`、`PickActionNode.MoveHelper.cs:775`）**没有超时参数**，只有到位精度 `AccuracyMode.HighAccuracy`。

**异常**：分三层，**并没有吞异常**，但处理方式不统一：

1. **最外层 `DoWork()` 统一兜底**（几乎每个节点都长这样，例如 `BondActionNode.cs:366-371`、`PickActionNode.cs:503-508`、`UpLookCorrectionActionNode.cs:503-508`）：
   ```csharp
   catch (Exception ex)
   {
       LogHelper.Post(Level.Error, $"流程{this.Name}运行故障", ex, LogCategory.Bond);
       AKRSMessageBoxExt.Show(ex.Message, "Exception", ...);   // ← 自动流程里弹模态框
       return ExcuteResult.Exception;
   }
   finally
   {
       this.State = RunStateEnum.Stop;
       this.WorkStop?.Invoke();
   }
   ```
   **`State = Running` 只在 try 之前设**，`finally` 里必定写 `Stop`。
2. **内层方法记日志后 `throw`**，由外层接住：`PickActionNode.cs:668-693`（`Pick()` 捕获 `NullReferenceException` 单独处理再 `throw`）、`PickActionNode.MoveHelper.cs:326-337`（捕获 `DsaException` 后 `throw`）、`SubstrateCameraCorrectionActionNode.cs:756-768`（`throw ex;`——**丢失原始堆栈**）。
3. **视觉定位失败不抛异常，走专门的对齐弹框**：`UcMainSystem.VisionAlarmFunc(pREntity, name, msg)`（`UpLookCorrectionActionNode.cs:1488`、`SubstrateCameraCorrectionActionNode.cs:582`）或 `VisionAlarmLockFunc`（`AfterBondCheckActionNode.cs:385`），返回 `Abort / Retry / Ignore / OK` 再由节点翻译成 `ExcuteResult`。

**视觉节点特有**：`VmException`（海康 VM SDK，`using VM.PlatformSDKCS;`）被单独 catch，只弹 `AKRSXtraMessageBox` 然后返回 `Exception`，**不写日志**（`S2ModuleVisionActionNode.cs:78-83`、`S2SubstrateVisionActionNode.cs:77-81`、`BondPositionVisionActionNode.cs:82-86` 等 6 处同型代码）。

**自动重取上限**：上视定位失败时，若 `component.UpLookAutoSkipTimes != 0 && System2RunTimeProvider.UpLookAutoSkipCount < 该值`，自动抛料重取并 `return (ExcuteResult.Retry, null)`，否则弹框（`UpLookCorrectionActionNode.cs:1413-1483`）。
