# 料单元系统 - 界面层（`AKRS.ZX2200/TransportUnitSystem/Controls/`）

> 料单元（载具 / 基板 / 基岛 / 焊点）的全部 WinForms 界面：手动操作、示教向导、Mapping 图、参数配置。
> 代码规模：38 个文件 / 12,314 行（不含 `*.Designer.cs`；另有 36 个 Designer 文件、34 个 `.resx`）
>
> 📌 **配套文档**：`31-料单元系统全景与流程图.md` 是同一目录的**图解版**（25 张 Mermaid 流程图）；`43-料单元系统按钮与交互流程详解.md` 是**按钮逐条详解版**（243 个处理器）。本篇讲**每个窗体有哪些控件、触发哪些事件**；`31` 讲**这些事件背后的完整调用链与落盘链路**；`43` 把**每一个按钮**从入口一路画到最终效果（含校验失败 / 异常 / 用户取消 / 重入分支）。排查"这个按钮绑的是谁"看本篇，排查"流程为什么没走到"看 `31`，排查"这一点下去具体改了哪个文件、落没落盘"看 `43`。

## 5. 关键实现细节

### 5.1 示教向导的统一模式：`AssistantConfig` 步骤表

本层 11 个示教窗体复用同一套模板（`AssistantConfig` 定义在 `Infrastructure/Models/CommonModels/AssistantConfig.cs:28`，不在本范围内）：

- 一个 `List<AssistantConfig> assistantConfigList` 字段，每个元素携带 `Index` / `Descritpion` / `IsShowTitle` / `IsShowBack` / `IsShowNext` / `IsShowDone` 和三个 `Action`（`BackAction` / `NextAction` / `DoneAction`）。
- `SetUiControl()` 把当前步的描述与按钮可见性刷到 UI，并把 `TileBarTeach.SelectedItem` 指向 `tileBarGroupN.Items[stepIndex]`。
- 步骤里的 `NextAction` 负责"记录当前点位"，`DoneAction` 负责"记录 + 计算 + Save + 关闭"。
- 每次调用都 `new UcGuideMove("窗体名")` + `CommonHelper.ChangeUcMove(ucGuideMove, CurrentMachineSystem)` 挂到 `PnlControl`，`FormClosed` 里 `ucGuideMove?.Dispose()`。

**设计器 UI 项在运行时删除**是本层反复出现的做法，因为多个窗体共用了同一套 TileBar Designer 定义：

| 位置 | 行为 |
|---|---|
| `Assistant/FrmEditPRs.cs:284-308` | 按 `AdjustType` 单向点/两点/三点裁剪 `Items.RemoveAt(3/2/1)` 与 `assistantConfigList.RemoveAt` |
| `TransportUnitEdit/FrmAssistantHeight.cs:45-46` | 构造函数里 `tileBarGroup2.Items.RemoveAt(0)` 连删两次 |
| `TransportUnitEdit/FrmAssistantSizeAndCenter.cs:275-278` | 非 TU 时 `RemoveAt(2)`，前一步改为 Done |
| `Assistant/ModuleTeach/FrmModulePositionTeach.cs:472-475` | `Configurable` 时 `while (Items.Count > 4) RemoveAt(4)` |

### 5.2 绘图：全部是 GDI+ 手绘，不用图表控件

- `UcTransportShow`（`Mapping/UcTransportShow.cs`）：`PlControl_Paint`（:508）里按"主框架 → X/Y 刻度 → 基板 → 基岛 → 焊点 → 选中框 → 索引文字"顺序绘制。坐标变换用 `Graphics.TranslateTransform` + `ScaleTransform`（:523-524），滚轮缩放范围钳制在 `[0.1, 10]`（:368），双击复位（:737）。
- 焊点着色逻辑在 `PaintBondPosition`（:278-349），5 个分支：`Disable`→黑、`EnableInSystem1`（仅非实物载具）→`Cyan`、`EnableInSystem2`→`Crimson`、已在此系统完成→`Green`、其它→`BurlyWood`。
- 实体归一化统一走 `TuService.PointFNormalization(...)`（:248、:291；`MappingDraw.cs:127`）。
- `UcTransportUnitView`（`TransportUnitEdit/UcTransportUnitView.cs:255`）在**每次 Paint 里**重算 `OppositeSexConfiguration.InitOppositeSexConfigPosition()` 和 X/Y 包围盒来求 `ratioX/ratioY`（:261-277），即布局不做缓存。
- `MappingDraw` 用 `ControlPaint.DrawReversibleFrame` 画橡皮筋选择框（`MappingDraw.cs:395`）。

### 5.3 框选判定

`UcTransportShow.IsInSelectedArea`（:675-678）只判断**选区是否跨过实体中心点**：

```csharp
return maxX > baseMatter.Rectangle.X && minX < baseMatter.Rectangle.X
    && maxY > baseMatter.Rectangle.Y && minY < baseMatter.Rectangle.Y;
```

被注释掉的旧实现（:670-673）才是按半宽/半高完整包含判断。`MappingDraw.ChooseEntityByRectangle`（:285-305）则用另一套逻辑，且第二个 `else if` 分支的条件（`:297-300`）在数学上难以同时成立（`X < start.X - W` 且 `X > end.X`，配合 `Y` 的镜像条件），实际只对反向拖拽的极端情形生效。

### 5.4 状态监视：WinForms `Timer`，无跨线程

本范围**没有任何** `Invoke` / `BeginInvoke` / `InvokeRequired` / `SynchronizationContext` / `Thread.Sleep` / `Task.Delay`。唯一的周期刷新是：

```csharp
// Setting/UcTransportUnit.Designer.cs:698-700
this.timer1.Enabled = true;
this.timer1.Interval = 300;
```

## 8. 注意事项与风险

### 8.1 硬编码绝对路径

```csharp

    "D:\\ZX2200存储数据\\" + MachineConfigContext.GetInstance().RecipeName + "//" + id + ".txt");
```

### 8.8 存疑，未在代码中得到解答

1. **`FrmTuMappingNew` 与 `FrmTuMapping` 的分工**。两者由 `UcMainSystem.cs:1030/1041` 按 `TransportUnitConfig.UseNewMappingUi` 二选一。新版的 `FrmTuMappingNew` 只有作业顺序/蛇形排列/清空，**没有** `FrmTuMapping` 的三级 Tab 与右键改制程状态；但它的 `UcTransportShow` 用单参构造（`IsRealTu = false`，`UcTransportShow.cs:68-79`）又保留了右键菜单（`popupMenu1.LinksPersistInfo.RemoveAt(2)` 只摘掉一项）。两者功能是否等价、`UseNewMappingUi` 该取什么值，代码里没有说明。

4. **"保存到哪"的最终答案在平台层**。本层只调用 `ProductConfiguration.GetInstance().Save()` / `productConfig.Save()` / `VisionEntityRepository.GetInstance().Save()` / `OtherConfig.SaveInformation(...)`，具体文件路径（是否为 JSON、是否按配方分目录）由 `AKRS.Galaxy2.*` 实现，本范围内不可见。**唯一能确认的硬编码路径是 8.1 的载具 Mapping 文本**。
