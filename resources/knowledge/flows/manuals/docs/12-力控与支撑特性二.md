# 力控与支撑特性二（BondSystem/BondForce · SupportFeature/Compensate · SupportFeature/Statistics · SupportFeature/Consumables · SupportFeature/TemperatureMonitoring）

> 覆盖焊头压力采集与力控、标定/去皮、位置与热漂补偿、产能与良率统计、耗材寿命、温度监控六块支撑特性。
> 代码规模：54 个文件 / 10,303 行（不含 `*.Designer.cs`；逐文件实测汇总，任务书给出 10,316，差 13 行，疑因统计口径不同）

## 1. 模块定位

本模块是固晶机的**工艺执行支撑层**，不含运动规划与动作状态机，只做五件事：

1. **力控**（`BondSystem/BondForce/`）：焊头 Z 轴在"下压到焊点"阶段由位置闭环切换为**压力闭环**，把设定力（克）下发到固高卡，并把 ADC 原始值换算成克回读。本目录**只装标定、配置、DTO、Modbus 与配置界面**；真正的力控算法与固高 API 调用在 `BondSystem/Controllers/BondHeadController.ForceRelated.cs`（见第 4/5 节，这是本篇最重要的结构结论）。
2. **补偿**（`SupportFeature/Compensate/`）：四类互相独立的补偿——实时视觉补偿（`RealTimeCorrection`）、温漂补偿（`TpMarkCompensate` / `AirCooledController`）、焊点区域补偿（`BondCompensate` / `TransportUnitCompensate`）、不良品补偿（`DefectCompensate`）。
3. **统计**（`SupportFeature/Statistics/`）：产能/良率/操作日志/参数变更/温飘/测高数据的**查询与展示**，以及写入数据库的异步队列。
4. **耗材**（`SupportFeature/Consumables/`）：按时间或次数计寿命，到期在后台线程弹框提醒。
5. **温度监控**（`SupportFeature/TemperatureMonitoring/`）：一个独立窗体，轮询热电偶与轴温度并存 Excel，与加热设置模块无代码耦合。

上游：`BondSystem/Controllers/System2Controller*.cs`、`BondSystem/Models/ActionNodes/BPActionNode/*`（生产动作调用力控）。下游：固高运动卡（`GTN.mc`）、EasyModbus（力传感器/压力表）、SqlSugar + SQL Server。

## 5. 关键实现细节

### 5.1 ADC → 克的完整系数链（逐项）

公式出现在两处，写法一致：

```csharp
// BondSystem/Controllers/BondHeadController.ForceRelated.cs:83-86
double initialValue = Math.Round((pValue / 32767) * maxPress, 8);
return initialValue * 1000;
```

| 项 | 值 / 来源 | 行号 | 说明 |
|---|---|---|---|
| `pValue` | `GTN_GetAuAdc` 出参，`out double` | `BondHeadController.ForceRelated.cs:75-80` | 固高模拟量输入通道的**原始 ADC 值**，量程 0..32767 |
| `32767` | 字面量 | `:83` | **满量程码值**，即 2^15−1。这是软硬件约定，不是算出来的：固高 AU_ADC 通道以 32767 对应传感器满量程 |
| `maxPress` | `ForceConfig.GetInstance().BondheadMaxPress`，默认 `2` | `:46` + `ForceConfig.cs:74` | 传感器满量程，**单位 kg**。LVDT 支路用 `LVDTMaxPress`（默认同为 2，`ForceConfig.cs:80`） |
| `1000` | 字面量 | `:86` | **kg → g** 单位换算 |
| `channel` | `private static short channel = 1;` | `:41` | ADC 通道号。另有 `System2Controller.cs:1200` 改用 `bondHead.ReadBondheadForce.SensorIO`，两处不一致 |
| `p2Clock` | 输出时间戳 | `:80` | 未参与换算 |

即 **克 = pValue ÷ 32767 × maxPress(kg) × 1000**。任务书要问的"位深/放大倍数"在本项目中**没有对应的 C# 常量**：ADC 的增益/偏置不做软件乘法，而是通过 `TAdcConfig` 下发到卡上——`adcCfg.a = 1; adcCfg.b = pValue;`（`:273-275`），即增益固定 1、偏置取当前采样值（充当一次零点写入）。`ForceConfigItem` 里也没有放大倍数项。

另有一处**同源但公式不同**的实现：`BondSystem/Controllers/System2Controller.cs:1202` 写 `(pValue / 32767) * BondheadMaxPress * 1000.0`（与上式一致），而 `:1225` 的标定台力写 `(pValue) * CalibrateTableMaxPress * 100.0` ——**漏掉了 `/ 32767`**，且系数是 100 而非 1000。标定台读数是磅秤还是别的量纲无法从代码判定，如实记录为疑点（见第 8 节）。

### 5.2 力控闭环：控制律在哪里

**本项目 C# 里没有力控控制律**。C# 只做三件事：

1. **下发设定值**：`double pressTarget = forceValue * 32.767 / maxPress;`（`BondHeadController.ForceRelated.cs:369`）。这是与 `:83` 互逆的换算（克 → 0..32767 码值），`32.767 = 32767/1000`。
2. **下发 PID 参数**：`pressPid.kp = configItem.Kp; ki = Ki; kd = Kd; kvff = 0; kaff = 0; derivativeLimit = 10000; integralLimit = 10000; limitMax = 20000; limitMin = -20000;` → `GTN_SetPressPid`（`:292-304`）。参数来自 `ForceConfigItem`，随力段变化。
3. **配安全与切换**：`GTN_SetPressAutoSwitchPrm` 的 `limit1/limit2 = 32767 / maxPress * modelChange (-5)`（`:327-328`、`:395-396`），`GTN_SetLimit(MC_PRESS / MC_TORQUE, 29000/30000/7000)` 并 `GTN_LmtsOn`（`:342-350`）。

因此**闭环（P/I/D 运算、反馈比较、输出到电机）全部由固高运动卡在卡内完成**，调节对象是**力矩/压力环输出**（等价于调 Z 轴推力），既不是 C# 算完再调 Z 高度，也不是调气压。

力段的选择：`GetForceModelChange(forceValue, configItem)`（`Services/ForceCalibrationService.cs:359-373`）给出"力位切换阈值"，若为负则抛 `力控切换阈值为负数，请检查LVDT/应变片模拟量是否为负数！`（`:319-324`）。小力段的 `GetSmallForceModelChange`（`ForceCalibrationService.cs:310-351`）按 0.5 / 0.1 / 0.01 三档带宽查表，最后 `/1000.0`（`:350`）把克还原成 kg。

### 5.3 力参数如何随产品配方变化

分两层：

- **设备层（不随配方）**：`ForceConfig`（`Models/DevicePara/ForceConfig.cs`）是 `Singleton<ForceConfig>`，落在 `ZX2200PathConfig.ForceConfig` 的 JSON，整机共用。
- **配方层（随产品变）**：`ForceConfigItem` 是**力段表**，按力值区间索引：
  `GetLargeForceConfigItem(forceValue)`（`:196-223`）/ `GetSmallForceConfigItem(forceValue)`（`:230-259`）取"最近的段"，越界时夹到首/末段；内部用 `OrderBy(ForceLowerLimit)` 会**原地重排该 List**。
- **真正随产品走的**是产品参数本身：`BondActionParameter.BondForce`、`DipActionParameter.DipForce`、`SlowTravelDistanceBeforePlace`、`ForceControlOutTime` 等（调用点见 4.2），以及 `ForceConfig.ForceCaliMode` / `ForceRange` / `ForceBoundary` 这些标定策略开关。

### 5.4 标定与去皮（Tare）

- **去皮通道**：`ModbusService.ResetManometer()` / `ResetBondhead()` 都是 `WriteMultipleRegisters(94, new int[]{1})`，失败后 `Thread.Sleep(50)` 重试（`Modbus/ModbusService.cs:202-231`、`236-252`）。
- **去皮模式**：`ForceConfig.ForceZeroMode`，默认 `ForceZeroModeEnum.Modbus`（`ForceConfig.cs:140`）。
- **零点漂移**：靠 `ForceCalibrationData.ForceInitialValDic`（角度→初始值）补偿，生产时用 `ForceCalibrationService.GetInitialValByAngle(angle)` 取固定值，标定时用 `GetBondForceCurrentVal()` 取实时值（`BondHeadController.ForceRelated.cs:188` 的 `isUseActualInitial` 分支）。
- **另一层零点**：`ZeroBondhead(isSmallForce)`（`:1072-1134`，内部 `Thread.Sleep(20 * resetCount)`）+ 生产流程里的 `ZeroBondhead` 守卫（`System2Controller.Assistant.cs:504-509` 取料、`:853-858` 固晶）。

## 8. 注意事项与风险

**结构性问题（最重要）**

1. **力控实现位置与目录划分不符**：`BondSystem/BondForce/` 的 17 个文件里**没有任何 ADC 采集或 `GTN_SetPress*` 调用**，全部在 `BondSystem/Controllers/BondHeadController.ForceRelated.cs`（本文件 1,136 行，属 `BondSystem/Controllers/`）。改力控算法必须改那里，改标定策略才动 `BondForce/`。这一点与另一项目（力控在 `SupportFeature/ForceControl/`）不同，不能沿用。
2. **机型分支不对称**：读力用 `if (AxisDrive is ETELAxis) { Modbus } else { 固高 }`（`BondHeadController.ForceRelated.cs:67-88`），切通道用 `if (... is GTAxis)`（`:1027-1036` 的 `ChangeChannelAndSetForceControlPara`）。两个谓词不同源，Leadshine DMC 既不满足 `ETELAxis` 也不满足 `GTAxis`，会落到固高 API 分支——**雷赛配置下力控行为未定义**。全项目 `is GTController` 仅 3 处。

**数据正确性**

3. `System2Controller.cs:1225` 标定台力换算 `Math.Round((pValue) * CalibrateTableMaxPress, 6) * 100.0` **缺 `/32767`**，与同文件 `:1202` 的焊头力公式不一致。同一物理量两条公式必有一条错。
4. `BondHeadController.ForceRelated.cs:41` 的 `channel` 是 `static` 且默认 1，而 `System2Controller.cs:1200` 用 `bondHead.ReadBondheadForce.SensorIO` 作通道；两处若不一致会读错通道。
5. `BondHeadController.ForceRelated.cs:46` 的 `maxPress` 是 **static 字段**，在类型初始化时读取一次 `ForceConfig`。运行中修改 `BondheadMaxPress` 并保存**不会**影响这个静态值，需重启进程。
6. `ForceConfig.GetLargeForceConfigItem/GetSmallForceConfigItem` 内部 `OrderBy(...)` 返回新序列被赋回字段，**会原地改变列表顺序**；`ForceConfigItem` 的"最近段"选取依赖顺序，反复调用存在顺序漂移风险（`ForceConfig.cs:196-259`）。
7. `ForceConfig.IsActiveBondForceCheck = true`（`ForceConfig.cs:68`）**全项目 0 处引用**，是个死配置项。
8. `DefectCompensate.GetPostBondCompensation` 里 `Z = point3Ds.Average(it => it.X)`（`DefectCompensate.cs:221`），Z 分量取自 X 数组，疑似笔误。
9. `FrequencyConsumables.IsRemind`（`FrequencyConsumables.cs:69-84`）整数除法导致恒不提醒。
10. `BondCompensate.GetBondCompensate` 方法首行 `return new AKRSPoint3D();`（`BondCompensate.cs:76`），**整段插值算法是死代码**；生效的是 `TransportUnitCompensate` 里的同源副本。
11. `GetTotalAlarmSeconds()`（`StatisticsService.cs:170-186`）在 `:183` 有**不可达的 `return 0;`**，且用字符串拼接构造 SQL；`GetMaxMTBA()`（`:142-162`）无调用者。
12. `StatisticsService.SaveEntityToDb` 的 `switch`（`:110-140`）**只认 4 种实体**，`ProductTimeStatisticsEntity` / `CapacityLogEntity` 即使入队也会被静默丢弃。结合第 5.6 节：**`CapacityLog` 表全项目无人写；`ProductTimeStatisticsEntity` 只被一个随机数测试按钮写**。产能/良率的真实数据源是 `BondPositionLog` + `DefectStatisticsEntity`。

**未完成/占位实现**

13. `VoiceCoilMotorCalibrationController` 整个方法体被注释；`GooGolCompensate` 两个方法为空（`GooGolCompensate.cs:17-28`）；`EtelCompensate` 是空类（`EtelCompensate.cs:9-11`）。
