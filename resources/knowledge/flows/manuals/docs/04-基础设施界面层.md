# 基础设施界面层（`AKRS.ZX2200/Infrastructure/Controls/`）

> 全机共用的 DevExpress 控件与对话框库：产品程式示教树、数据集仓库 CRUD、方向盘/摇杆、报警弹窗与报警历史、光源与相机调节、测高/测距工具。
> 代码规模：37 个文件 / 12,156 行（不含 30 个 `*.Designer.cs`、30 个 `*.resx`）

## 1. 模块定位

### 1.1 这一层到底是什么（与任务书预期不符，已核实）

任务书假设本目录包含「机器参数/轴参数/相机参数/通讯参数界面」与「用户/角色/权限管理界面」。**在本项目中这两类界面都不在本目录**，已在代码中逐一核实：

| 任务书预期内容 | 本项目中实际位置 | 核实方式 |
|---|---|---|
| 参数配置界面（机器/轴/相机/通讯） | `SupportFeature/Parameters/`（含 `Attributes`/`Editor`/`Model`/`Models`/`ObjParameter`/`Service` 六个子目录），基类 `UcBaseEditor : XtraUserControl, IParamEditor` 在 `AKRS.ZX2200/SupportFeature/Parameters/Editor/UcBaseEditor.cs:17` | 目录枚举 + `grep "class UcBaseEditor"` |
| 用户/角色/权限管理界面 | `AKRS.ZX2200/Main/Controls/Ucmain/UcUserManager.cs`（及 `.designer.cs`） | `grep -rl "RoleMenuPair\|UcUserManage"` |
| 硬件编辑器（对应 `User`/`Role`/`MenuItem`） | `AKRS.ZX2200/Main/Controls/Ucmain/UcHardwareEditor.cs` | 同上 |

因此本层的真实职责是**被上述模块复用的通用 UI 积木**，共 4 类：

1. **产品程式示教主界面**——`UcEditProductProgramming`（4 个分部文件，4,214 行），通过 `TreeList` 节点切换 25 类子配置控件，是全机示教流程的入口面板。
2. **通用数据集仓库对话框**——`FrmRepository<T>`，泛型化的「数据集增删改查 + 抽取到 Recipe」界面。
3. **硬件操作控件**——方向盘/摇杆（`UcGuideMove`）、光源（`UcLight`/`UcLampRegulation`）、相机曝光/增益/伽马调节、实时影像窗（`RealTimeImageForm`）、旋转中心散点图（`PointShow`）。
4. **报警与提示基础设施**——`AKRSXtraMessageBox`（44 个 `Show` 重载，全部改道 UI 线程）、`AKRSMessageBoxExt`（带报警等级的模态报警框 + 三色灯联动 + `AlarmLog` 落库）、`FrmVisionAlarm`（定位失败强交互窗）、报警历史查询（`UcAlarmHistory`/`FrmAlarmHistoryQuery`）。

### 1.2 在整机中的位置

本层**不持有业务流程状态**，所有配置对象都从外部单例取用：`ProductConfiguration`（`Feature/EditProgram/UcEditProductProgram/UcEditProductProgramming.Assistance.cs:42`）、`WaferSystemDomain`、`System1Domain`/`System2Domain`、`BondProgram`、`MachineHardwareConfiguration`、`MachineStateModel`。本层只做「读单例 → 显示 → 改单例 → 调 `Repository.Save()`」的搬运。

- **上游**：UI 主框架 `Main/Controls/MainForm.cs`（提供 `SendUiAction` UI 线程投递入口，`MainForm.cs:50`）。
- **下游**：`BondSystem`/`WaferSubSystem`/`DispenseSystem`/`TransportSystem`/`TransportUnitSystem` 各自的 `Controls` 与 `Models.Repositories.*`。`UcEditProductProgramming` 一个文件就 `using` 了 40 余个跨模块命名空间（`UcEditProductProgramming.cs:3-76`），是本项目耦合度最高的 UI 文件。

### 1.3 UI 框架归属（已核实）

本目录 **37 个文件全部使用 DevExpress 21.2.7**，无一处 `SunnyUI` 或 `DevComponents.DotNetBar2`（`grep "Sunny\|DotNetBar\|DevComponents"` 在本目录内返回空）。基类只有两个：

- `DevExpress.XtraEditors.XtraUserControl` —— 24 个控件类
- `DevExpress.XtraEditors.XtraForm` —— 11 个窗体类

`Currency/BaseControl.cs:12`（`BaseControl : XtraUserControl`）是全项目的主模块基类（外部 12 处引用），但**本目录内没有任何控件继承它**——它只是恰好被放在 `Currency/` 下。

> **结论：任务书中「新界面用 DevExpress，老界面用 DotNetBar/SunnyUI」的分界不在本层。** 本层整体属于「新界面」一侧。

## 5. 关键实现细节

### 5.1 数据绑定机制（与任务书假设不同）

任务书假设「`UcParameter` 类普遍靠 `PropertyChanged.Fody` 做 bind」。在本目录**不成立**，已核实：

- `FodyWeavers.xml` 主工程启用了 `<PropertyChanged />` 与 `<MethodBoundaryAspect />`（`AKRS.ZX2200/FodyWeavers.xml`），但 **`PropertyChanged.Fody` 只对实现 `INotifyPropertyChanged` 的类注入**；本目录内 `grep "INotifyPropertyChanged"` **返回空**，也没有 `[AddINotifyPropertyChangedInterface]`。
- 本目录内 `grep "DataBindings.Add"`（含全部 `*.Designer.cs`）**返回空**——没有任何 `Control.DataBindings` 双向绑定。
- 实际只有两种方式：
  1. **整表赋值**：`GridControl.DataSource = List<T>`。用于 `FrmRepository`（经 `BindingSource`，`FrmRepository.Designer.cs:48`）、`UcAlarmHistory.cs:55,76`、`UcConfiguration2.cs:75,78`、`FrmMeasureHeightPoints.cs:235`、`FrmBondheadStandardMeasurement.cs:73`。
  2. **手工读/写（无绑定）**：加载时 `SpXxx.Value = obj.Prop * 1000.0`，保存时 `obj.Prop = (double)SpXxx.Value / 1000.0`。见 `UcDefect.Init`（`UcDefect.cs:42-82`）/`UcDefect.BtSure_Click`（`:89-118`），`UcAddOffset.SetOffset`（`UcAddOffset.cs:55-140`）/`BtSure_Click`（`:281-362`）。

**工程含义**：任何「改了 UI 但没点保存」的路径都会静默丢弃，且没有绑定层帮你发现；反之任何「改了对象但没刷新 UI」也不会自动同步。**长度单位换算（mm ↔ µm 的 ×1000 / ÷1000）散落在每个读/写点上，共 20 余处**（如 `UcDefect.cs:44-45,51-52,93-94,100-101`；`UcAddOffset.cs:73-79,83-89,99-103,120-137,292-294`），新增字段极易漏乘/漏除。

## 8. 注意事项与风险

### 8.1 已确认的功能性缺陷

1. **`UcDefect`：界面控件从未生效（「有问题」自述）**

### 8.3 并发与生命周期

22. **`UcEditProductProgramming` 的静态委托是全局可变状态**
    `RefreshILstAssistantStep.cs:25-50` 的 6 个 `static Action<>` 属性，在 `UcEditProductProgramming_Load`（`UcEditProductProgramming.cs:1088-1099`）里 `+=` 订阅**实例方法**。**只有订阅、没有退订**：窗体反复打开会不断累加，且每次打开都换新实例，旧实例被静态委托长期持有 → **内存泄漏 + 旧实例方法被重复调用**。多实例并存时，任一子窗体的刷新请求会打到所有历史实例上。

23. **`UcGuideMove` 的静态状态跨实例串扰**
    `IsJoystickEnable`（`UcGuideMove.Joystick.cs:42`）与 `CurModule`（`:47`）都是 `public static`，而 `UcGuideMove` 在本项目里是**多实例**使用的（`UcGuideMove.Designer.cs:51`、`FrmMultipleHeightMeasurement.cs:135`、`FrmDistanceMeasurement.cs:181` 等）。实例 A 打开摇杆会改变实例 B 的下拉框；任一实例 `Dispose`（`UcGuideMove.cs:101-108`）都会把全局 `IsJoystickEnable` 置 `false`，**打断另一个实例正在运行的摇杆运动**。`while (IsJoystickEnable)`（`:413`）在后台线程读取该静态字段，且无 `volatile`/`Interlocked`，无内存屏障保证可见性。

24. **`UcGuideMove` 构造函数的副作用**
    `:90-95` 的重载在构造时就调用 `MainForm.MF.UcMainSystem.GuideMoveClose()` 关闭主界面方向盘。**实例化一个控件会改变主界面状态**，且 `MainForm.MF` 为 null 时会崩（构造期无法 catch）。`isMainUi` 参数只用于这一句，未保存。

26. **`FrmMeasureHeightPoints` 用 `Thread.Abort` 终止测高线程**
    `:351` `this.thread.Abort()`。本项目目标框架是 `.NET Framework v4.8`（`AKRS.ZX2200.csproj:12`），此处**仍可运行**，但 `Thread.Abort` 在 .NET 5+ 会抛 `PlatformNotSupportedException`，且即使在 4.8 上也可能在 `TUAssistantHelper.MoveToPos` 中途中断、留下轴在运动状态。若将来迁移框架需一并改造（改为 `CancellationToken`）。此外 `DoWork` 中 `return`（`:101`）会跳出循环但不减线程引用，`timer1_Tick`（`:244-247`）据此取消勾选。

27. **`FrmVisionAlarm` 在工作线程里做 UI 忙等**
    `:344-347` `while (this.isWork) { Thread.Sleep(100); }`、`:431-434` 同样，以及 `:518-521` `while (this.task.Status == TaskStatus.Running) { Thread.Sleep(10); }`。这些都在按钮点击/窗体关闭的 UI 线程上，**会冻结界面**（`isWork` 由 300 ms 周期的后台线程置位，`BtEditProgram_Click` 最坏要等满一个采样周期）。

    `:52` `this.task = Task.Run(() => this.BackgroundWorkerDoWork());` 结果从未 `await`/`Wait`；而 `BackgroundWorkerDoWork` 的 `catch` 是 `throw new Exception("定位失败实时显示线程异常" + ex.Message)`（`:181-184`）——在 Task 里重新抛出后被丢弃，**异常既不上报也不记录**。同理 `UcGuideMove.Joystick.cs:580-581` 在 `Task.Run` 的循环里 `catch → 弹框 → throw`，最终异常同样无人观察。

    `:105-111` 在 `Task.Run` 的委托里执行 `this.BtnStart.Appearance.BackColor = Color.Transparent;`（`:110`）。没有 `Invoke`/`BeginInvoke`，属于未定义行为的跨线程 UI 访问。

    `:18` `private static RealTimeImageForm realTimeImageForm = new RealTimeImageForm();` 是饿汉单例，`ShowForm()`（`:23-33`）会在 `IsDisposed` 时重建，但 **`ShowDialogForm()`（`:38-41`）不重建**，直接 `realTimeImageForm.ShowDialog()`。窗体一旦被释放，再次调用 `ShowDialogForm` 会抛 `ObjectDisposedException`。
