# 实验系统框架（`AKRS.ZX2200/Experiment/Test`、`AKRS.ZX2200/Experiment/TestFunction`）

> 实验系统的「框架」部分：这里没有框架，只有一堆各自独立的 `XtraForm` 测试窗体。本文件描述它们的共同形态、数据采集/统计/落盘惯例、启动入口，以及真实驱动硬件带来的风险。
> 代码规模：21 个文件 / 12,406 行（不含 `*.Designer.cs`）；另含 21 个 `*.Designer.cs`（7,108 行）与 21 个 `.resx`，均不计入。

## 1. 模块定位

本范围覆盖两个目录，职责并不对称：

| 目录 | 性质 | 说明 |
|---|---|---|
| `Experiment/Test/` | 诊断/标定类测试窗体 | CMK 测试、整机功能测试、振动测试、上视模拟贴片、旋转中心精度、回零精度、Z 偏差等，由主界面「诊断」菜单直接弹出 |
| `Experiment/TestFunction/` | 两个「杂物箱」窗体 | 与主流程无耦合的一次性试验代码堆放处，入口带密码保护 |

关键结论：**本项目中不存在实验系统框架**。已在本项目全仓 grep 核实：

- 无 `ExperimentBase` 之类的抽象基类——范围内 21 个类型全部直接继承 `DevExpress.XtraEditors.XtraForm`（如 `FrmBMCTest.cs:41`、`FrmMachineFunctionTest.cs:58`、`FrmVibrationTest.cs:41`）。
- 无 `IExperiment` 接口、无 `ExperimentAttribute`、无注册表/工厂/管理器（`grep -rn "ExperimentBase|IExperiment|ExperimentAttribute|RegisterExperiment|ExperimentFactory|ExperimentManager"` 结果为空）。
- 唯一的公共基类 `FrmBaseTest`（`Experiment/Test/FrmBaseTest.cs:49`）**不是基类**，它只是一个名字取得像基类的普通业务窗体，没有任何类型继承它。

在整机流程中的位置：实验窗体是**旁路分支**，不参与自动固晶主流程的调度；它们由操作工手动打开，直接调用与主流程相同的控制器（`BondModuleController`、`BondHeadController`、`System2Controller`）和视觉服务，因此**与主流程共享同一套硬件资源**（详见第 8 节）。

## 5. 关键实现细节

### 5.1 数据采集惯例

- **采集次数来自界面控件**，不是常量。典型：`int testNum = int.Parse(this.SpBondZTestNum.Text)`（`FrmBaseTest.cs:188`）、`this.cycles = (int)this.SpCycles.Value`（`FrmBMCTest.cs:1402`）、`int intervalTimes = Convert.ToInt32(this.spIntervalTimes.Value)`（`FrmRotateCenterAccuracyTwo.cs:103`）。
- **原始点全部保留，不做去极值、不做剔除**。范围内没有找到任何去掉最大/最小值、3σ 剔除或中位数滤波的实现；统计全部基于全集。
- 典型循环是「移动 → `Thread.Sleep(N)` 等稳定 → 视觉定位 → 记录」。延时值通常来自界面（`visionDelay`，`FrmBMCTest.cs:231`/`:548`），HARD-CODE 的也有：`Thread.Sleep(5000)`（`FrmRotateCenterAccuracyTwo.cs:122`）、`Thread.Sleep(500)` 在每次 `DoWork()` 前（`FrmRotateCenterAccuracyTwo.cs:558`）。
- 视觉结果只取 `MatchResult.CenterX/CenterY/Angle`（平台 `AKRS.Galaxy2.*` 类型），例如 `FrmTestMoveAccuracy.cs:301-302` 里还会减去硬编码的相机中心 `1224`/`1024`。

### 5.2 统计量——全部集中在 `FrmBMCTestResult.CalculateResult()`

这是本范围内**唯一**成体系的统计实现（`Experiment/Test/FrmBMCTestResult.cs:56-145`），逐项：

| 统计量 | 实现 | 行号 |
|---|---|---|
| Max | `bMCTestResultList.Max(t => t.XResult)` | `:66-68` |
| Min | `bMCTestResultList.Min(...)` | `:79-81` |
| Mean | `bMCTestResultList.Average(...)` | `:91-93` |
| 极差 Difference | `xMax - xMin` | `:103-105` |
| 3σ | `3.0 * Math.Sqrt(sumDeviation / (count - 1))`，即**样本标准差×3** | `:120-122` |
| CMK | `Math.Min(accuracy - mean, mean + accuracy) / threeSigma` | `:132-136` |

其中 `accuracyXY`/`accuracyAngle` 是公差界限，由 `FrmBMCTest` 从 `bMCDevicePara.AccuracyXY/AccuracyAngle` 传入（`FrmBMCTest.cs:1403-1404` → `FrmBMCTestResult.cs:24`）。

其它实验的统计都是**即席的手写聚合**，没有复用：

- 力控误差：把 ≤100g 与 >100g 分两段，分别算 `Min/Max/Average`，>100g 段按百分比误差（`FrmMachineFunctionTest.cs:1149-1177`）。
- 测高重复性：`Max()`、`Min()`、`MathService.GetRange(data)`（`FrmMachineFunctionTest.cs:1196-1202`，`GetRange` 定义在 `Infrastructure/Service/MathService.cs:341`）。
- 振动到位判定：取 `Skip(20).Take(10).Average()` 作基准，再算各点与基准的绝对偏差最大值（`FrmVibrationTest.cs:357-366`）——**`Skip(20)`/`Take(10)`/`index < 29` 都是硬编码，要求采样序列长度固定为 30**（采样循环 `for (int i = 0; i < 20; i++)` 在 `FrmVibrationTest.cs:115`，与 `Skip(20)` 不匹配，见第 8 节）。
- 旋转中心极差：`list.Max() - list.Min()`（`FrmRotateCenterAccuracy.cs:615`）。

## 8. 注意事项与风险

### 8.1 实验会真实驱动轴与相机，且没有本层保护

- 所有实验都直接调用控制器的真实运动：`bondModuleController.MoveToG0Pos(...)`、`bondHeadController.PickAction(...)`、`BondModule.BondAxisX.GoHome()`（`FrmBaseTest.cs:877-878`）、`bondHeadController.RotateAxisT(-180)`（`FrmRotateCenterAccuracyTwo.cs:124`）等。
- **本范围内没有任何速度上限、软限位或行程校验代码**（`grep "MaxSpeed|SpeedLimit|SoftLimit|软限位"` 在范围内零命中）。保护完全依赖 `bondModuleController.MoveSafeBondXYZ(...)` / `MoveToSafePos()` / `bondHeadController.MoveBondZToSafePos()` 这些下游方法内部是否做了判断——**这些方法在平台 DLL 或控制器层，本范围无法核实**，请勿假定它们有保护。
- `FrmDryMoveTest` 是最危险的一个（虽然不可达）：`while (this.testFlag) { bondAxisX.AbsoluteMove(-170); bondAxisX.AbsoluteMove(180); }`（`FrmDryMoveTest.cs:35-36`），X/Y/Z 三个轴各一个 `Task` 并发跑，**循环体内没有 `Thread.Sleep`**，等于以最快速度反复下发绝对位置指令。硬编码行程：BondX `-170/180`、BondY `-154/108`、BondZ `-35/0`、晶圆台X `0/190`、晶圆台Y `-300/0`（`:35-36`、`:46-47`、`:57-58`、`:124-125`、`:135-136`）。`BtDispenseMoveTest_Click` 里点胶三轴的往复目标值被写成同一个数（`:80-81`、`:91-92`、`:102-103` 全是 `AbsoluteMove(0)`），**是明显的死代码/占位逻辑**。
- `FrmUpLookSimulateBondTest` 的产物路径 `D:\UpLookBitmapData\` 里保存的是位图（`:365`），单次测试可能产生大量文件。
- `Experiment/Test/FrmTest.cs:106-113` 的「存图」按钮会在 `Task.Run` 里循环 500 次、每次 `Thread.Sleep(100)` 存一张 bmp 到 `D:\小芯片图片\3\`——**无停止按钮**，且 `tag` 字段（`:139`）只用于真空读取线程，与存图无关。

### 8.2 与主流程并发

- **实验与主流程之间没有任何互斥**。除 `FrmMachineFunctionTest` 内部的 `isWorking` 标志外，实验窗体不检查 `Machine.GetInstance().IsWorking()`，也不检查自动运行是否已启动。
