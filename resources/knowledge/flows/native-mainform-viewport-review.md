# 原主窗体客户区尺寸矩阵与裁切

两份独立原生 UI 进程各通过 71 项检查，使用原始 MainForm、原始 SDK 文档和 PrintWindow；每份执行 6 个公开客户区尺寸请求，再返回紧凑尺寸。没有改变物理显示器、DPI 或生产源码。两轮同一尺寸的控件几何、溢出值和截图哈希一致。

|---|---|---|---:|---:|---|---:|
|1024×600|1024×600|1920×999|896|399|否|54|
|1536×793|1536×793|1920×999|384|206|否|41|
|1920×999|1540×846|1920×999|380|153|否|41|

|2300×1300|1540×846|1920×999|380|153|否|41|
|返回1024×600|1024×600|1920×999|896|399|否|54|

请求大于当前桌面工作区的尺寸被 Windows/原窗体限制为 1540×846；这不是对目标设备屏幕的替代。96 DPI 下 Designer 的原始 MinimumSize/Size 为 2194×1284，经 7×14 字体缩放后实际文档为 1920×999，且原控件 AutoScroll=false。观察到的 1536×793 客户区稳定超出右384、下206；紧凑客户区超出右896、下399。

每个场景均保持一次 QueryControl、同一个原始文档实例和原始最小尺寸；没有注入滚动条、重设 DPI、改变 Form 最小尺寸、调用 Program.Main、启动设备/SQL/图像消费者或业务任务。PrintWindow flags=2 输出已实际查看，截图保留在隔离目录。

[测试回执](native-mainform-viewport-test.json)、[审计](native-mainform-viewport-audit.json)、[进度](native-mainform-viewport-progress.json)绑定两轮进程、矩阵、PNG、编译和源/IL 输入。该证据证明当前配置存在稳定裁切，不能证明所有现场设备均裁切，也没有修复生产界面。正式1328、Program.Main 台账19106及前轮布局台账18705保持独立；29组仍partial，整体目标未完成。
