在完整消费者/四种原搜晶/取料移动/台面控制器/单步测试链上，新增完整原Machine.Stop、SetState、SetStopStateAlarm和IsStop，总计18个原方法、1个原属性；直接编译原Signal和机器枚举，绑定3处原信号构造声明。运行时.NET 10.0.11。测试结果及文件哈希、方法偏移/行号和片段哈希见wafer-stop-chain-test.json。生产源码未修改。

## 已验证的边界

| 条件 | 受控执行结果 |
|---|---|
| 正常原Stop | 按创建日志、提交Stop状态、日志入队、清弹窗、取报警器并设置停止状态、关闭单步、重置需料、关上料请求、关顶针真空、清计数的顺序执行 |
| 已接收请求后Stop | 四模式均不发许可；九宫格在计算前拦截，其他三模式仍先到达一次原台面轴接口，再被StopSearch拦截 |
| 原取料移动的标记中心接口处Stop | 已越过StopSearch，四模式继续原动作链并发送许可；原Stop成功并不等于当前消费者立即返回 |
| 正在单步等待时正常Stop | 原Stop关闭单步开关，WaitSingleStep返回false，SingleStep抛异常；本次没有轴命令 |
| 单步等待时早期Stop失败 | 日志创建、日志入队、清UI、报警读取/设置失败均可留下单步开关；随后发送单步事件仍可使控制器调用轴接口，除日志创建失败外状态已是Stop |
| X命令接口内调用原Stop | 原控制器仍调用Y命令接口；Nine所选路径仍发送许可，其他三模式在随后StopSearch被拦截 |
| 停止前已发送许可 | 原Stop不重置允许取料信号，许可仍可被消费 |
| 停止前单步事件已Set | 原Stop仅关闭单步开关，不清空这个AutoReset事件 |

## 清理故障矩阵

七处故障：日志创建、日志入队、清弹窗、取报警器、报警输出、关闭上料请求、关闭真空。验证状态提交、单步开关、真实需料事件以及后续计数清理边界。

消费者已发送许可后的Stop失败会进入其catch并再次调用Stop；日志入队失败时状态已Stop，重试跳过SetState中的日志入队并完成后续清理。持续的其他六处所测故障使第二次Stop也抛出，消费者线程记录未处理异常，已发许可仍保留。

另覆盖：真实需料事件已释放导致ObjectDisposedException；null报警列表提交状态后失败；空列表继续清理；离线只跳过报警包装；非Online配置只跳过关闭上料请求；null焊后检查项造成前面计数归零、后面计数保留。
