## 已验证结果

| 范围 | 结果 |
|---|---|
| 全部8种Task状态 | 正常保护块和完整空跑方法都只保留Running；Created、WaitingForActivation、WaitingToRun、WaitingForChildrenToComplete及3种终态都会替换字段 |
| 被替换任务 | 原任务未被本次启动调用取消或等待；测试结束由夹具显式释放它们。非终态检查采用预置真实Task，不等于已复现生产并发重复任务 |
| 初始任务字段为空 | 两种启动入口创建任务；机器已Stop时工作线程直接退出 |
| 启动前置操作 | 空跑在检查任务状态之前调用两段Clamp、写有料状态、发送到料完成信号并构造材料；入口Pause/Stop不阻止这些操作 |
| 入口Pause | 两个工作线程尚未消费放行事件；恢复Working后消费并替换材料 |
| 已进入Signal.Wait后Pause | 两个消费者仍会消费放行、发送完成信号并替换材料，记录时状态为Pause |
| 下一个循环Pause | 下一次WaitStart会阻止第二个排队事件被消费；恢复后无需再发事件即可处理 |
| 等待中稳定Stop | 两个线程正常完成，不再替换材料；未测试所有状态切换竞争窗口 |
| 重复空跑启动 | 两个Running任务被保留，但前置Clamp、完成信号及材料初始化再次执行，旧材料对象被替换 |
| 正常/空跑相互切换 | 共用固晶到等待区任务字段；已有Running任务保持原引用，不会自动变成另一模式的任务体；空跑前置初始化仍执行 |
| 启动前置异常 | Clamp、材料构造或完成信号Set失败可直接逃出StartDryRun，任务尚未创建，未调用Stop |
| 工作线程内异常 | Set或构造异常被各自catch处理，目标任务RanToCompletion，另一线程仍活跃且机器保持Working |
| 完成信号与材料先后 | 先写HasMaterial、再发送完成信号、最后构造/赋值材料；构造失败时，完成事件已发出，材料仍为空或保留旧对象 |

## 证据与解释

状态矩阵使用真实Task：手动未启动任务、TaskCompletionSource、受控TaskScheduler、运行中门闩任务、等待附属子任务和三种终态。两个入口分别检查，覆盖全部TaskStatus枚举值。Running任务被门闩保持，未依赖碰巧足够慢的调度。

暂停验证使用每个工作线程的机器状态读取计数；Working且无放行事件时，至少十次状态读取确认原线程已经进入Signal.Wait的轮询。随后才切换Pause并发事件。两个循环之间的Pause同样等待各线程持续读取状态，不以固定短延时推断阻塞。

“只保留Running”不能等同于“所有未完成任务均被保护”。本测试已证明原保护条件如何处理预置的非终态任务，但尚未强制复现两个生产Start调用同时越过检查后创建重复任务的竞争过程。正常模式其它任务和模式切换调用者也未整体运行。

材料构造失败后完成信号已发送，说明原顺序允许下游观察到部分更新；没有运行真实下游取料逻辑，因此不声称已经发生设备误动作。
