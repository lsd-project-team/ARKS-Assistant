# 晶圆系统界面层（AKRS.ZX2200/WaferSubSystem/Controls）

> 晶圆子系统（WaferSubSystem）的全部 WinForms 人机界面：产品编程用的参数编辑页、逐步骤「导航示教」向导、以及产线人员用的手动/调试面板。
> 代码规模：51 个文件 / 20,952 行（不含 `*.Designer.cs`）

## 1. 模块定位

本目录只放 **UI 层**，不含任何业务调度与设备控制逻辑。它的职责边界是：

- **把用户操作翻译成对子系统的调用**。所有实质动作最终都落到本目录之外的三个门面上：
  - `WaferSubController.GetInstance()` → `WaferTableController` / `EjectController` / `MagazineController`（见 `Assistant/EjectionsTeach/FrmNeedleZeroPositionTeach.cs:153`）
  - `WaferSubDevicePara.GetInstance()` → 各模组设备参数（见 `Assistant/WaferHandlingTeach/FrmWaferMagazineGeoTeach.cs:181`）
  - `WaferSystemProgram.GetInstance()` / `WaferSystemDomain.GetInstance()` → 配方级程序与业务校验（见 `Assistant/EjectionConfigurationTeach/FrmEjectionSetting.cs:51`）
- **把用户示教的结果写回配置仓储**。每个示教向导的 `doneAction` 末尾几乎都是 `CarrierConfigRepository.GetInstance().Save()` 或 `WaferSubDevicePara.GetInstance().Save()`（例如 `Assistant/ComponentsTeach/FrmWaferEdgeWithWaferTeach.cs:222`、`Assistant/WaferHandlingTeach/FrmWaferTableCollisionCircleTeach.cs:172`）。
- **视觉相关的量测动作**统一通过 `Block.GetInstance()` 这一个门面（`Assistant/ComponentsTeach/FrmInkDotWithWaffleTeach.cs:165`、`Assistant/ComponentsTeach/FrmChangePositionTeach.cs:101`）。

**上游**：`AKRS.ZX2200/Infrastructure/Controls/Feature/EditProgram/UcEditProductProgram/UcEditProductProgramming*.cs`（产品编程主框架，本目录绝大多数示教窗体的唯一调用者）与 `AKRS.ZX2200/Main/Controls/` 的手动/数据管理菜单。

**下游**：`WaferSubSystem/Controllers|Modules|Services|Tasks`（调度与服务）与 `WaferSubSystem/Models`（数据模型），两者已由 `09-晶圆系统调度与服务.md`、`10-晶圆系统数据模型.md` 覆盖，本文不展开。

**UI 技术栈（本目录内已核实）**：全部 51 个类型均继承自 DevExpress 的 `DevExpress.XtraEditors.XtraForm` 或 `DevExpress.XtraEditors.XtraUserControl`（批量类型声明核对，例如 `UcCarrierMapping.cs:23`、`FrmDebug.cs:70`）。在 `AKRS.ZX2200/WaferSubSystem/Controls/` 下 grep `DevComponents` / `Sunny.UI` / `ZedGraph` **零命中**，即本目录没有旧式 DotNetBar / SunnyUI / ZedGraph 界面——它们是老界面的技术栈，不属于本范围。DevExpress 版本为 **21.2.7**（`AKRS.ZX2200/AKRS.ZX2200.csproj` 中 `DevExpress.*.v21.2, Version=21.2.7.0` 程序集引用，如 `DevExpress.Dashboard.v21.2.Win, Version=21.2.7.0`）。本工程启用编译期 AOP：`AKRS.ZX2200/FodyWeavers.xml` 中 `<PropertyChanged />` 与 `<MethodBoundaryAspect />` 两个 weaver——本目录大量「参数界面」依赖 `PropertyChanged` 织入实现数据绑定，但本目录内**没有**任何显式的 `MethodAopAttribute` 使用（grep 未命中），权限切面主要由更上层调用。

## 5. 关键实现细节

### 5.1 `AssistantConfig` 是字符串驱动的"步骤表"，不是状态机

`AssistantConfig` 的 8 个参数把"显示什么按钮 + 点按钮做什么"打包成数据（见 4.2）。由此产生三个必须知道的既有约定：

1. **步骤描述里的 `{stepIndex}` 是构造期快照**，不是运行时渲染（`FrmWaferEdgeWithWaferTeach.cs:142`）。
2. **`descritpion` 是拼写错误但被全项目沿用**（`AssistantConfig` 构造参数名），grep 时不要用 `description`。
3. **有些窗体的 `stepCount` 字段纯属摆设**。`FrmFlipToWaferTeach` 声明 `stepCount = 11`（`FrmFlipToWaferTeach.cs:50`）却只构造了一个步骤、描述直接写死 `"1/1:..."`（`:93-98`）；`FrmComponentCarrierAdjustWithWaferTeach` 声明 `stepCount = 1` 而 `doneAction` 是**空委托**（`FrmComponentCarrierAdjustWithWaferTeach.cs:126-128`）——两者的步数变量都不能作为"这个示教有几步"的依据。

### 5.2 `UcGuideMove` 方向盘：模块名是字符串约定

### 8.8 脆弱的数据约定（改数据结构时必须同步改的位置）

- **槽位索引靠字符串反解**：`Name.Split(':')[0].Substring(4)`（`FrmMagazineFilling.cs:177 / :253`、`FrmStaticWaffleConfiguration.cs:165 / :182`）。它同时假设 `Node.Name` 一定以 `"Slot"` 开头且带冒号，以及 `Id = 父索引 + 子序号` 的连续分配（`FrmStaticWaffleConfiguration.cs:334` 用 `node.Id - node.ParentId` 当子序号）。任何一处改名/改 Id 规则都会静默算错槽位。
- `Node` 是外部类型（本目录未定义），`FrmMagazineFilling` 与 `FrmStaticWaffleConfiguration` 各自维护一份 `List<Node>` 副本，两者对同一份 `MagazineAllocationsConfig` 的编辑互不感知——`FrmWaferChangeTeach.cs:420` 靠回调 `UcMagazineGeometry.RefreshMagazineBoxDataAction()` 手动通知刷新。
- **`UcMagazineGeometry.RefreshMagazineBoxDataAction` 是静态 `Action`**（`UcMagazineGeometry.cs:31`），构造时 `+=`、`Disposed` 时**只解绑定时器、没有 `-=` 该静态委托**（`:44-48`）。多次打开/关闭该编辑页会累积悬挂引用。
