# 项目删除入口与流程验收（2026-11-03）

按用户确认补齐侧栏项目菜单的“删除项目”和确认流程，复用现有项目删除接口。

## 行为与范围

- 项目菜单末尾提供删除项目，打开确认弹窗后显示实际项目名和两种对话处理方式。
- 默认保留对话并移至独立对话；也可选择移入回收站，之后恢复对话。源码文件与交接工作台资料不受影响。
- 项目存在运行中的对话或待发问题时，沿用后端保护并在弹窗显示具体错误，保留选择、项目及草稿，允许重试。
- 请求中禁用操作并通过同步标记防止重复提交，关闭不能提前结束请求；取消不会发送删除请求。
- 成功后移除失效项目的缓存、阅读状态及浏览器项目记录；删除当前项目时切到独立对话，保留对话的默认处理会继续打开原对话。
- 已保存对话的草稿按原编号保留。项目新对话草稿迁至独立对话；已有独立草稿时合并正文与全部选区，保留双方内容。
- 删除其他项目时保留当前项目及其草稿。当前页面不因打开或取消弹窗而切换。

新增组件归 `features/projects/components/ProjectDeleteDialog.tsx`，状态操作归现有项目 store；没有新增依赖、后端业务接口或数据库迁移。
