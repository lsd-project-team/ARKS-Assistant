# 历史重答与末条回复版本切换

2026-10-29，按用户确认的两种规则调整当前对话的重新生成功能。

## 最终行为

- 历史回复：原回答及后续消息保留；在同一对话末尾追加重答，并以“重新回答：原问题”标明出处，不创建新对话。
- 最后一条回复：共用当前问题的版本组，在原位置通过左右箭头和 `1/2`、`2/2` 等页码切换。查看旧版本时也可以再次生成，新结果默认显示。
- 历史重答追加到末尾后，再重生成这一条时，同样在该位置切换版本。
- 原问题的选区、知识来源及源码身份保留。运行中、未完成、来源目录不兼容及项目创建限制仍被拒绝；账号和项目访问边界保留。

## 实现与数据边界

历史重答保存独立的原题快照，沿用原始问题关联。前端将该快照显示为原题提示，避免把历史新答案合并进原位置的版本组。现有数据库表结构不变，不迁移或覆盖旧记录。

历史重答使用独立的上下文代，按原问题之前的有效记录恢复；后续新问题重新读取完整当前会话，保留中间问答并使用各组最新答案。已过期的项目上下文不复用，读取上下文的接口只返回重建结果，不写检查点。原有回收站永久清理会覆盖这些上下文代。

重新生成使用原问题当时的分析计划与进度，缺少旧事件时只向当时以前回查。源码已读证据仍按相同版本和目录恢复。重答 `/记录问题` 沿用原消息提交键；隔离代码修改也继续绑定原人类请求，不能借重答新建副本或重置验收范围。

补充修复冷检查点末条重生成的边界：没有本题输入时，不移除前一轮答案。失败后的末条新版本使用干净上下文，避免继续使用未完成的工具调用状态。

## 浏览器与本机更新

使用 `localhost:8878` 的独立临时数据库、普通测试账号和固定模型实测。两条原回复均显示重新生成入口；重答第一条后，两条原答案各保留一份，新答案位于末尾且没有版本合并。再重新生成末条，显示 `2/2`，可以切回 `1/2` 并再切回新答案。刷新后原答案、原题提示和两个版本均保留。
