## Bugs Found / 失败归因

修复的产品问题：原中间件一律拒绝非本机 Origin；代理终止 HTTPS 时 Cookie 可能按内部 HTTP 降级；恢复暂存建在数据目录父级，目标本身为独立卷时出现 EXDEV。构建器额外堵住了白名单文件祖先目录链接带入外部文件的问题。

真实构建还发现精简镜像 PATH 不含管理员工具目录，创建低权限账号失败；改为使用 groupadd/useradd 的绝对路径。首轮 Docker DNS 临时失败，实际解析恢复后重试同一构建，未更改宿主 DNS。构建中 3 条空默认 FROM 参数提示来自基础镜像参数必须显式提供；脚本只接受已核对的固定镜像身份。

首轮全量有 1 项 CLI 30 秒超时、809 通过、9 跳过。原因是没有 --live 时仍先导入完整模型运行时；改为参数授权检查通过后再导入，不延长测试超时。新增 Python -S 反例，确保第三方依赖缺失时也能拒绝未授权运行。最终全量无失败。

首轮 Linux 夹具给了恰好 1 GiB tmpfs，写入数据库后触发现有 1 GiB 剩余空间门槛；改为提供 2 GiB 临时盘，没有降低产品策略。产品入口探针曾误以为 dotnet 必须在 PATH，后改为调用镜像声明的绝对运行时路径；应用 Roslyn 从首轮即通过。这两项属于夹具问题，未据此修改产品预期。

## Test Limitations / Untested Risks

公司 Linux 服务器尚未实际部署，没有真实 Windows 构建节点、私有 SDK/DLL 和设备。没有执行 ZX2200 构建、设备程序、当前供应商质量评估或全仓模型阅读。没有浏览器视觉验收，HTTP 页面读取不能代替交互与视觉结果。

应用镜像未带 embedding 权重缓存，Linux 多语言向量检索还需管理员显式准备模型卷并验收；本轮没有把关键词回退当作语义检索通过。跨系统路径与源码身份迁移也未实现，不能直接替换 Windows 路径复用旧验证。

**已确认的待完成访问边界**：在本轮独立容器中，不带会话请求 `/engineering/manifest.json` 和 `/archify/module-source-explorer.html` 均返回 200。现有静态页面及前端 archifyData 编译数据包含业务知识，现有 API 登录保护没有覆盖这部分。公司部署前需要将业务知识从未登录可下载的前端包中移出，并通过服务端认证提供知识资源；仅限制 Host/Origin 不能替代这项工作。本轮未宣称整套生产安全验收完成。
