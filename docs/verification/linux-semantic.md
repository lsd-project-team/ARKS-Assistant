## 前置条件与执行

应用依赖须已按锁文件准备。模型为 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`，384 维，CPUExecutionProvider；管理员单独准备 `/opt/arks/.tools/embedding-models` 的公开权重，运行时只读挂载。当前应用发布镜像仍不内置权重。

在带有验收脚本、应用代码和依赖的 Linux 源码目录执行：

```sh
ARKS_LINUX_SEMANTIC_ROOT=/tmp/arks-semantic python -m scripts.verification.linux_semantic
```

临时根必须为应用目录之外的绝对空目录，不能是链接、应用祖先或现有非空目录。脚本不接管其他数据、不创建容器、不准备或下载模型；缺少模型时失败。容器及模型卷由操作者预先准备，不挂正式 data、trunk、供应商配置或宿主 Docker socket。

脚本复用真实 SemanticRetrieval、DebugIssueCorpus、DebugIssues 和 SQLite。依赖只收到净化环境、临时 HOME 和离线标志。结果写入临时根的 `report.json`，仅含检查布尔值、模型摘要和通用失败类别。

## Bugs Found / 失败归因

首轮夹具错误地要求底层编码器直接输出单位范数，触发 `embedding_vector_not_normalized`。底层编码器没有这项契约，产品在保存文档向量前执行归一化。修正为检查编码器维度/有限值，并核对实际持久化向量范数，随后全部通过；未修改产品代码或取消归一化检查。

本轮没有发现 Linux 模型缓存兼容或调试检索产品缺陷。Windows 上已有公开缓存原样复制后可在 Linux 加载，包括包含 Windows 分隔符的缓存元数据，没有改写该模型缓存。

## Test Limitations / Untested Risks

本机容器结果不能代替公司 Linux 服务器、真实容量与多用户性能验收；上线仍需准备模型卷并在目标服务器运行相同验收。小型合成检索不是业务正确率评测，不能证明全项目理解或真实问题均能正确处理。当前供应商问答、隔离改代码与历史复用属于另一项明确授权的验收，不能用 embedding 结果代替。Windows .NET Framework 4.8 构建节点、ZX2200 私有依赖和设备仍未验收。

本报告固定基底镜像内的检索模块未改；随后代码工作意图和提示的修正另见 [当前模型验收](current-model-quality.md)。公司部署前应从所选提交重新构建，不能把本轮临时检索镜像当作最终应用发布。
