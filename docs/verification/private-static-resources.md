## Tested Areas

- **真实构建依赖**：主入口、LoginPage 及静态 imports 的闭包；不把工作区动态 imports 一起公开。当前构建生成 121 个公开文件，包括 6 个 JS、3 个 CSS、字体和登录图像。实际编译后的登录依赖逐文件经 HTTP 读取并核对 SHA-256，CSS 字体引用均落在清单中。
- **拒绝错误构建**：真实 Vite 临时工程把业务资料保留在私有动态分包时构建成功；改为从登录入口静态导入业务数据后构建失败。另覆盖 Windows 路径、大小写、未知脚本和越界资源，不用模拟的编译成功代替真实构建。
- **服务端访问**：资料 HTML、工程 JSON、Agent 索引、业务 JS、源码映射、控制清单和旧哈希脚本未登录均拒绝。Range、HEAD、条件请求、查询串及编码路径无法绕过会话。授权的管理员和普通用户读取原始文件字节；退出后重放旧 Cookie、账号切换请求头和跨站请求被拒绝。
- **构建身份**：公开文件固定 SHA-256；修改字节、硬链接、路径越界、错误 schema 和坏 JSON 不被接受。清单缺失时静态访问关闭，API 仍可启动，不能回退公开整个 assets 目录。
- **响应边界**：私有内容禁止共享缓存并按 Cookie 区分，资料 iframe 只接受同源嵌入。公开的成功哈希资源可以长期缓存，416 和 404 等失败响应使用 no-store，首页不长期缓存。
- **Linux 流程**：两类知识资源和当前构建的所有非公开 JS，在匿名状态返回 401，登录后逐字节匹配镜像文件；同时保留 C# 语义、公司 HTTPS 来源登录、CSRF/Host 拒绝、隔离修改、原件摘要不变、重启持久化、在线备份、独立挂载根恢复及恢复后 HTTP 读取。

在补访问控制元数据时，先核对 473 个原有 UI 文件字节完全一致，只补齐两份元数据；已有 UI、资料 URL 和旧哈希文件保留。工作区期间出现其他任务的页面及 Agent 调整，这些修改已保留，不属于本次访问控制结论。

## Bugs Found

原中间件提前放行所有非 API 请求，资料直链和前端业务分包绕过登录。修复为可信构建清单只开放登录依赖，其余文件先校验现有会话再交给 StaticFiles。构建阶段另阻止业务知识进入公开入口，不能只保护某个页面 URL。

首轮新增测试有 4 项失败，原因是临时应用根缺少真实 Alembic 模板，属于夹具问题；补齐模板后仍使用真实临时 SQLite 和完整生命周期，没有绕过迁移或降低响应断言。

补充缓存反例时发现，公开资源的 416 响应被错误赋予一年缓存。反例实际失败后修复生产代码，仅给 200、206、304 使用哈希缓存，错误状态设置 no-store；同一测试还删除临时资源验证 404 不被长期缓存。这项检查也加入 Linux 实际流程。
