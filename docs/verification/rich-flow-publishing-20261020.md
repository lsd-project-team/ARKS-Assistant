# 流程回答整理与正式页面发布验收

日期：2026-10-20。原问题：`我想在做设备标定，给我输出一下标定流程`。

## 问题与修复

正式服务 8765 原先仍提供 2026-10-19 的前端资源 `index-CNnlvN64.js`，隔离页面已经存在的 Rich Content 渲染器未发布到该目录。仅改提示词不能补上正式页面缺失的渲染代码。

后端还有三条独立路径：长流程只要含合法展示块就绕过整理；整理器原先强制纯 Markdown、超长或失败就静默保留长稿；`unknown` 复核即使没有具体争议也会将整篇卡片降为文本，表格投影还缺少 Markdown 分隔行。浏览器复测另外确认，续写完成事件会在整理与复核之前提前发布原始草稿。

本次改为：

- 默认用步骤组织源码支持的操作主线，多个入口按需要用概览；补充实现放在默认收起的详情。明确要求详细、逐字或纯 Markdown 时保留其要求。
- 按实际可见正文计算长短，排除收起的补充内容及引用地址；合法卡片也不能绕过长文检查。默认主阅读区上限 1,400 字符，按实际流程安排步骤数。
- 整理器复制原稿已有的合法引用对象，校验展示协议、来源集合与主阅读区；失败最多重试一次，并反馈不含原输入的具体校验错误。仍失败则明确说明并保存完整原稿供展开核对，不当成成功整理。
- 整理后继续走原来的引用与源码语义复核。`unknown` 没有具体争议时保留合法卡片并显示提示；有具体争议时替换相关块，其他结构保留。跨块或无法安全处理时仍保守转为文本；表格保留可渲染的 Markdown 格式。
- 流程正文的 token 和内部续写替换事件均等待最终整理、复核完成后再发布。检查点与历史档案保留。
- 源码引用定位与后端对齐：同一路径、同目录、同版本的连续读取片段可以合并覆盖引用。缺行、跨版本、跨目录、已变化或不可读取的证据仍拒绝定位，不能把多段拼成虚假完整依据。
