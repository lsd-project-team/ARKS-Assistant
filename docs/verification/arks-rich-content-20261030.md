# ARKS 经验图文专项验收

日期：2026-10-30。用户在正式聊天询问“蓝膜穿孔如何解决用图文并茂告诉我”，得到“自动事实核查未完成”的原文摘录。本轮针对这条 ARKS 经验链路补测和修复。

## 原因与实现

通过当前登录账号的会话接口读取对应运行轨迹：经验搜索、片段筛选及原文读取成功，事实核查连续两次要求修订后以 `unresolved_facts` 降级。另一条旧会话还存在引用版本过时的筛选失败，不能混为没有资料。

经验工具的回答提示仍要求“只展示文字和原图”，核查器也曾以记录 `image_count=0` 为由要求说明无图、保留文字。此前新增的展示协议只证明通用问题可以生成图形，没有覆盖经验工具及事实修订的完整链路。图内结论和建议本身仍可能有真实事实问题，不能直接停用核查或放行未审稿。

修复包含：

- 统一展示协议、经验工具与核查提示：原图和根据资料生成的示意图区分，无原图也可展示有依据的方案关系；不伪造照片、业务数值或试验顺序。
- 经验核查保留 `answer` 原协议，并在结构化内容存在时附程序生成的 `answer_text` 可读投影；图内标签、连线、表格、折叠说明及建议均需核查。只在模型内部使用，不增加 HTTP 或 SSE 字段。
- 修订沿用完整白名单、无争议块 ID 与引用；错误单位、超出证据的因果或未通过终审的内容仍按原机制修订或摘录降级。
- 合入正式分支同期的回答组织更新，保留不重复图表、不例行追加调参顺序等要求。

没有更换 Agent、模型供应商、消息存储、数据结构或渲染器，没有修改原始经验和只读源码。旧会话原答案不会被自动改写，失效引用不会被静默换成新版本。

## 测试结果

自动化覆盖30个后端测试文件，321项通过、0失败、0跳过。范围包括经验筛选及失败边界、图形保留、事实修订和终审、错误单位、固定版本原图、源码证据、HTTP/SSE及Last-Event-ID重放、工具事件、多轮历史和结构化格式。新增完整链路用供应商替身注入错误高度单位，真实执行筛选与核查流程，确认修正单位时保留Mermaid及其ID，并实际运行React与Mermaid渲染。

首轮发现7项失败：1项原图提示断言与新要求冲突，改为同时检查示意图支持、全部原图、重复图片和不能冒充原图；6项断言在本轮改动前就与当前源码/经验分工提示不一致，更新为同时要求软件实现读源码、经验不强制扩展源码排查。未删除测试或关闭功能。

前端352项通过、0失败、0跳过；TypeScript检查、生产构建及变更Python的Ruff检查通过。覆盖率未采集，未执行变异测试。测试质量判断：中；具有明确反例和真实运行链路，但模型事实核查仍非形式证明。

## 真实模型与浏览器

脚本 `scripts/verification/arks_rich_content.py` 读取当前供应商配置至内存，在临时账号和数据库中保存截图案例的问答副本，明确无原图。没有复制正式账号、会话或整库资料，也没有往正式库写入测试记录。

同一句问题在修复前复现事实核查两次修订、原文降级。修复后执行两轮：原问题及“把上面的组合方案用流程图展示，保留适用条件、单位待确认和原经验引用”。已检查认证HTTP、完成事件、格式合法、事实核查通过或修订后通过、同版本经验引用、实际参数、SSE精确重放和2/4条历史恢复，并运行前端解析器、React组件与图形引擎。

首次修复生成参数表及Mermaid；增加逐块核查投影后，两轮事实修订仍保留关系图和Mermaid，浏览器回放可见参数表、关系图及实际Mermaid图片。原始报告和失败结果均保留在当前工作树忽略目录 `output/arks-rich-content/`，没有只保留成功样本。

合入同期回答组织更新后重新执行全部321项后端回归和两轮真实调用：首轮保留参数表和 `diagram`，追问生成 `mermaid`，两轮核查均为 `passed`。报告为 `output/arks-rich-content/integrated/live.json` 及同目录 `frontend.json`；浏览器回放也更新到该版本。前端源码未因合并改变，沿用本轮已通过的352项、类型检查及构建结果。

## 限制与人工验证

本工作树未准备离线向量模型，经验检索按既有关键词降级，本例确实命中并经过独立筛选；不据此宣称全库语义召回已经验收。真实样例只覆盖这一条蓝膜经验及其追问，不代表全部ARKS工艺与源码问题通过。没有执行设备程序或验证实际工艺效果。

发布后刷新正式页面，新开对话测试同一句问题；确认图形可见、经验引用能打开对应版本、原图仍按既有逻辑展示。对历史版本失效的旧会话应重新检索资料，不能复用过时引用来证明本轮事实。模型输出有波动，发现事实问题或核查未完成仍允许安全降级。
