# 代码修改循环修复与开阀案例复测

日期：2026-11-05。

## 原问题和修复

用户实际聊天触发116步执行上限，耗时约3分22秒。日志中60次工具请求，包含42次原源码批量读取，其中相同范围重复37次；副本版本0、无修改、无需求测试、未开始仿真。

旧 RetrievalBudget 包围全部工具，把副本准备、定位、读取、编辑和验证一起计入源码检索额度。进入保留额度后，副本工具被拒绝并要求转用原源码读取；检索耗尽又设置全局 tool_choice=none。与此同时，同版本缓存读取免费但没有防重复退出条件，导致反复读取也不能推动预算结束。

修复按实际注册的代码副本工具确定独立工作流：这些工具由自身的版本、验证次数和停止规则控制，不扣源码检索额度。进入复核或耗尽阶段时，只收紧来源工具，副本读取、编辑、需求断言和仿真仍可调用。普通问答继续保留检索上限及供应商协议对应的结束方式，没有提高图执行上限。

同一来源读取在没有新的读取内容或副本操作的情况下，命中缓存三次后停止重复来源读取；路径/范围不同的缓存读取仍免费，读取理由换词不能绕过判定。修改请求可以继续副本流程，普通问答根据已有内容结束。补充 CountCalls 的方法体接口、作用域、完整业务类型名及同一需求断言先失败后通过的规则。
