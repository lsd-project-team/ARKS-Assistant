# 源码检索与业务步骤专项验收

日期：2026-10-30。用户指出“取片的步骤”回复杂乱，认为后端组织导致前端难以展示，并明确允许去掉结论复核。本轮在此前源码回答组织更新基础上继续实现。

## 原因与修改

在当前账号页面读到实际回复：把`BondHeadController.PickAction`作为完整取片流程，长段展开局部实现、嵌套分支和异常细节，末尾追加大量结论复核意见，还关联上一轮蓝膜经验。真实隔离复测确认，仅增加入口与组织提示仍会选旧控制器；“取片”的前100条命中集中在9个控制器/界面文件，没有当前动作节点。

本轮修改：

- Agent宽范围搜索按文件分散返回定位片段，优先字面路径匹配、非生成实现和任务/动作入口；每文件最多4条，再按文件轮流补充，截断如实标记。启发式只提供线索，结论仍依赖实际读取，不按业务问题写死文件或答案。
- `search_source`与Agent文件协议的`grep`共同采用该策略，多源码目录保留稳定前缀。目录/文件范围先于结果截断，修复先取全库前100条再过滤导致限定目录漏命中的问题；指定单个文件的grep仍可返回其完整限定数量。源码浏览器沿用原有默认搜索语义和HTTP参数。
- 主模型先确认业务入口及当前调用场景，再按业务阶段组织步骤；聚焦本题阶段的分支，方法名、日志、公式和异常实现不主导正文，不额外关联前文故障。复用step_flow、Markdown及Mermaid，前端不重写内容。
- 按用户要求，聊天装配不再给`SourceEvidenceGuard`接入结论复核模型，不发送`source_verification`请求或追加新的复核结论。文件路径、行号、当前版本与工作区身份校验及必要补读保留。经验事实核查保持原有范围；历史复核事件和旧回复不删除，离线复核辅助实现保留。
- 实测还发现一次模型漏写富内容JSON末尾括号，造成原文降级。只有已结束回答出现JSON/围栏语法损坏时，才沿原模型链最多修正一次，要求保留正文、块ID及来源元数据；合法内容、未知类型/版本及未完成流不触发该修正。无独立事实或排版复核，失败仍降级，不静默丢弃内容。

没有新增依赖，没有修改数据库、HTTP/SSE协议或只读业务源码。
