# Rich Content 真实模型与历史页面验收（2026-10-20）

## 结论

本轮已实际执行真实供应商问答和真实历史页面抽查。真实模型读取当前业务源码后，生成的合法步骤块、对照表经过原引用校验和语义复核，最终通过原 SSE、消息持久化和聊天页面展示；源码预览、定位、复制和刷新恢复均已操作核对。

已抽查当前登录账号的 6 个真实历史会话，覆盖普通问答、长技术文章、Markdown 表格、嵌套列表、多代码块和密集源码引用，并检查了固定版本原图。

**已测 UI 链路通过；不代表所有业务回答的语义质量通过。** 宽范围标定题仍触及原有源码复核预算，出现 `unknown` 和正文复核提示。本轮保留这些结果，没有用小范围成功案例替换或掩盖它们。真实模型仍可选择普通 Markdown，不保证每次都使用卡片。此前工程回归范围见[基础验收](chat-rich-content.md)。

## 环境与数据边界

- 使用本机当前配置的 DeepSeek-V4-Flash，Anthropic 兼容协议，temperature=0.2、上下文上限 1,000,000、配置回复上限 4,096。未使用模型替身，也未改正式模型配置。
- 新问答通过 `scripts/verification/rich_content_ui.py --live` 启动，后端 8877、Vite 5181，源码只读使用当前 `trunk/`，数据保存在 `output/rich-ui-yu5w4x_r/data/`。供应商密钥仅在内存读取，未复制到该隔离目录。
- 关闭隔离服务的 MCP、DeepWiki 和自动记忆；实际检索依据为 ZX2200 及轴补偿工程的现存源码。没有向正式库写入测试对话或资料，没有运行设备程序。
- 历史抽查使用新版 Vite 前端 5180 代理现有 8765 服务，用户通过正常登录访问自己的历史。页面读取、源码和资料引用走原账号权限；为补找嵌套列表，以该账号已导出会话的 owner_id 为边界，只读筛选同账号消息，再回到页面检查。未读取其他账号的对话；原文导出保留在本机忽略目录，未提交历史正文、原图或账号凭据。
- 最初两个服务共用 `127.0.0.1` Cookie 导致历史页掉线；改用 `localhost:5181` 作为隔离模型页面，用户重新登录了 `127.0.0.1:5180`。复现时应从一开始使用不同主机名。
- 本轮没有替换正式 `frontend/dist`，没有重启正式后端。
