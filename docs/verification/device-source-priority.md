# 设备业务问答的主工程优先规则

日期：2026-10-19。

## 行为变化

设备业务问题优先在当前项目的 `AKRS.ZX2200` 主工程中查业务入口、操作界面、任务流程和前置条件，再根据已读取的调用关系查其他工程。用户明确指定文件或附带选区先核对；主工程没有找到相关实现时，说明已查范围再扩展检索。源码根已经是主工程时直接从根查找；其他项目不套用 ZX2200 路径。

系统提示始终携带规则，不依赖知识资料、记忆或 DeepWiki 开关。设备主题与流程、操作、条件、原理等问法同时出现时，即使没有代码选区，也启用源码证据核查。原有代码问法、选区与深度模式继续沿用核查机制。

## 测试结果

- 测试文件：`test_device_business.py`、`test_source_evidence.py`、`test_paused_knowledge_sources.py`、`test_source_options.py`、`test_analysis_runtime.py`、`test_analysis_workflow.py`、`test_source_review.py`、`test_stale_selection.py`，均在 `backend/tests/integration/` 对应业务目录下。
- 用例：47；通过：47；失败：0；跳过：0。项目虚拟环境中执行 `python -m pytest -q`，指定上述八个文件，耗时34.79秒。
- 新增用例14项，覆盖设备标定、吸嘴校准、固晶取片、点胶晶圆顺序、回零前置条件、反向问法和跨行问法，以及历史经验、普通聊天、非设备流程的反例。
- 实际 Agent 图使用确定性测试模型，确认优先规则进入系统上下文，关闭三个可选来源后仍存在；模型不读源码时，回答包含源码核对提示。
- 变更的四个 Python 文件通过 Ruff 检查与格式检查；覆盖率未采集。

修改前新增测试复现了设备业务问法未要求源码证据、系统上下文缺少优先规则的问题。首轮实现仅按设备词识别，回归发现历史处理经验也被强制核查，现已改为结合设备主题与提问意图识别，并保留反例。未调整原有测试预期。

## 运行与边界

通过只读聚合计数确认没有活动对话、项目阅读、代码验证或排队问题后，使用仓库的停止和启动脚本重启本地服务，重新加载规则；健康检查通过。

测试数据均位于临时目录，未调用真实供应商、未运行设备程序。业务源码保持只读。优先顺序由系统提示指导模型执行，源码证据核查不强制每次工具调用的目录顺序；真实供应商是否遵循顺序、生成的设备流程是否正确仍需实际验收。自然语言识别使用关键词，不代表覆盖全部表达。

测试质量评估：中。已覆盖规则接入、关键识别分支和相关回归，未验证真实模型遵从性和设备业务语义。
