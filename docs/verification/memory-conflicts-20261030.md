# 长期记忆轻量冲突处理验收

## 最终行为

- 发布前对同账号、同项目的相关条目核对关系：重复、补充、条件不同、明确更正、未决冲突及无关。
- 模型只返回候选关系和原始编号。更正必须引用替代条目中存在的用户原话，并具备明确变更措辞；无充分依据的替代降为冲突，不按保存时间覆盖。
- 原始提取、各方依据和替代历史保留。读取时合并重复或补充条目，已替代事实及其重复来源退出当前事实召回；连续更正可沿链生效，替代环或互不兼容的替代降为冲突。
- 冲突各方组成一个读取单元，只作为待核实线索。模型不能用成员编号绕过整体复核，程序不能因预算只装入其中一方；原聊天或任一成员变化使旧选择失效。
- 设置中的记忆正文、可读文件显示状态及关联记录；原聊天及历史运行快照不重写。旧快照在后台按原有权限、闲置、开关和额度规则补检，复用原提取结果，不受原聊天30天候选窗口限制。

实现归属：`backend/app/modules/memory/`。关系协议、状态计算和读取单元位于 `conflicts.py`，候选比较及分片位于 `reconciliation.py`，沿用已有生成、原子发布及模型复核流程；未新增数据库表、人工裁决入口或代码修改工具。

## Test Limitations / Untested Risks / Quality

- 相关候选每条最多12条，可能漏召回；模型可能误判关系及适用条件。原文存在性校验和变更措辞检查不能证明归纳绝对正确。
- 本轮未执行真实供应商语义效果评测、正式业务冲突裁决、浏览器交互或设备验证；未修改前端，不重新构建前端。设置展示通过现有Markdown读取同一后端投影。
- 更正自动生效保守地限于可验证的用户明确变更依据；其他表达可能保留为冲突，源码事实仍须重新核查。
- 不保证回答模型必然遵守冲突提示；程序保证已识别冲突不被拆分带入，但事实正确性仍依赖证据核查。
- 质量判断：中。程序状态、持久化与上下文边界有正反例和集成验证；真实模型识别效果尚未验收，完整回归存在已独立复现的历史失败。
