模拟厂商 SIM-WAFER-B 改用 `.svb.csv`：左下原点、从 1 开始的 X/Y 坐标，BIN 0/9/255 分别转换为 1/2/空位；缺省点填 `.`。要求旧 Map 兼容、新复合后缀按载具名定位、在实际 `Block.LoadMap` 入口转换后交给现有 WaferMap 库。还检查 BOM/换行/字段空白、非对称网格、重复/越界/非法输入、原件及有效缓存保留。

文档通过真实附件 API 上传，并由模型的 `read_chat_attachment` 读取。历史输入为 `backend/tests/fixtures/wafer_vendor_b.md`，修正版为 `wafer_vendor_b_v2.md`。v1 模拟规范误用了 `Flat_Notch : Down`；实际库只接受 Top/Right/Bottom/Left/Unknown，v2 明确输入 DOWN 不变，输出 Bottom。此项是本次测试资料错误，不归因于模型违反原文，也未以修改第三方库掩盖错误。

## 改动与独立检查

隔离副本只改两个业务文件：

- 新增 `AKRS.ZX2200/WaferSubSystem/Services/SimWaferBMapAdapter.cs`。
- 修改 `AKRS.ZX2200/WaferSubSystem/Models/Entities/SearchChip/Block.cs` 的 Map 导入入口。

独立程序 `backend/tests/fixtures/wafer_vendor_checks.cs` 不采用模型给出的预期，覆盖正常、边界和非法输入，检查旧格式及新厂商原件、重复导入更新、非法输入不覆盖有效缓存。它反射检查真实编译调用路径，实际执行 LoadMap 的查找、复制及转换，仅替换最后的 UI 打开动作；参数对象使用隔离数据，避免构造真实硬件。再调用实际 `AKRS.WM.WaferMap.LoadFile` 读取既有样例及新结果，核对 3×4 大小和 ID。

独立程序早期因参数构造依赖未初始化控制器而失败，归类为验收夹具问题，改为注入无设备依赖的参数对象后重跑；没有将该环境错误算作业务缺陷。`independent-1/2/3` 为诊断，`independent-4` 是业务通过但模型用例仍失败时的检查，`independent-final` 才是最终当前通过构建的独立复验。
