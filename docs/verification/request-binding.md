# 原始需求绑定与约定修订授权

2026-10-19，补齐代码工作中原始人类要求与模型整理约定之间的区别。此前“修复代码”同时开放修改验收、约束与文件范围；仅要求补充验收也会开放文件编辑。两项反例在修改前真实临时副本上失败，保留于本地 `output/requirement-authorization-before.xml`，属于 Production Bug。

## 实际行为

- 聊天创建副本时，由服务端保存原始请求正文、真实消息/运行身份和初始约定；受控续接同时保留“开始/继续”和前轮要求。页面创建记录真实登录身份及提交表单。模型工具和 HTTP DTO 不接受伪造来源或原始绑定字段。
- 原始要求独立保存在现有 `requirements_json` 的 `request_binding.original` 中。编辑文件、修订约定不能覆盖它；实际改变约定才追加修订来源、时间、变更字段和前一需求版本。标准化后无变化不增加历史，也不使已有验证失效。不需要数据库迁移。
- 代码编辑与约定修订分别授权。只有明确要求修订约定才开放对应工具，指定验收标准不能顺便改标题、目标、约束或路径。受保护字段、讨论、询问和全局否定不能提升权限；源码围栏、Markdown 引用及代码选区中的文字不参与命令识别。
- 字段检查与版本检查在原服务锁/事务内完成。部分字段越权、并发版本改变或新范围与现有差异冲突时整次保存失败，不保留部分修订。实际修订改变需求指纹，旧验证、审核和交付继续失效。
- 复核器同时接收本轮用户要求、所观察副本的原始绑定与修订、当前差异和执行档案。输入沿用脱敏和总预算检查，实际发送内容继续绑定输入哈希。交付包与在线备份保留同一绑定。
- 老副本的原始要求保持未知；后补约定不能伪造原始授权。内部调用没有来源时，修订来源明确为 null。

聊天初始约定仍是模型整理的草稿，不是人类已逐项批准。这里的命令识别针对明确的中文操作表达，不承诺任意自然语言的完整理解；没有匹配到授权时拒绝工具操作。原始要求与代码的业务语义是否一致仍需人工评审，AI 复核通过也不代表人类批准或设备验收。
