# 最终依据核查改为只读

2026-11-02，按用户确认的规则完成：第六步的答案保持原文；第七步只检查，发现具体问题时在正文末尾补一句，来源仍在最后。

## 实现范围

- `backend/app/agents/runtime/knowledge_answer.py`：模型只返回`verdict`和`note`。一次有效事实复核后结束，忽略额外的替换答案，不再生成修订稿、终审稿或摘录降级。通过不附加文字；服务失败、超限或协议最终无效只记录运行详情。协议无效仍沿用一次JSON重试。
- 核查仍接收已选经验片段、其完整记录及混合回答实际使用的源码上下文，检查数值、单位、条件、结果和引用；不评排版，不将合理推断、已有不确定性或未问背景当成缺项。
- `backend/app/modules/source_analysis/evidence.py`：保留源码路径、行号、版本和目录检查，取消自动补查、改稿和删除原引用。只为具体失效引用提供一句定位说明；缺少可定位引用的情况留在运行结果，不再补固定提醒。生产聊天未开启额外的源码语义复核模型，本次未改变该设置。
- 新增`backend/app/agents/runtime/answer_review.py`统一补句。事实问题优先于引用问题，最多一句短纯文本；拒绝链接、HTML、过长或空说明，防止复核返回另一份答案。原文字符不替换，纯来源段前只插入说明；结构化内容保持原协议，由现有前端统一把来源移到最后。
- 新事件`answer_review_note`保存原答SHA-256及插入区间，便于验证去掉补句后原文一致。没有额外保存一份原答。原有最终回答、历史及SSE保存机制保持。
- 清理未使用的源码修订提示，同步查询路由与回答格式说明。未修改前端生产代码、数据库结构、账号权限或正式知识内容。

## 真实模型检查

四项定向检查使用合成经验与临时`Program.cs`：

| 场景 | 结果 |
| --- | --- |
| 参数与条件正确 | 原答完全一致，无补句，1次事实复核 |
| 把未标单位写成μm | 原错误句保留，只补“记录未标单位”的具体说明，1次复核 |
