# 移除自动追加的源码核对提示

日期：2026-11-01。

## 变更

用户明确要求无条件移除回答末尾自动追加的“源码核对提示：……上述相关结论仍需核对。”。本轮只删除源码引用核对中间件追加这段正文的逻辑，不调整问题分类、检索策略、最多两次补核对、校验规则或经验事实核查。

核查失败仍写入 `answer_validation` 事件；确有无效路径、范围、版本或目录身份的源码引用继续降为不可点击文字。纯经验答案在源码核查失败时保持原回答，不因没有源码引用被附加固定尾句。合法引用、富内容结构和运行回放沿用原机制。

修改只影响新生成或重新生成的回答，不改写正式历史消息、业务资料或只读源码。没有向正式数据库写入验收对话，也没有调用真实供应商。

## 验证

复用现有临时数据库、测试模型及真实Agent流程。新增4个参数场景，覆盖无需源码的经验回答、被要求源码但未读的经验回答、读过源码但最终只引用经验、合法源码引用；分别断言完整正文、补核对次数和保留的校验事件。

既有坏引用、混合经验与结构化源码、重新生成以及设备问题的测试同步改为检查尾句缺席，并继续验证无效引用停用、错误核对结果、版本/目录边界和事件回放。

4个测试文件、60项用例全部通过，失败0、跳过0；Ruff检查及格式检查通过，覆盖率未采集。测试覆盖本次变更的正常、缺引用、无效范围、版本和目录冲突、混合经验、重新生成及持久化/事件回放；未做真实供应商、设备或新回答浏览器验收。测试质量判断为中：真实执行核对和Agent链路，模型使用确定性替身，因此不评价实际模型的语言或事实质量。

后端已按启动约定重启，健康检查正常；原登录按既有规则失效，需要重新登录。82条正式问题与经验的编号、版本和正文摘要与重启前一致，正式历史消息不改写。
