# 后台长期记忆验证

目标：移除聊天即时保存及手动条目管理，以后台闲置聊天提取、持久化、整理和后续带入替代。旧文件归档，不清除原始聊天与历史版本表。功能契约见[后台长期记忆](../features/background-memory.md)。

## 核查范围

| 要求 | 对应证据 |
| --- | --- |
| 闲置筛选，排除运行中、短聊天、关闭来源和过期聊天 | `tests/integration/memory/test_background_memory.py` 使用真实 SQLite、原始问答与受控闲置时间 |
| 原文依据核查及个人偏好归属 | 无效消息引用、助手冒充个人偏好的反例 |
| 提取、整理与后续带入 | 真实数据库/文件的端到端后台测试；真实供应商合成场景 |
| 重启、重复扫描、失败后复用 | 租约恢复与持久化提取结果的反例；重复扫描不再调用模型 |
| 发布一致性 | 输入变化、途中关闭、租约失效时拒绝发布；原完整版本保留 |
| 账号与项目隔离 | 共享项目下的普通用户/管理员只读接口；运行快照脱敏及队列账号回归 |
| 旧功能退出 | Agent 装配不含 `remember`；旧写入、复核、历史恢复接口退出；新页面只读 |
| 数据保护 | 旧文件一次性归档；旧备份恢复保持；新数据库与生成文件共同恢复 |
| 供应商和上下文边界 | 输入/生成字段脱敏、长度预算、项目日额度不足时暂缓 |

2026-10-29 已运行真实供应商验证，合成聊天完成提取、整理和后续带入，生成两个 Markdown 文件；重复扫描复用完成状态。验证仅使用临时数据库和合成内容，没有发送正式聊天。

后端整仓回归：98 个测试模块、835 项，833 通过、2 项环境跳过、0 失败；前端 347 项通过，TypeScript 与生产构建通过。相关 68 项回归、新增后的 28 项定向检查及独立导出的提交版本 25 项检查也通过。随后修正候选时间范围与长期成果保留的边界：标题等元数据不改变事实指纹，后续整理复用仍有效的既有成果；受影响的 44 项及最终记忆模块 20 项检查通过，包含跨月与原始输入窗口轮换反例。Python 改动使用 backend 工作目录下的项目 Ruff 配置核对。

本机正式服务已更新，数据库迁移到 `0027`。部署前已生成本地备份；8 张正式业务表的记录数量及逐表内容哈希与部署前一致。本机没有旧记忆文件和符合闲置条件的聊天，没有强行把短聊天或旧记忆转换成新成果。后台任务启动与关闭由真实应用生命周期测试核对，后续按既定间隔筛选。

## 测试说明

模型网络在常规测试中使用确定性替身；筛选、指纹、原文核查、状态持久化、租约、文件发布和读取均运行真实实现。既有手动条目管理和即时保存行为的测试随功能删除，备份、上下文快照、来源开关和账号边界改用真实生成快照或明确的旧档案数据验证。

未采集覆盖率和变异测试。真实模型合成场景证明本次连接与流程可用，不代表所有业务聊天的提取准确性已验收；模型可能漏选、错归纳，最终仍须依据当前源码和具体条件判断。全程不运行设备程序或 Docker。

测试质量判断：状态持久化、权限、来源失效与发布边界的回归证据较充分；语义准确性仍仅完成合成场景验证，须继续通过真实业务样本评估。测试未采集覆盖率，也未做设备验收。

关闭边界补测：先复现来源任务已删除时状态回写抛出 `memory_lease_lost`、覆盖原取消信号的问题，再改为取消清理尽力回写并始终继续传播取消。最终记忆模块 21 项通过；该修正避免后台在应用关闭后因清理异常继续轮询。
