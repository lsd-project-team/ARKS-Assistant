# 检索前问题识别与查询路由验证

目标：用户要求先判断资料需求，“你好”和 Vue 介绍等普通问题直接回答，不再每次检索问题与经验。功能契约见[问题识别与查询路由](../features/query-routing.md)。

## 实现与验收范围

主模型结合当前问题和前文决定直接回答或调用工具，不增加独立分类请求。图装配只提供允许使用的查询工具定义；`DebugIssueLookup` 在第一次查询或实际引用时建立问题库快照，同轮并发调用共用版本。未查询的来源不伪装成已带入记录。

| 边界 | 证据 |
| --- | --- |
| 普通问题在开启/关闭经验、存在/不存在前文时均不查库 | `tests/integration/chat/test_general_with_knowledge.py`，问候、Vue、HTTP/WebSocket、翻译共32种组合；问题库构造函数被禁止，真实 Agent 图仍正常回答、入库与回放 |
| 不因装配定义或空复核而加载记录 | `tests/integration/knowledge/test_debug_lookup.py`，工具定义和未使用引用的副作用断言 |
| 第一次实际调用冻结版本，同轮复用，下轮读取新版本 | 同文件，真实 SQLite 修订与工具调用 |
| 并发快照 | 同文件，8次并行读取只建立一个快照 |
| 前文引用的继续追问 | 按编号与版本实际读取，再执行原文片段筛选和事实核查，不执行相似度搜索；真实对话及上下文来源验证 |
| 引用不存在或版本不符 | 无法核对时拒绝放行原答；单元和真实记录反例 |
| 经验问题仍走查询工具并保留事实修正 | 经验核查、暂停来源、`/记录问题`后续问答改为真实工具请求；原始录入人、原文、版本和引用断言保留 |
| 源码流程与重新生成 | 源码工具、引用补核对、结构化流程、缺证据修复和旧回答档案的既有组合回归 |

## 真实模型

实际执行 `scripts/verification/general_question_with_knowledge.py --live`，仅发送合成问题、合成资料和测试历史，关闭记忆、DeepWiki 与 MCP，使用空源码和临时数据库。供应商配置只在内存复用，不复制正式凭据。

| 场景 | 主模型等调用总数 | 问题库快照 | 相似度搜索 | 结果 |
| --- | --- | --- | --- | --- |
| 你好 | 1 | 0 | 0 | 正常问候，无经验筛选或核查 |
| 给我介绍一下vue框架 | 1 | 0 | 0 | 正常介绍，无经验筛选或核查 |
| 查询不存在日期的合成试验 | 4 | 1 | 2 | 搜索、读取后仍未选到对应日期，不套用其他日期的42 |
| 查询已有日期的合成试验 | 4 | 1 | 0 | 按编号读取，保留42与真实固定版本引用，并执行事实核查 |

调用数通过模型 `on_chat_model_start` 回调计数；流式用量事件不作为调用次数的依据。首次采用用量事件计数时发现部分流式回答未记录该事件，已改用实际调用回调验证，没有放宽“普通问题一次调用、零加载、零搜索”的断言。历史查询可按需要多次搜索，表中是本次结果。

为固定候选，真实测试对实际触发的语义搜索返回受控分数；没有触发查询时仍严格计数为零。这验证问题选择、工具路径与事实边界，不评估向量召回质量。真实模型曾在追问时直接复用前文引用，因此补上引用按编号核对的路径，并以独立反例验证。

## 路由提示词精简

随后按用户要求将路由提示词缩为三句，只区分与当前项目相关或无关。细分设备、日期、兼容性等规则不再放在路由提示中；引用和事实核查的运行逻辑保留。

真实验证发现旧能力说明“仅提供源码读取与分析”会使模型忽略经验工具，已更正为“业务源码保持只读”；查询工具说明明确本地记录库包含故障、处理办法、设备试验结果和工作记录。这些是工具用途说明，没有增加路由分类。

提示词装配、普通问答、延迟加载和经验核查四个模块共31项通过，Ruff通过；四个真实供应商场景再次全部通过，普通两题仍零经验检索。合成验证明确当前项目名称，允许问候提及该名称，同时仍禁止在未检索时输出合成记录的数值和引用。早期验证曾出现未查询或只查源码的失败，纠正能力表述和工具用途说明后复测通过，未放宽项目记录查询的要求。未采集覆盖率或变异测试，未重复整仓回归和前端构建。

质量判断：对零检索、工具触发、前文引用、固定版本、并发与事实降级有实际断言；模型仍可能误判意图，回归与四例实测不能保证所有问题均路由正确。
