# 前端发布保持登录验收（2026-11-03）

仅更新前端时，运行中的服务重新校验登录资源清单，继续使用现有登录会话；刷新页面即可加载新构建。

## 原因与实现

此前公开登录资源只在启动时加载。前端构建改变入口哈希后，新文件仍被旧白名单拒绝，发布需要重启服务；现有认证初始化会撤销全部旧会话，因此用户需要重新登录。

本次由 `StaticAssets` 检查 `public-assets.json` 和首页的文件身份、大小及修改时间，变动后沿用原完整校验，包含路径、文件身份、硬链接及 SHA-256。通过后整体替换公开集合，并发请求共用一次校验；文件操作在工作线程执行，未变化时不重复计算摘要。

清单先到、首页未替换、校验期间版本再次变化或清单无效时，暂不匿名开放静态文件，已有登录仍走原授权。清单或首页再次变化立即复查，单独修复资产后最多一秒重试。清单缺失仍关闭匿名静态访问，初始坏清单仍拒绝启动。旧哈希资源继续保留，但不因保留而自动公开。

未调整会话有效期、密码、角色、CSRF、退出或服务重启时的会话撤销。以后仅改前端时先发布资产和两份构建清单，最后原子替换首页，复用现有后端；约定已补入 `agent.md` 和[静态访问边界](../architecture/static-resource-access.md)。

质量判断为 Medium：发布切换、会话保持、失败恢复及原认证边界通过自动化和浏览器验收；未执行整仓后端回归或真实模型、设备验证。浏览器切换使用已有生产构建，正式服务未通过测试账号登录。以后仅更新前端可保留仍在有效期内的登录；主动退出、会话到期、后端升级或恢复数据仍按现有认证规则处理。
