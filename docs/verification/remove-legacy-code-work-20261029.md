# 清理旧代码修改流程

日期：2026-10-29。

## 授权范围与结果

用户要求清理原来的代码修改思路，并再次明确“只清理我们的，不开始编写Codex逻辑”。本轮删除97个专用文件，移除隔离修改任务、需求约定与修订授权、预设验证命令、环境探测、Linux/Windows执行器、审核、交付及从验证档案录入经验的接口和实现，也删除对应残留组件、类型、样式、工具、资源和专项验收脚本。没有开发新的编辑、终端、自动命令选择、Git工作树或Codex接入逻辑。

聊天不再装配旧修改工具；检索预算不再为修改工具保留独立额度，恢复问答时不再恢复修改引用，源码结论复核不再读取旧需求、差异和验证档案。系统提示明确当前仅能读取、分析源码和给出修改建议，不能声称已经修改文件或执行命令。管理端不再显示项目验证命令配置。

保留源码搜索、读取、调用分析、有效历史上下文、问题与经验、记忆和来源核查。原修改模块中两项通用依赖已拆出：模型Token额度预留/结算归`settings/model_ledger.py`，聊天归档的路径与完整性检查归`infrastructure/storage/files.py`。沿用既有额度和存储格式，不重置用量或放宽默认日额度。

旧数据库表定义移至`infrastructure/database/legacy_code_work.py`，只用于既有迁移、历史档案与备份兼容。没有旧修改服务、接口、执行器或启动恢复任务。已有正式数据不删除，清理89个已无源文件的孤立Python字节码文件。
