## 检查结论与修改

原实现已经给模型提供 Markdown、列表、表格及富内容协议，且在实际 Agent 图装配；不能据此认为后端没有考虑展示。薄弱点在于组织要求笼统、组件语法占较大篇幅，经验修订也未明确保留原有展示结构。格式中间件验证合法性，不判断阅读质量。

`agents/prompts/system.py`增加可执行的组织要求，由`runtime/graph_builder.py`放在协议及运行背景之后。参数分项、条件紧邻、对比维度一致、图文互补；保留简单回答、用户指定格式与自主选择。经验工具和事实修订提示同步，修订时保留无争议块、引用与id，并同步更正图表和正文中的错误数据。没有增加独立排版请求、确定性正文改写或新的失败放行规则。

这属于生成提示和修订约束调整。基线样例中的事实修订也成功保留了图表，本轮没有复现一个“所有修订都会丢失结构”的确定性缺陷，不能将新增提示描述成修复了必现的组件删除。

## 尚存限制

A/B是同一配置下的少量模型采样，不能给出总体改善率。流程样例仍会在步骤组件后重复部分分支，方案比较也偶尔追加未要求的假设条件，因此不能称所有回复的阅读质量已经验收通过。直接模型A/B没有完整检索及事实核查，不能将其中的解释当作设备结论；蓝膜实测采用了完整调用链，但仅一条经验。
