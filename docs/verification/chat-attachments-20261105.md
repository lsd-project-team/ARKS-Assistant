# 聊天附件与依据文档改码验收

日期：2026-11-05。

## 实现范围

聊天上传支持 DOCX、文本 PDF、XLSX、CSV、约定的源码/文本/配置格式及源码 ZIP，提供批量选择、逐项解析状态、失败重试、移除、正文分页预览和原件下载。服务端保存固定原件及解析正文，消息只绑定服务端附件编号和版本元数据。

附件贯通首次发送、历史、待发队列、问题编辑、恢复、重新生成、分支、项目移动和完整备份。彻底删除对话时检查其他引用，保留分支共用原件。模型仅能读取当前有效对话中的附件；依据文档改码复用既有独立副本、版本编辑、需求断言、编译和仿真机制。

格式限制和使用方法见[功能说明](../features/chat-attachments.md)。没有接入扫描件 OCR、旧版 DOC/XLS 或新设备执行流程。

## 缺陷与质量判断

引用保护测试检出了紧凑 JSON 与查询标记空格不一致造成的漏检，已修复并用“已绑定附件不能删除、分支引用继续保留、跨项目移动继续可读”反例覆盖。异常格式和超限内容明确失败，不把缺失正文冒充读取成功。

本轮对上传、绑定、归属、恢复、固定版本读取及文档驱动实际副本修改有接口、状态、模型图、浏览器和真实供应商证据。真实模型仅覆盖上述明确需求，仿真不替代视觉、力控、标定或真实设备验收。
