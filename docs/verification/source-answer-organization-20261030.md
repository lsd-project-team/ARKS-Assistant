# 源码回答组织验收

日期：2026-10-30。针对“检索到的代码回复也要优化，展现效果很差”的反馈，调整后端源码问答生成和证据修订提示。

## 范围与实现

新增`agents/prompts/source_answer.py`，区分方法作用、流程分支、问题原因与修改建议。修改建议默认聚焦现有文件、方法和最小代码，不附带多套未请求的接口重构；代码可复制，固定版本引用放在相应正文或代码块外。

`TaskGuidance`保留源码系统规则，并在当前模型请求末尾放置一次带固定id的控制提醒，明确不是新用户问题，用户的格式、原文要求优先。原有消息、工具调用与返回均保留；提醒仅用于该请求，不写聊天历史，也不继承到后续普通问答。引用修复与语义修订共用组织要求，模型仍有自主选择展示格式的空间。

没有增加独立排版模型调用，没有正则重排最终正文，也没有修改前端、正式数据库结构、来源权限或只读`trunk/`。保留现有引用与语义核查和失败提示，不为外观放行未核实结论。源码复核新增明确边界：部分已读文件不等于整个工程，事件日志不等于硬件动作，没有显式throw不证明绝不抛异常。

还对额外改稿请求做过本机对照，改善不稳定，因此未接入产品调用链。当前仍由主生成与既有事实修订落实组织要求，没有引入第二套最终排版器。

## 限制与质量判断

发布前确认无活动问答，完整备份保存到本机`output/source-answer-20261030/publish-before.sqlite3`。同项目、同数据目录后端重启后，健康接口与首页通过；账号、项目、聊天、运行、交接记录及修订/图片数量一致，交接正文、历史修订和图片字节逐项一致。沿用原启动机制，旧登录会话失效。没有将本轮测试账号、对话或源码导入正式库。

样本少、模型有波动，无法给出总体改善率或保证所有长对话效果。事实修订可能重新扩写，复杂流程仍可能重复；需要更多业务题和实际页面阅读评价。没有执行或编译模型建议的C#代码，也没有设备测试，原文件及正式业务数据未用于这些合成场景。
