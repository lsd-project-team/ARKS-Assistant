## 修复行为

- 引用处的当前源码优先，再补齐本轮实际读过的相关调用、测试文件；检查版本，合并已包含的范围。未读文件不带入，过期或超出预算的资料明确记为遗漏，不把复核自动扩展的片段当成回答模型已读。
- 只记录创建、读取副本/差异或验证时实际选择过的修改 ID，复核时从当前项目服务重新取得差异、约定和验证历史。历史工具消息、模型自述、未选择的旧修改不能充当执行证明；恢复运行只恢复身份，再回读当前档案。
- 检查副本、源码、需求和验证配置的身份，保留失败及过期记录。普通可信宿主命令与真实容器证明分别标记，命令通过、人工审核、交付保持不同状态。
- 日志与差异先脱敏再裁剪，避免裁掉敏感赋值前缀而漏出值。日志尾部、差异、修改数量和历史记录均有界，截断、缺失或遗漏明确标记；不向复核器重复发送命令 argv。
- 复核调用等待期间再次发生源码、约定或执行档案变化时，不能沿用 passed；降为未知并去掉失效的源码链接。
- 新的 `source_review_context` 事件记录实际脱敏输入的 SHA256、估算 Token、文件版本与行号、修改及验证身份，不在事件中重复存放源码和日志正文。质量报告收录此事件及 `code_change_reference`。

当前单次复核保留最多 3 个观察过的修改、每项最近 4 条验证；差异最多 1500 估算 Token、每条日志尾部最多 1000。源码部分最多 8000；整个请求仍受该轮输入预算约束。遗漏不代表未发生，截断不能证明所有测试细节均已核实。
