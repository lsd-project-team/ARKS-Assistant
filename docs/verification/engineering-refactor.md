# 工程重构与功能回归

日期：2026-10-16。

本次将应用整理为模块化单体，保留既有功能、接口、运行数据和 Windows 启动方式。交接工作台分离领域规则、应用用例、仓储和 HTTP 接口，其余业务按实际复杂度保持轻量。

## 完成的结构调整

- 后端按账号、项目、聊天、源码分析、知识、记忆、交接、设置和管理业务归类。各模块拥有自己的 ORM 模型，数据库基类与统一注册保持独立。
- 应用入口与装配分开；业务模块不导入启动装配。Agent 的入口、图构建、执行、提示词、源码工具、历史工具和调试录入工具分别维护。
- 交接状态与固定版本规则放在领域层，写入命令放在应用层。用例通过接口接收仓储、解析、导出和模型候选生成实现；应用层不导入 SQLAlchemy、FastAPI 或具体适配器。
- 文档解析、Word/ZIP 导出和模型协议处理归适配器。作业仍固定输入版本，排队时保持原模型配置，并保留取消、失败、恢复和连接释放行为。
- 前端按功能归类；聊天、项目、源码阅读和布局状态分开组合，保留原持久化与账号隔离。交接页面中的记录查看、编辑、候选操作、交接包和复核页面分别维护。
- 通用前端 UI 与 HTTP 不依赖具体业务。带源码引用等业务交互的组合组件归应用层，交接内部公共代码留在交接模块。
- 知识资源统一迁入 `resources/knowledge/`；原 `/archify/`、`/engineering/` 和 `/agent-knowledge.json` 地址保持不变。
- 启动、维护、显式验证脚本和文档分别归类；历史构建移入 `output/`。根目录启动、停止入口和原备份恢复入口保留。
- 测试按类型和业务归类，复用测试模型与登录辅助。前端测试递归发现业务子目录，避免目录调整后漏跑。

重构前已有的消息编辑与样式修改、`InlineQuestionEditor` 和协作说明均保留在新结构中。

## 数据保护

在独立备份上核对表结构和逐行内容摘要；源码、记忆和知识资源按 SHA-256 核对。正式数据不作为测试夹具，测试账号只创建在独立临时目录。

前端发布先复制资源，最后替换首页；保留旧哈希资源，避免已打开页面引用的文件立即失效。发布的 3597 个文件与最终构建逐文件一致。

正式库全部 24 张表结构一致；启动后除登录会话外，23 张表的行数和内容摘要均一致。检查点 2 张表、6259 个源码/记忆文件及 3119 个知识资源文件均一致，源码和记忆的文件集合也没有增减。私有配置和初始账号文件在启动前后的指纹一致。

原有 `AuthService.initialize()` 在重启时撤销全部旧登录会话。本次 5 条旧会话变为 0 条，方法语法树与重构前完全一致，且认证回归覆盖了此行为。严格逐表报告仍如实记录这一差异；`restart-data-audit.json` 单独核实其来源，没有将所有运行表变化笼统忽略，也没有恢复旧凭证。

重构前已有的 7 个前端文件通过 TypeScript 语法树和 CSS 结构核对，排除路径迁移与格式调整后内容一致。
