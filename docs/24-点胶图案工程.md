# 点胶图案工程（AKRS.Galaxy2.Dispense）

> 点胶图案（Epoxy Pattern）的离线编辑器：操作员在这里画出/导入点胶轨迹点、给每段配速度与延时、把图案存成 `.ep` 文件，供主程序读取成 `EpoxyApplication` 后再转成运动指令。
> 代码规模：70 个文件 / 10,560 行（不含 `*.Designer.cs`；含 Designer 共 82 个文件 / 13,645 行）

> **阅读前必读（工程史）**：本工程改过两次名。当前真名是 `AKRS.Galaxy2.Dispense`，前身依次是 `AKRS.DispensingPattern`、`AKRS.EpoxyPatternEditor`。仓库里同时躺着这三代的产物，详见第 3.0 节与第 8 节第 1 条。**改动本工程前先读 3.0 节**。

---

## 1. 模块定位

本工程是一个**独立的 WinForms 图案编辑器**，职责边界非常清晰：

| 做 | 不做 |
|---|---|
| 在控件上画点胶折线（多条曲线） | 不做运动轨迹插补 |
| 每条线段配 `MaxSpeed`/`EndSpeed`/`Acc`/`Time`/`PreDelay`/`PostDelay`/`Dummied` | 不访问任何硬件（无 `HardwareRepositoryService` 调用） |
| 把图案存成 `.ep`（XML）+ `.bmp`（背景图）+ `Snapshoot_*.bmp`，并管理这个仓库目录 | 不写 Recipe，不碰 `AKRS.Galaxy2.Recipe.dll` |
| 通过 `EPEData` / `EPEPointData` 与外部交换数据 | 不引入 ETEL / 固高 / 雷赛 三方运控 |

**在整机流程中的位置**：

```
操作员在 主程序 界面
  → UcEpoxyApplication（点胶应用设置页，含一个内嵌 EpoxyPatternControl 预览）
  → 点「编辑图案」→ 弹 EpoxyPatternForm 模态框（本工程的图案编辑器）
        UcEpoxyApplication.cs:241-282
  → 编辑完 → GetContent() 返回 EPEData      EpoxyPatternForm.cs:1274
  → 主程序 把 EPEPointData[] 逐点搬进 EpoxyApplicationLocation[]（含坐标旋转/缩放/偏移）
        UcEpoxyApplication.cs:291-332
  → 存 EpoxyApplicationRepository.json     ZX2200PathConfig.cs:105
  → 生产时 DispenserMoveHelper.Interpolation 逐段下发运动
        AKRS.ZX2200/DispenseSystem/Services/DispenserMoveHelper.cs:53
```

**上下游**：

- **上游**：`AKRS.ZX2200/DispenseSystem/Controls/Setting/EpoxyApplication/UcEpoxyApplication.cs` —— 唯一的宿主，用 `ProjectReference` 直接引用本工程。
- **下游**：无。本工程不被任何其它 `AKRS.Galaxy2.*` 平台层引用（`AKRS.Galaxy2.PR`、`Machine`、`Calibration` 等工程均不引用它）。
- **本工程自己也引用了一个平台 DLL**：`libs\AKRS.Base.dll`（`AKRS.Galaxy2.Dispense.csproj:43-45`），只用来做 XML 读写（`SXml` / `SXmlTagAttribute` / `SxmlTagAttributes`，见 `PatternFile.cs:8,59,130,215`）。

> ⚠ `AKRS.Galaxy2.Dispense` 这个名字在本仓库里**有两个不相干的含义**：本工程（图案编辑器，2.2.7.0）和 `AKRS.ZX2200/libs/AKRS.Galaxy2.Dispense.dll`（平台层小 DLL，1.0.0.0，无源码，只有 `DispenseEntity`/`DispensePoint` 两个类型）。两者 GUID 不同（`49dbb2e6…` vs `d9ffc013…`），但**程序集简单名相同**。见第 8 节第 2 条。

## 5. 关键实现细节

### 5.1 坐标系与三层坐标

这是本工程最容易搞错的地方。同一个点在三个层里各有一套坐标：

| 层 | 类型/字段 | 单位 | 换算 | 出处 |
|---|---|---|---|---|
| 逻辑坐标 | `Endpoint.LogicalPoint` / `EPEPointData.Point` | **像素**（注意不是 µm！） | 原点在 Die 中心，y 轴朝上（笛卡尔） | `Endpoint.cs:15` |
| 实际/像素坐标 | `Endpoint.RealPoint` / `RealRectangle` | 控件像素 | `x = origin.X + logical.X * scale`<br>`y = origin.Y - logical.Y * scale` | `EpoxyPatternControl.cs:1632-1638`（`CreateRealPoint`） |
| 反向 | `ConvertToLogicalPoint` | — | `x = (px - origin.X)/scale`<br>`y = (origin.Y - py)/scale` | `EpoxyPatternControl.cs:1610-1615` |

- `origin` = 控件位图中心（`InitBackgroundBitmap` 返回 `bitmapCenter`，`EpoxyPatternControl.cs:1060-1077`），由 `RebuildBackgroundBitmap`（`:903`）在尺寸变化时重算，并通过 `LogicalCoordinateSystemOriginChanged` 事件通知 handler（`:948-965`）。
- `scale` 是**放大倍数**，`SetScale` **只接受 `>= 1`**（`:1042-1054`），所以缩小到 100% 就到底了（见第 8 节）。
- Die 尺寸传给控件前会被 `EpoxyPatternForm.cs:202-203` 除以 `micronPerPixel`，也就是说控件里的 `dieSize` 是**像素**。`EPEData.DieWidth/DieHeight` 才是原始单位（默认 350/300，`EpoxyPatternForm.cs:146-148`，看起来是 µm）。

### 5.2 持久化格式（`.ep` = XML，`AKRS.Base.SXml` 读写）

`PatternFile.SaveFile`（`PatternFile.cs:46-108`）的实际输出结构：

```xml
<EPEData>
  <MicronPerPixel value="50" />                       <!-- :63 SetAttrDouble -->
  <DieSize width="350" height="300" />                 <!-- :67-69 -->
  <Image m11="1" m12="0" m21="0" m22="1" dx="0" dy="0" />  <!-- :72-78 -->
  <DefaultInfo AltitudeCompensation=".." MaxSpeed=".." endSpeed=".."
               Acc=".." Time=".." dummied=".." preDelay=".." postDelay=".." />  <!-- :81-82, AddInfo :201 -->
  <Curves>
    <Curve>
      <Segment x=".." y=".." AltitudeCompensation=".." MaxSpeed=".." endSpeed=".."
               Acc=".." Time=".." dummied=".." preDelay=".." postDelay=".." />    <!-- :94-98 -->
      ...
```

要点：

1. **坐标是 `x`/`y` 两个独立属性**，不是 `point="x,y"`。
2. **`x`/`y` 都是 `float`**。`PatternFile.cs:166-173` 有一段 2024-07-03 的修改注释：原先用 `GetAttributeInt64("x")` 转 int 会报错，改成了 `float.Parse(attributes.GetAttribute("x"))`。**改回整数转换会破坏现有数据**。
3. **`AddInfo`（`:201-213`）写 8 个属性，唯独不写 `HeightMeasurement`**；`RetrieveInfo`（`:215-226`）也只读这 8 个，**从不设置 `HeightMeasurement`**。也就是说「测高」标志（`EndpointSetting.HeightMeasurement`，在 `EndpointSetting.cs:81-96`）**存盘即丢失**。见第 8 节。
4. `ReadFile`（`:110-199`）先读背景图，再读 XML；**任何异常都被 catch 成 `Console.WriteLine` 并返回 `null`**（`:192-196`），调用方 `EpoxyPatternForm.cs:1162-1177` 只用 `null` 判断弹「调取失败」。`Debug` 下没有 `Debugger.Break`，异常堆栈只进控制台。
5. 背景图/缩略图**存的是文件名约定，不是路径**：`<图案名>.bmp`（`:50-56`、`:118-127`）、`Snapshoot_<图案名>.bmp`（`EpoxyPatternForm.cs:1204`）。改名 `.ep` 会与它的两张位图脱钩。
6. `ReadFile` 读图时先拷成 `tmp_<Ticks>.bmp` 再 `new Bitmap`（`:124-127`），是为了绕开文件锁；`ClearTmpFiles`（`:27-44`）和三个对话框都在退出时清理 `tmp_*.bmp`。

**仓库路径**（关键的一条）：

### 5.6 图案 → 运动轨迹的转换在哪里（本篇边界的核心结论）

**本工程内部没有任何「图案 → 运动轨迹」的转换算法。** 它产出的只是「逻辑二维点 + 每段速度/延时/高度补偿」这样的**参数集合**（`EPEData` / `EPEPointData` / `EndpointSetting`）。转换分散在两处、都在本篇范围之外：

1. **图案 → 生产数据模型**（含坐标旋转/缩放/偏移、开胶关胶标志、加减速）：
   `AKRS.ZX2200/DispenseSystem/Controls/Setting/EpoxyApplication/UcEpoxyApplication.cs:291-332`（`ChangeListPosToPatternData`，`EPEPointData[]` → `EpoxyApplicationLocation[]`）。
   反向的 `EPEData` → 控件预览在 `UcEpoxyApplication.cs:334`（`InitPatternData`）。
2. **数据模型 → 实际运动指令**（插补、开关胶、安全高度、Z 轴）：
   `AKRS.ZX2200/DispenseSystem/Services/DispenserMoveHelper.cs:53`（`Interpolation(EpoxyApplication, Axis x, Axis y, Axis z, Electric dripElectric, ...)`），逐段读 `epoxy.DispensePatternParas[i][j]`（`:342,370,432`）。

**唯一算得上「几何预处理」的转换在本工程里只有**：

- 逻辑坐标 ↔ 像素坐标（`EpoxyPatternControl.cs:1610-1638`）；
- 整条曲线的平移/旋转/缩放（`Curve.cs:238-342`，用 `System.Drawing.Drawing2D.Matrix`，`Scale` 检查 NaN 并抛 `InvalidOperationException`，`Curve.cs:322-326`）；
- 端点命中检测：`ContainsEndpoint`（矩形框内含，`Curve.cs:589-616`）与 `ContainsSegment`（点到线段最短距离 ≤ 阈值，`Curve.cs:625-642`，距离算法用海伦公式，`Utility.cs:144-180`）。

### 5.7 绘制模型

- 控件**不逐帧重画背景**，而是维护一张 `backgroundBitmap`（`PixelFormat.Format32bppArgb`，`EpoxyPatternControl.cs:914/924`），由 `RebuildBackgroundBitmap`（`:903-940`）在**尺寸变化 / 缩放变化 / Die 尺寸变化 / 背景图变化**时整体重画：铺白底 → 画背景图（`InitBackgroundBitmap_BackgroundImage` `:1079`）→ 画 50×scale 像素的虚线网格（`:1102`）→ 画点划线坐标轴（`:1143`）→ 画红色 Die 边框（`:1160`）。
- `OnPaint`（`:1335`）只做两件事：`DrawImage(backgroundBitmap)` + 画曲线 + 交给当前 handler 画提示。曲线绘制在 `Curve.Paint`（`Curve.cs:423-500`）：**其它曲线用蓝色 (`otherCurvePaintingToolSet`)，当前曲线用红色**（`:295-296`），`Dummied` 段用虚线笔，起点画空心圆、其余点画矩形（`Curve.cs:446,492-495`）。
- 缩放上限硬编码 16（`EpoxyPatternControl.cs:1780`）。

## 8. 注意事项与风险

1. **【最高优先，工程史】** `GuidAttribute` 与 `ProjectGuid` 不一致（`AssemblyInfo.cs:21` vs `csproj:7`），但**这不是缺陷**：`GuidAttribute` 只是 COM 类型库 ID，不参与 .NET 程序集标识，三代改名都没动过它，所以它反而成了「同源」的指纹。**真正需要记住的是**：本工程当前 `AssemblyName` = `AssemblyTitle` = `AKRS.Galaxy2.Dispense`（`csproj:11`、`AssemblyInfo.cs:8`），三者一致，**不存在程序集标识与工程标识脱节**。仓库里同时存在三代名字的产物（`AKRS.DispensingPattern.dll` 一代、`AKRS.EpoxyPatternEditor.dll` 二代、`AKRS.Galaxy2.Dispense.dll` 三代），清理时不要误删 `AKRS.EpoxyPatternEditor.csproj.bak`（唯一改名档案）；但 `Properties/Resources.Designer.cs` 可以安全删除。

2. **【高】`AKRS.Galaxy2.Dispense` 程序集简单名被两个不相干的程序集占用**：本工程（2.2.7.0）与 `AKRS.ZX2200/libs/AKRS.Galaxy2.Dispense.dll`（1.0.0.0，平台层，只有 `DispenseEntity`/`DispensePoint`，全仓无人使用）。`InterpolationMovementTest.csproj` 同时直接引用 stub（`:78-80`）并经 `ProjectReference → AKRS.ZX2200`（`:205`）拿到真身，同一构建里两个同名不同版本、无强名的程序集会互抢文件名。**要么给平台层 stub 改名，要么把它的引用清掉。** 主程序自身不受影响（无该引用）。

3. **【高】`.ep` 存取丢字段：`HeightMeasurement` 不上盘。** `PatternFile.AddInfo`（`:201-213`）只写 8 个属性，没有 `HeightMeasurement`；`RetrieveInfo`（`:215-226`）也不读它，且构造函数 `EndpointSetting.cs:70` 把 flags 硬写成 `EndpointFlags.AltitudeCompensation`，`dummied=false` 时也不会补 `HeightMeasurement`。操作员在窗体上勾的「测高」（写入点 `EpoxyPatternForm.cs:1114`）**存盘再读回来就没了**。

4. **【高】`EpoxyPatternForm.SetContent` 用了陈旧的尺寸参数。** `:1232-1234` 先用**旧的** `micronPerPixel`/`dieWidth`/`dieHeight` 调 `SetDieSize`，`:1243-1247` 才把新值从 `epeData` 赋进来。首次打开用构造函数默认值（50/350/300），之后每次打开用**上一份图案**的值。后果：Die 边框画错大小；**并且 `SaveSnapshoot`（`EpoxyPatternControl.cs:2159-2161`）用 `dieSize` 当位图尺寸** → 生成的 `Snapshoot_*.bmp` 是 7×6 像素这种废图（350/50=7），仓库缩略图实际上是坏的。

5. **【高】无背景图时选「平移/旋转背景图片」必崩。** `AffineTransformBackgroundImageHandler.SetMode()`（`:39`）无空判断地取 `EpoxyPatternControl.BackgroundImageInfo.Image.Size`；`TranslateBackgroundImageHandler.SetMode`（`:35`）和 `RotateBackgroundImageHandler.SetMode`（`:66`）都先调 `base.SetMode()`。而右键菜单在 `ActionEnum.None` 时**总是**把基本动作显示出来（`EpoxyPatternControl.cs:1848-1858`），不检查有没有背景图。正常生产流程里图案就没有背景图 → 一点就 `NullReferenceException`。

6. **【中】缩放不能小于 100%。** `SetScale` 要求 `scale >= 1`（`:1044`），而 `Zoom` 允许负增量（`:1785-1788`）。所以 `ZoomOut()`/滚轮缩小在 100% 时静默无效，用户感知为「滚轮往下不管用」。另外 `OnScaleChanged` 里有 `RebuildBackgroundBitmap()` + `UpdateAllCurves()`（`:1317-1318`），每次滚轮都全量重画整张背景位图，大图下会卡。

7. **【中】`GetFigure()` 静默丢弃不足 2 点的曲线。** `EpoxyPatternControl.cs:875-880`：`if (points.Length >= 2)` 才加入结果。保存时单点曲线无声消失。相关：`Curve.RemoveEndpoint`（`Curve.cs:348-356`）在删到只剩 1 个点时会把整条曲线清空，而 `EpoxyPatternForm.cs:708-712` 又会在 `EndpointCount == 0` 时 `RemoveAllCurves()` —— 删点操作可能一次删掉**所有**曲线。

8. **【中】`SaveEpoxyPatternDialogBox` 的「文件已存在」检查永远不触发。** `:64-69` 检查 `File.Exists(Path.Combine(_strDirPath, strName))`，但真实落盘名是 `strName + ".ep"`（`:123-124`）。**同名图案会被静默覆盖**，没有任何提示。

9. **【中】`ReadFile` 吞掉所有异常。** `PatternFile.cs:192-196` catch 一切、`Console.WriteLine`、返回 `null`；调用方只弹一句泛化的「调取失败」。图案文件损坏时无法定位原因。同类问题：`RetrieveEpoxyPatternExDialogBox.cs:51-54`、`ManageRepositoryExDialogBox.cs:49-52` 对缩略图加载失败也只 `Console.WriteLine`——**但 `imageList1` 不补位**，导致后续 `listView1.Items.Add(name, imageIndex)` 的索引与项可能错位。

10. **【中】生产代码里留着调试输出。** `PaintCurveHandler.cs:166-170` 在 `HandleMouseMoveEvent` 里打 5 行 `Console.WriteLine`（**每次鼠标移动都打**）；`DieSizeHandler.cs:74-78`、`EpoxyPatternForm.cs:936,941,983` 也有。合计 17 处 `Console.WriteLine`，且**没有任何日志框架**（不依赖 `AKRS.Galaxy2.Log`）。

11. **【中】`Curve.RemoveSegment` 是个空壳。** `Curve.cs:362-397`：只有 `iInitialPointIndex == 0` 分支真正干活，中间点分支（`:388-390`）是空的，`catch` 里只 `Debug.Assert(false, ...)`（Release 下 `Debug.Assert` 不生效）→ 出错时静默失败。

12. **【低】`ActionEnum` 有 6 个成员是死的**：`PaintPoint`、`HideSegment`、`EraseSegment`、`MoveSegment`、`SelectSegment`、`SelectPoint`（`ActionEnum.cs:11,14-17,23`），`handlerDict`（`EpoxyPatternControl.cs:335-351`）里没有对应 handler，`SetAction` 的 `ContainsKey` 判断（`:407`）会静默忽略。同样的残留还有 `EventArgs/` 里 3 个从未实例化的类。

13. **【低】`Utility.CalculateArrowPoints` 全程整数截断。** `Utility.cs:62-82`：`L=10, H=10` 是 `int`，`H / 2` 是整数除法，最后又 `(int)(... + 0.5)`。低倍率下画的箭头端点会偏 1 像素左右，纯视觉问题。另外 `:55` 的 `tan` 在垂直线段上会溢出（`dstPt.X == srcPt.X` 时除零 → `sita = π/2`，靠 `Math.Atan(∞)` 侥幸正确）。

14. **【低】`patternFile.xml` 与实际格式已经对不上。** 该文件只有 16 行，写的是 `<Unit unit="1"/>`、`<Image center="320,240" angle="0"/>`、`<Segment point="-96,45" .../>`，而 `PatternFile.SaveFile` 实际输出的是 `<MicronPerPixel>`、`<Image m11..dy>`、`<Segment x=".." y="..">`（见 5.2 节）。**它不是格式定义，是过时样例**，但 `PatternFile.cs:15-17` 的注释仍在指着它说「XML内部格式参考patternFile.xml文件」——照着它改代码必然改错。

15. **【低】`EpoxyPatternForm.CurrentCurveIndex` 与 `SetContent` 的顺序问题。** `SetContent`（`:1238`）调 `SetFigure` 会把当前曲线设为 0（`EpoxyPatternControl.cs:854-861`），但**不触发 `CurrentCurveIndexChanged` 事件**，窗体侧的表格靠 `:1249-1264` 手工刷新。若将来在 `SetFigure` 后直接依赖事件刷新，表格会不同步。

16. **【疑问，未能核实】历史 JSON 是否含 `AKRS.DispensingPattern` 的 `$type`。** 我怀疑 `libs/AKRS.DispensingPattern.dll` 被保留下来的真实原因是：早期 `EpoxyApplicationLocationType` 可能声明在 `AKRS.DispensingPattern.PointEx` 里（这正是 `EpoxyApplicationLocation.cs:7` 那句 `using static` 的来源），那么当年写出的 `$type` 就会带一代程序集名，读旧数据时必须靠这个 DLL。**但本仓库内没有任何生产 JSON 文件**（`find -name "*.json"` 只命中 `obj/` 下的 nuget 文件），`EpoxyApplicationRepository.json` 也不在仓库里，**无法验证**。请有实机数据的人确认后再决定是否删除旧 DLL。

17. **【疑问】`EpoxyPatternControl.OnActionChanging` 里对 `ActionEnum.PaintCurve` 的清理逻辑**（`:1534-1555`）：`eventArgs.OldActionEnum == PaintCurve` 且当前曲线端点 < 2 时删掉当前曲线。而 `PaintCurveHandler.HandleExitActionRequest`（`:55-67`）已经做过同样的事（`RemoveCurrentCurve`）。两条路径都会删，是否有双重删除风险取决于 `OnActionChanging` 与 `handler.HandleExitActionRequest` 的调用顺序，我没能完全确定这条链上的最终行为，留待实测。
