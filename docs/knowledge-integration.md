# 流程图谱与功能说明

主程序仍通过根目录的 `Start.ps1` 启动，地址为 `http://127.0.0.1:8765`。
左上角依次为新对话、流程图谱、功能说明；点击新对话进入空白会话，已有会话从下方列表打开。会话列表上方不再重复显示新对话按钮。
导航展开时点击右上角三横线收起为图标栏；收起后点击 Trunk 图标，展开完整导航与会话列表。
展开或收起状态保存在本机，切换页面、会话和刷新后保持；点击正文或按 Esc 不会自动收起。
桌面布局随导航宽度调整，窄屏展开时覆盖正文，仍由三横线主动收起。
左侧底部保留外观和设置，长期记忆管理移至“设置 → 长期记忆”，支持查看、编辑、删除、历史恢复及来源跳转。

- 61 张面向阅读的图谱：8 条生产主流程、53 张深入阅读图。

资料页从 `frontend/src/knowledge` 加载，样式限定在资料工作区中。
默认外观为纯白，保留旧版卡片、圆角、字体层级和间距；柔和灰绿与深色模式可在左侧外观入口或设置中切换。
外观保存在独立的本机偏好项 `trunk-appearance` 中。

## 主程序联动

点击原图中的生产节点，可以进入对应模块、方法和源码依据。
“在当前源码区查看”以及“项目中查看”读取主程序当前的源码，并再次核对文件指纹。
文件变化时打开当前文件，提示重新定位，不沿用未经确认的旧行号。

“讨论这个流程”“讨论这个方法”“结合这段源码提问”把业务说明、资料版本和源码依据加入当前对话草稿。
原有草稿保留，资料不会自动发送。每次最多加入三段已核对的源码，每段最多 60 行，总选区上限沿用现有的 8 段。
文件发生变化时保留文字依据，并说明旧位置需要重新确认。

## 源码一致性与资料版本

`POST /api/knowledge/check` 是只读核对接口，沿用主程序的源码路径边界。
资料页自动核对所有索引文件，并在窗口重新聚焦或定时刷新时更新状态。
复核依据同时保留生成索引时的有效标记、代码片段指纹和当前文件状态；不会把旧版已失效的依据升级为有效。
核对文件一致只证明版本相同，静态调用分析、业务复核范围和原有待确认项仍按资料记录显示。
资料页直接展示阅读内容，不再显示顶部核对状态栏、“核对详情”和手动核对按钮。
后台核对结果继续用于资料有效性判断；打开当前源码时会再次确认文件版本与行号。

静态资料独立保存于 `frontend/public/archify` 和 `frontend/public/engineering`。
新版运行无需启动 8775 端口的旧服务，也不访问其数据库。旧项目的代码和资料保留。

## 同步与检查

在 `frontend` 中执行：

```powershell
npm run knowledge:source-check
npm run knowledge:check
npm test
npm run build
```

`npm run knowledge:sync` 仅用于按需重新导入历史资料，正常开发和构建不需要执行。同步脚本默认从 `其他模块/archify-ui` 复制只读资料和当前索引版本。
可以通过脚本参数指定另一个旧版 UI 目录。它不会复制旧版聊天服务、数据库、依赖目录或重复的源码工程。
资料检查覆盖目录中原图、模块记录、源码文件、入口方法分片和完整模块复核记录的资源路径。

源码修改后只读核对会提示变化，业务说明和静态调用索引需要另行重新生成与复核。
