# 固晶系统调度与任务（`AKRS.ZX2200/BondSystem/{Controllers,Modules,Services,Tasks}`）

> 固晶（System2）的运行时执行链：谁在遍历动作节点、用什么信号启停、几个线程、异常怎么收场。
> 代码规模：28 个文件 / 15,632 行（其中 1 个文件已从工程移除，见第 8 节）

## 1. 模块定位

本模块是固晶域（System2）**运行时的执行主体**，处在"动作节点定义"与"硬件驱动"之间的中间层：

```
ProcessDomain / System2Process        （工艺步骤、排序模式的来源）
        ↓
S2ActionNodeController                （排序器 + 游标，Main/Machine/Process/）
        ↓  产出 ActionNode
BondSystem/Tasks/BondTask.cs          （唯一的固晶工作线程，本模块）
        ↓  actionNode.DoWork()
BondSystem/Controllers/*Controller    （本模块：把动作翻译成硬件调用序列）
        ↓
BondSystem/Modules/*Module            （本模块：硬件名 → HardwareRepositoryService）
        ↓
AKRS.Galaxy2.LogicHardware / ETEL / GTN / LTDMC   （平台 DLL）
```

- **上游**：`ProcessDomain.S2SystemProcess`（步骤与排序模式）、`ProductConfiguration`（基板/基岛/焊点配置）、`System2Domain`（控制器与任务的容器单例）。
- **下游**：`HardwareRepositoryService.GetHardware<T>("名字")`（唯一硬件入口）、`BondSystem/Models/ActionNodes/`（各 `ActionNode` 实现，由 `05-动作节点框架.md` 覆盖）。
- **横向**：`SignalPool`（跨域握手信号）、`StatisticsDomain`（产能/不良统计）、`MachineStateModel`（全局状态机）。

排序器 `S2ActionNodeController` **不在本模块目录内**（位于 `AKRS.ZX2200/Main/Machine/Process/S2ActionNodeController.cs`），但它是本模块所有任务类的直接依赖，本文按"外部核心依赖"一并说明。

## 4. 核心流程

### 4.0 触发链总览：本项目用的是 `Task`，不是 `Thread`，也不是 `Timer`

实测结论（与 `ZX2200DAF-2` 无关，以下均为本项目行号）：

```

  → PrepareMachineReadyToStart()                     同文件 :266
```

- **线程模型**：`System.Threading.Tasks.Task` + `TaskCreationOptions.LongRunning`（即 CLR 会为其开专用线程，不占线程池）。**不是** `new Thread`，**不是** `Timer`。
- `BondTask`（`Tasks/BondTask.cs:365`）与 `SlideFluxerTask`（`Tasks/SlideFluxerTask.cs:238`）用同一套 `Start()` 模板，仅线程名与 `DoWork` 不同。
- `CancellationToken.None` 被硬编码传入（`BondTask.cs:371`、`SlideFluxerTask.cs:244`），因此**取消令牌完全未使用**。
- 同类模式在全工程一致：`DispenseSystem/Tasks/DispenseWorkTask.cs:69`、`TransportSystem/Tasks/TransportTask.cs:135/221/324/440/480` 都是 `while (Signal.WaitStart())`。这是本项目的统一任务循环范式。

### 4.4 暂停 / 停止 / 急停：用什么信号

**实锤结论：本项目的停止信号既不是 `IStatus.IsStop()` 驱动循环，也不是 `CancellationToken`，而是全局枚举 `MachineStateModel.MachineState` + `Signal.WaitStart()` 轮询。**

```
暂停：Machine.Pause()                     Machine.Operate.cs:314
        → SetState(MachineStateEnum.Pause) :317
        → Signal.WaitStart() 进入 while 循环，每 20ms 轮询一次       Signal.cs:217-225

继续：Machine.Continue()                  Machine.Operate.cs:323
        → SetState(MachineStateEnum.Working) :327 / :339（安全门分支）

停止：Machine.Stop()                      Machine.Operate.cs:347
        → SetState(MachineStateEnum.Stop)  :350
        → AKRSMessageBoxExt.ClearMessageBox() :353   ← 强制关闭所有报警弹窗
        → SetAlarmState / 三色灯            :356
        → IsSingleStepWork = false         :359
        → SignalPool.IsBondNeedChipSignal.ReSet() :362
        → 关顶针真空                        :371
        → 焊后计数清零                      :374-377
        （注意：Stop() 不 Join 任何 Task，也不置任何取消标志）

急停：Machine.EmergencyStop()             Machine.Operate.cs:383
        → Parallel.ForEach(所有 Axis, axis.StopMove(false,true))  :388-393
        → Machine.Stop()                   :396
        → BondTask.AbortThread()           :400   ← 空实现！
```

`Signal.WaitStart()` 的全部实现（`AKRS.Galaxy2.Machine/Models/Signal.cs:202-228`）：

```csharp
public static bool WaitStart()
{
    if (MachineStateModel.GetInstance().MachineState == MachineStateEnum.Stop)  // :211
        return false;                                                          // :213
    while (MachineStateModel.GetInstance().MachineState == MachineStateEnum.Pause)  // :217
    {
        if (MachineStateModel.GetInstance().MachineState == MachineStateEnum.Stop)  // :219
            return false;                                                      // :221
        Thread.Sleep(20);                                                      // :224
    }
    return true;                                                               // :227
}
```

- 返回 `false` ⇒ 循环退出，`DoWork()` **直接 `return`**（`BondTask.cs:112` 起的每一处调用点都靠 `while` 条件自然结束），线程进入 `RanToCompletion`。
- `Machine.IsStop()`（`Machine.StateRelated.cs:34-37`）只是读同一个枚举，**它不是循环条件**。
- `Machine.IsPause()` 只在 `SlideFluxerTask.cs:113` 的防撞超时循环里用来重置计时器。
- `Stop()` 之后线程不会立即死：`DoWork()` 可能正卡在 `SignalPool.*.Wait()` / `AKRSMessageBoxExt.Show()` 里。`Signal.Wait()`（`Signal.cs:116-145`）内部先调 `WaitStart()`、再每 5ms 检查 `MachineState == Stop`，所以阻塞中的信号等待也能被停止打断。
- **弹窗解阻塞**：worker 线程弹出的报警框被登记进 `AKRSMessageBoxExt.msgBoxDict`（`AKRSMessageBoxExt.cs:32`），`Stop()` → `ClearMessageBox()`（`:42-55`）用 `BeginInvoke` 把它 `Hide()` + `DialogResult = DialogResult.Abort`，从而让阻塞在 `Show()` 的 worker 线程带着 `Abort` 返回。这是本工程"停止能穿透报警弹窗"的关键机制。

### 4.5 动作结果的五种收场（`BondTask.cs:234-315`）

| `ExcuteResult` | 处理 | 行号 | 是否继续 |
|---|---|---|---|
| `Abort` | `Machine.Stop()` → `MoveBondZToSafePos()` →（配刮胶盘时）`SlideFluxerHomeWaitArrive()` → `return` | `:236-251` | 线程结束 |

## 5. 关键实现细节

### 5.1 停止/暂停状态是无锁全局可变量

`MachineStateModel.MachineState` 是普通自动属性（`MachineStateModel.cs:87`），`SetState`（`Machine.StateRelated.cs:52-68`）直接赋值，**没有 `lock`、没有 `volatile`**；每个工作线程在 `Signal.WaitStart()` 里每 20ms 读一次它。设计上够用（枚举写入原子），但多点写入（UI 停止、`ActionNode` 内部 `Machine.Stop()`、`EmergencyStop`）之间没有顺序保证。

### 5.2 状态变更会落库

每次 `SetState` 且状态确有变化时，会构造 `ParameterChangeLogEntity`（记录旧值→新值 + 当前登录用户）并投入 `StatisticsService.DbEntityBlockingCollection`（`Machine.StateRelated.cs:58-65`），由"数据库存储线程"异步写库（`SupportFeature/Statistics/StatisticsService.cs:101-103`、`:110-140`）。

### 5.3 `ExcuteResult` 与 `RunStateEnum` 的边界

- `ExcuteResult` 定义在平台程序集 `AKRS.Galaxy2.Infrastructure.Enums`（源码不在本仓库）。本模块用到的取值：`Success`、`Abort`、`Retry`、`Exception`、`Alarm`、`Fail`。
- `ActionNode.State`（`RunStateEnum`）在基类 `DoWork()` 的 `finally` 里被强制置为 `Stop`（`ActionNode.cs:115`），因此**外部看不到 `Running` 态**，该字段不构成可用的运行指示。

### 5.4 三家运控的分支判据（本项目实测）

- `is GTController`（**按轴卡**）：全工程 3 处 —— `Controllers/System2Controller.cs:1197`（`GetBondheadForceValue`）、`:1220`（`GetCalibrateTableForceValue`）、`Program.cs:197`。真值 ⇒ 走 `GTN.mc.GTN_GetAuAdc` 读固高模拟量；假值 ⇒ 走 `ModbusService.ReadBondForce()/ReadManometer()`（即 ETEL 配置下压力表走 Modbus）。
- `is ETELAxis`（**按单轴**）：`BondSystem/` 内 12 处，本范围 6 处 —— `Controllers/BondHeadController.ForceRelated.cs:67`（读力值）、`:134`（`ForceControlSet`）、`:868`、`:1079`，`Controllers/S2DispenseController.cs:516`（画胶插补）。
- 结论：**判据不统一**。轴卡级能力（ADC/力表）看 `is GTController`，力控/插补看 `is ETELAxis`。

1. **`BondTask.AbortThread()` 是空方法**（`Tasks/BondTask.cs:382-384`），注释只有 `/// AbortThread`。`Machine.EmergencyStop()`（`Machine.Operate.cs:400`）调用它但什么也不会发生。急停的实际效果只有：轴 `StopMove` + 状态置 `Stop` + 弹窗清除。**若某动作正阻塞在不检查 `MachineState` 的硬件等待里（如 `Axis` 的到位等待、`Sensor.WaitSignal`），急停不会把它拉回来。**

3. **停止不 Join**：`Stop()` 不等待任何 Task 结束。重启动画由 `Machine.cs:198` 的 `IsAllowTaskClosed()`（`:250-256` 遍历 `WorkTasks` 查 `Status == Running`）兜住，但 `WorkTasks` 列表是每次调用时**重建**的（`:200`），且 `DispenseWorkTask.DispenseTask` / `BondTask.BondWorkTask` 等字段若为 `null` 会被 `task?.Status` 跳过——即**线程从未启动过时也视为"已关闭"**，这是正确的；但反过来意味着**无法区分"从未启动"和"已崩溃退出"**。
4. **`IsStop()` 在 `BondTask` 里与循环无关**（`BondTask.cs:450`、`:463`，只在 `SendAway()` 里决定要不要给流道发传送信号）。若有人以为改这两个判断能停止固晶，是错的——真正的闸门是 `Signal.WaitStart()`。

### 8.3 `ExcuteResult.Fail` 未被 `BondTask` 处理（缺陷）

`BondTask.cs:234-315` 的 `switch` 只列举 `Abort`/`Retry`/`Exception`/`Alarm`，**没有 `Fail` 分支，也没有 `default`**。`S2DispenseController.InterpolationApplication()` 在 `catch` 后 `return ExcuteResult.Fail`（`S2DispenseController.cs:618`）。结果是：点胶/画胶过程抛异常 → 弹一个 `AKRSXtraMessageBox`（`:617`）→ 返回 `Fail` → `BondTask` 当作成功 → `FinishCurrentActionNode()`（`:319`）→ 该焊点被标记完成并继续下一颗。**建议加 `case ExcuteResult.Fail:` 或 `default:`。**

### 8.4 产能/统计表的真实写入情况（跨模块核查）

- **`CapacityLog`：全工程没有任何 `new CapacityLogEntity(...)` 调用。** 只有建表（`Infrastructure/Service/DBService.cs:60`）、清表（`:164`、`:302-315`）、查询（`SupportFeature/Statistics/StatisticsDomain.cs:313-315`）、UI 读取（`SupportFeature/Statistics/UcCapacityStatistics.cs:136`、`:309`）。**产能统计界面读的是一张永远为空的表。**
- **`ProductTimeStatisticsEntity`：唯一写入点是 `SupportFeature/Statistics/UcProductStatistics.cs:133-155` 的 `simpleButton1_Click`，而该事件处理器没有任何对应的控件声明**（整个 `SupportFeature/Statistics/` 目录下 `simpleButton1` 只出现这一次，`UcProductStatistics.Designer.cs` 中没有该控件）——即：该处理器不可达，且其内部逻辑是 `for (int i = 0; i < 100; i++)` 插入 **100 条随机造的数据**（`:135-152`）。生产时间统计图表的写入路径实际上不存在。
