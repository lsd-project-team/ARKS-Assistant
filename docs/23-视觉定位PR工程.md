# 视觉定位 PR 工程（`AKRS.Galaxy2.PR`）

> 本工程是整机的**视觉定位模板库**：既提供 PR（Pattern Recognition）模板的数据模型与执行引擎，也提供模板编辑/硬件绑定/结果展示的 WinForms 界面。**匹配算法本体不在本工程内**，而是由海康 VisionMaster 的 `.prc` 流程文件承载，本工程只负责调度流程、灌图、取结果、画图。
> 代码规模：87 个 `*.cs` / 23,483 行（不含 `obj/`；其中非 Designer 67 个文件 / 17,047 行）。附属测试工程 `AKRS.Galaxy2.PR.Test` 6 个 `*.cs` / 297 行。

---

## 1. 模块定位

### 职责边界

本工程做四件事：

1. **PR 模板的数据模型与持久化**：`PREntity`（一个 PR 模板 = 一个相机 + 三轴 + 6 路光源 + 曝光/增益/Gamma + 一个算法流程），整体序列化成 JSON 落到设备级目录。
2. **算法流程调度**：`BaseAlg` 及其 30 个子类，每个子类对应一个 VisionMaster `.prc` 流程；`FindModel()` 就做「把 Bitmap 灌进 VM 图像源 → `VmProcedure.Run()` → 从流程结果里按变量名读浮点数组 → 用 HALCON 画标注 → 转成 `Bitmap` 塞进 `MatchResult`」。
3. **模板编辑 UI**：`FrmPRList`（列表）→ `FrmPREditor`（编辑）→ `UcAlgEditor`（算法页签、ROI 绘制、参数下发）；`FrmHardwareSet`（相机/轴/光源绑定）。
4. **结果推送到主影像区**：`PRResultShowModel` + `BroadcastBlock<PRResultShowModel>` 数据流管道。

### 不在本工程内（重要）

- **像素→机器坐标的换算不在本工程**。本工程只输出**图像像素坐标**（`MatchResult.CenterX/CenterY/Angle`）。换算所需的「X/Y 方向像素比 mm/pixel」定义在 `AKRS.ZX2200/CalibSystem/Models/CalibrateResult.cs:20/:25`，属主程序标定模块（详见 `docs/13-整机标定.md`）。本工程内 grep `PixelSize|像素当量|mm/pixel|CalibParam|RatioX|RatioY` **零命中**。
- **匹配算法本体不在本工程**。见第 5.2 节。
- `PatternRepository/`、`UiMapFile/` 这两个目录**在本仓库中不存在**（全仓库 grep 零命中，`PatternRepository` 仅作为字符串出现在 `AKRS.Galaxy2.Dispense/DialogBoxes/ManageRepositoryDialogBox.cs:16` 等无关位置）。

## 5. 关键实现细节

### 5.1 匹配算法用的是哪一路视觉库？—— **海康 VisionMaster，HALCON 只做画图**

**判别依据（全部取自本项目 `AKRS.Galaxy2.PR.csproj` 与源码）：**

| 证据 | 位置 |
|---|---|
| csproj 引用了 **24 个 `VM.*` / `IMVS*ModuCs` / `VMControls.*`** 海康程序集 | `AKRS.Galaxy2.PR.csproj:52-226`（`VM.Core`、`VM.PlatformSDKCS`、`IMVSFPFeatureMatchModuCs`、`IMVSContourMatchModuCs`、`IMVSGrayMatchModuVACs`、`IMVSBlobFindModuCs`、`IMVSCaliperCornerModuCs` …） |
| csproj 引用 `halcondotnet` 17.12 | `AKRS.Galaxy2.PR.csproj:55-58` |
| **csproj 没有引用 `OpenCvSharp`** | 全 csproj grep 零命中 |
| **csproj 没有引用 `ImageAlignmentDll`** | 全 csproj grep 零命中 |
| 源码里 33 个文件 `using HalconDotNet`，37 个 `using VM.PlatformSDKCS`，33 个 `using VM.Core` | 全工程 `using` 统计 |
| **HALCON 算子只有 26 个，全是画图/显示类**：`PaintRegion`(165 次)、`ConcatObj`(151)、`GenRectangle2`(82)、`GenRegionLine`(73)、`Compose3`(64)、`ZoomRegion`(59)、`VectorAngleToRigid`(19)、`AffineTransRegion`(19)、`GenRegionPoints`(18)、`GenEmptyObj`(293)…**没有 `FindShapeModel`/`FindNccModel`/`BestMatch`/`MeasurePos` 等任何匹配/测量算子** | 全工程 `HOperatorSet.*` 统计 |
| 真正的匹配调用是 `VmProcedure.Run()` + `ModuResult` | `XldModelAlg.cs:87-113`、`HighPreModelAlg.cs:52-60`、`FcUplookModelAlg.cs:75-88` |
| `VM.PlatformSDKCS.VmSolution.Instance["流程全名.模块名"]` 是全局流程注册表 | `BaseAlg.cs:196`、`:300`、`:309`、`:310` |

**结论**：**匹配/测量 100% 由海康 VisionMaster 完成**，流程存放在 `.prc` 文件里。HALCON 承担三个职责：(a) 把 VM 输出的 ROI/匹配框/轮廓点画到图上；(b) 把图缩到 1/4（`ZoomImageFactor(..., 0.25, 0.25, ...)`，`BaseAlg.cs:277`）以便快速上屏；(c) `HObject` ↔ `Bitmap` 转换（`ImageHelp.HObjectToBitmap`，`Models/Services/ImageHelp.cs:258`）。

> 附带发现：`AKRS.Galaxy2.PR.csproj` 引用了 `predictPD` / `predictPDNative` / `MWArray`（`:79-88`），但**源码中零使用**（全工程 grep `predictPD|MWArray` 零命中）。

### 5.2 算法流程的「字符串契约」（最容易踩的坑）

C# 与 `.prc` 之间的接口全是**硬编码字符串**，没有任何编译期检查：

### 5.3 图像通道与 1/4 缩放

- 相机取图统一 `SnapShot(false, SnapImageFormat.Format8bppIndexed)`（`PREntity.cs:444/:465`、`FrmPREditor.cs:140`、`FrmPRImage.cs:77`）—— 8bit 灰度。
- `ImageHelp.BitmapToImageBaseData`（`Models/Services/ImageHelp.cs:97`）用 `LockBits` 直接把 `Scan0` 交给 VM 的 `ImageBaseData`（`:105` / `:110`），**只支持 8bpp 与 24bpp**。
- 传给 HALCON 的显示图是 **1/4 缩放的灰度图**（`BaseAlg.cs:277`），所以所有绘制坐标都手工 `/ 4`（`XldModelAlg.cs:172-173/:200-201`、`HighPreModelAlg.cs:110-111/:137-138`、`FcUplookModelAlg.cs:133-134/:290-291`），而回填到 `MatchResult` 的 `CenterX/CenterY` 是 **VM 的原始全分辨率像素值**（`XldModelAlg.cs:237-238`）。**「显示坐标」与「结果坐标」差 4 倍，是本工程最容易误读的地方。**

### 5.5 模板 ID / 命名

- **模板 ID 就是模板名字符串**。`VisionEntityRepository.PRVisionList` 是 `List<BaseVisionEntity>`，查重靠 `item.GetName()`（`VisionEntityRepository.cs:78`、`:138`）。
- 自动生成名：`新PR模板{DateTime.Now:ssffff}`（`FrmPRList.cs:156`）—— 用「秒+4 位毫秒」而非完整时间戳，**同一秒内相隔整百毫秒会撞名**。
- 改名：`PREntity.ChangeFilePath(oldName, newName)`（`PREntity.cs:644`）只 `DeleteFile` 旧 `.prc`，**并不重命名/复制文件**；真正的重命名靠后续 `SaveProcedure` 用新名字另存。
- 克隆：`PREntity.Clone(newName)`（`PREntity.cs:659`）走「写临时 `Guid.NewGuid()+".json"` → 读回 → 删临时文件」实现深拷贝；失败返回 `null`（`:673`）。

### 5.7 曝光/增益/Gamma 约定

`BaseVisionEntity` 默认值：`Exposure=500`（`:90`）、`Gain=1`（`:95`）、`Gamma=40`（`:100`）。

### R1 —— 静态委托未注入时，PR 结果会静默变成「未执行」（**高**）

`PREntity.IsSaveLocateImage`（`PREntity.cs:52`）与 `SaveLocateImageAction`（`:57`）在本工程内**只有读取没有赋值**，赋值方只有主程序 `AKRS.ZX2200/Program.cs:250-251`。而 `Excute` 里：

```
PREntity.cs:535   if (IsSaveLocateImage() && postImage)     ← Func<bool> 为 null → NullReferenceException
PREntity.cs:580   result = ExcuteResult.Success              ← 在异常点**之后**，永远不会执行到
PREntity.cs:633   catch (Exception ex) { LogHelper.Post("...采图失败,{ex.Message}") }   ← 吞掉，result 停留在 ExcuteResult.None
```

即：**当 `IsSaveImage=true` 且宿主没注入这两个委托时（例如 `AKRS.Galaxy2.PR.Test`），`DoWork` 会返回 `ExcuteResult.None` 而不是 `Success`**，上层通常把 `None` 当失败处理。同时 `IsSaveImage` 分支还调用 `SaveLocateImageAction(...)` 而**没有任何 null 检查**（`:532/:546/:595`）。

### R2 —— `Bitmap` 所有权混乱，多处「传进去就被 Dispose」（**高**）

| 位置 | 行为 |
|---|---|
| `BaseAlg.SetImage` | 末尾无条件 `bitmap.Dispose()`（`BaseAlg.cs:278`）——**把调用者的图释放掉了** |
| `PREntity.DoWork(Bitmap)` | `this.Alg.SetImage(bmp)`（`:209`）之后又 `bmp.Dispose()`（`:290`），双重 Dispose |
| `PREntity.Excute` | `Alg.SetImage(bmpClone)`（`:509`）在 `using(bmp)` 块内，`bmpClone` 由调用方 `DoWork` 负责释放（`:396-399`） |
| `FrmPREditor.RealTimeRefreshImg` | 每轮把同一个 `bitmapClone` 传给 `UcAlgEditor.RefreshImg`（`:152`），该处 `SetImage` 会把它 Dispose；虽然下一轮会重新赋值，但显示控件若仍持有旧引用就会渲染已释放图 |

**约定：把 `Bitmap` 传进 `SetImage` 就等于放弃所有权。** 新增调用点时必须自己 Clone。

### R3 —— `.prc` 流程与 C# 之间全是硬编码字符串（**高**）

模块名（`快速匹配1/2/3`、`轮廓匹配1/2/3`、`高精度匹配1/2/3`、`灰度匹配1/2/3`、`位置修正1/2`、`BLOB分析1/2`、`图像源1`、`输出图像1` …）与变量名（`ReasultX/Y/A/S` ——**"Result" 被拼错成 "Reasult"**、`IsFirPR`、`FirPRType`、`Threshold`、`Area`、`1BlobArea` …）全部散落在 C# 里，共约 40 个模块名 + 30 个变量名。

**在 VisionMaster 里改任何一个模块名/变量名，C# 侧不会编译报错，只会静默失败**（`GetOutputFloat` 返回空数组 → 走 `IsSuccess=false` 分支）。反之，新增算法类型必须在 `AlgsFactory.cs:23` 的 `switch` 里加分支，否则落到 `default` 变成 `FastModelAlg`（`:116-117`）。

### R11 —— 线程安全隐患（**中**）

- `FrmPREditor.isGrab`（`Controls/FrmPREditor.cs:87`）是普通 `bool`，在 UI 线程写（`:477`）、在工作线程读（`:130`），**没有 `volatile`、没有内存屏障**。取消勾选后采图循环**不一定立即退出**。
- `RealTimeRefreshImg` 是 `while(isGrab) { ...; Thread.Sleep(300); }`（`:130-157`）——**轮询式**采图，非事件驱动。`FrmPRImage.RealTimeRefreshImg` 同样是 `while(!isFinish) { ...; Thread.Sleep(200); }`（`Controls/FrmPRImage.cs:75-91`），且 `isFinish` 全工程 grep **只在 `:41` 声明、`:75` 读取，没有任何地方赋值** → **该循环永不退出，线程泄漏 + 相机被持续占用**。
- `PREntity.lockObj` 是**静态**字段（`:42`），意味着不同 PR 模板之间也互相阻塞（见 5.8）。而 `Excute` 内层又用 `lock(this)`（`:505`）——**两个不同的锁对象、锁序不一致**，是潜在死锁面。
- `UcVmResultShow.ShowResult` 对 `listImages` 的「加-裁剪」不是原子操作（`:103-113`），若多线程投递会 `IndexOutOfRange`。

**`AKRS.Galaxy2.PR.Test` 的用法与能力**（源码极简，`:20` 的注释就是它的规格说明）：

```
// 1. 创建PR  （2种创建方式，名称不能重复） 删除
// 2. 保存 读取
// 3. PR 功能
```

- **能测**：模板的新建/重命名/删除/克隆、`.prc` 与 `TemplateConfigRepository.json` 的读写往返、`FrmPREditor` 的全部编辑器交互（光源/曝光/Gamma 调节、ROI 绘制、30 种算法切换与实时预览）、`ImageHelp` 的三种图像转换、`FindModel` 的真实耗时（`UcAlgEditor.cs:137` 的 `Console.WriteLine("Findmodel耗时:")`）。
- **怎么用**：直接跑起来后点 `Form1` 上唯一的 `simpleButton2`，它会 `EditPr("test2")`（`Form1.cs:48`）—— 名为 `test2` 的模板不存在就建一个（默认 `XldModelAlg`），然后弹出 `FrmPREditor`。**要试别的模板名必须改代码重新编译**（`:48` 是硬编码字符串）。
- **不能测**：所有跨线程/生产调用相关的路径。因为 `PREntity.IsSaveLocateImage`/`SaveLocateImageAction` 依赖主程序注入（见 R1），在 Test 宿主里 `DoWork` 会因 `IsSaveLocateImage()` 为 null 而走进 catch。另外它 `OutputPath=bin\Debug`（自己的目录），`AlgFlowTemplates` 不会随之复制 —— 它在 `EditPr` 里 `SetAlgFlowType(XldModelAlg)`（`Form1.cs:67`）之后第一次 `FindModel` 就要读 `AlgFlowTemplates\轮廓匹配.prc`，**在 Test 目录下大概率加载失败**（`BaseAlg.cs:304` → catch 吞掉 → `VmProcedure` 为 null）。使用前需把 `..\AKRS.Galaxy2.PR\AlgFlowTemplates\` 手工拷到 Test 的 `bin\Debug\` 下。
- 另外 Test 工程 `Form1.cs:28-41` 自带一套 `SettingsPath` / `RecipeDirPath` 定义，与主程序 `PathConfig`（`AKRS.Galaxy2.MachineSupport/Config/PathConfig.cs`）**是两套并存的路径实现**，实际生效的是 `PathConfig` 里那套。
