## 数据边界

- workspace_id：源码和项目记忆的范围。
- thread_id：一条会话及其 Agent 检查点。
- run_id：一次执行；中断恢复保留原消息，不重复提交用户问题。
- 选区：文件路径、起止行号、内容快照、SHA-256 文件版本。
- 业务数据库保存原始消息与运行事件；检查点数据库保存 Agent 工作状态；记忆目录保存长期笔记。
- 同一会话最多一个活动运行。写数据库使用短事务；SSE 从持久化事件序号重放，浏览器断线不取消任务。

## 界面设计

按用户最新截图重排：左侧会话导航，问答在左，源码工作区在右，文件树位于源码区最右侧。编辑器文件标签与会话标题处于同一高度，以真实文件路径和选区为核心。

按用户要求停止使用 `frontend-design` 技能。布局参考 Codex，配色和面板质感参考用户提供的简历编辑器：暖白底色、柔和灰色边线、独立圆角面板与轻阴影；源码在浅灰画布上以白色阅读面板呈现。用户消息采用浅暖灰气泡，黑色用于关键按钮。共享 CSS 变量统一对话、文件树、设置与记忆弹窗的颜色。中文系统字体与 Segoe UI；代码使用 Consolas 等宽字体和低饱和语法主题。选区卡显示文件与行号，回复引用支持跳转。

问答宽度可向右拖动扩大，也可通过分隔线的方向键调整；文件树独立收起。中等窗口优先保留左右双栏，会话导航以浮层展开；800 像素以下才切换问答与源码视图。启动页直接展示实际源码和对话，不加入营销内容。

## 体验优化验收（2026-10-10）

- 源码阅读：问答与文件树独立调整宽度，保存布局、文件阅读行号。引用跳转居中，恢复阅读位置从原行开始；虚拟列表渲染后记录行号，避免旧节点覆盖新位置。
- 会话草稿：文本和代码选区按会话隔离并持久化。异步提交仅清理提交的快照；新会话首次运行失败时保留草稿，成功后迁移，期间追加内容仍保留。
- 流式滚动：靠近底部才跟随新内容；真实长回复生成时，向上阅读后的滚动位置保持不变，点击“回到最新”可继续跟随。
- 文件查找：Ctrl+P 按文件名与路径查找，键盘选择打开；文件树搜索使用 200 ms 防抖，显示匹配文字并保留完整路径提示。
- 回复操作：复制、重新生成、旧版展开、停止与恢复；工具名称和执行状态以中文呈现。真实模型重新生成和重新生成失败后的恢复已完成，保留原问题及旧回复；失败过程有明确提示。
- 上下文透明度：每次运行保存实际注入的记忆内容、版本与截断范围。旧运行明确提示未记录快照。长期记忆显示更新时间，可跳转到来源对话。摘要读取通过图还原增量状态，避免直接读检查点遗漏消息和摘要。
- 摘要纠错：页面显示原生压缩摘要，保存纠正后重新加载可见，改动写入真实检查点并用于后续回复。原始消息保留；运行互斥与版本检查防止覆盖。页面验收使用单独标记的“摘要纠错验收（框架测试）”会话，由确定性模型产生原生压缩状态；真实供应商压缩验收仍见前文。
- 连接修复：关闭模型时不会关闭 LangChain 共享的连接池；Anthropic 和 OpenAI 模型使用各自拥有的连接。新增连续请求与重叠请求的 SDK 回归，真实接口再次调用成功。
