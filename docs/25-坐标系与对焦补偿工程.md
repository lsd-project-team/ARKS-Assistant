# 坐标系、自动对焦与轴补偿（`AKRS.Galaxy2.CoordinateSystems` / `AKRS.Galaxy2.AutoFocusing` / `AKRS.Galaxy2.AxisCompensate`）

> 三个被主程序 `ProjectReference` 引入的外围基础设施工程：机器坐标系树与图像→机器坐标变换、Z 轴自动对焦搜索、轴位置补偿（多项式拟合）。
> 代码规模：19 个文件 / 2,435 行（不含 `*.Designer.cs`，已用 `wc -l` 核对）

## 1. 模块定位

三个工程互相独立，只共享上游（都被 `AKRS.ZX2200.csproj` 以 `ProjectReference` 引入）：

| 工程 | 输出 | 定位 | 状态 |
|---|---|---|---|
| `AKRS.Galaxy2.CoordinateSystems` | Library | 机器坐标系树（`G0` 为根）+ 图像↔机器坐标变换 + 标定文件读写 | **核心，全机在用** |
| `AKRS.Galaxy2.AutoFocusing` | Library | Z 轴自动对焦（爬坡搜索 + 清晰度评价） | 只有 `AutoFocus` 一个方法在用，其余 3 个实现全死 |
| `AKRS.Galaxy2.AxisCompensate` | **Exe**（`OutputType=Exe`，`Program.Main` 为空） | 轴位置多项式补偿 | **休眠**：补偿表为空、开关无人读、标定入口无调用点 |

三者在整机中的位置：**坐标系工程是上游最底层的基础设施**——`WaferSubSystem`/`BondSystem`/`DispenseSystem`/`CalibSystem` 的所有"轴位置↔机器位置↔像素位置"换算都要经过它；对焦与轴补偿是标定/测试性质的旁路功能。

## 4. 核心流程

### 4.1 图像坐标 → 机器坐标（变换链）

`Vm` 类型（相机）坐标系的完整链路——每一步的矩阵来源都在本节标出：

```
调用方（主程序，如 WaferTableController.cs:143）
  → MachineCoordinateSystem.GetInstance().WaferCoordinateSystem   MachineCoordinateSystem.cs:161（按名 "WaferTableCoordinateSystem" 查找）
  → GeneralCoordinateSystem.SelfPosToG0(point)                    GeneralCoordinateSystem.cs:44
      · while(true) 沿 UpperCoordinateSystem 向上收集整条链        GeneralCoordinateSystem.cs:50-61
      · 自下而上逐个 ForwardConvertCoordinate                      GeneralCoordinateSystem.cs:63-66

若链上某一环是 DependentCoordinateSystem（相机系）：
  → DependentCoordinateSystem.SelfPosToG0(ownPoint3D, upperPoint3D)   DependentCoordinateSystem.cs:43
      · point = ForwardConvertCoordinate(own)                      DependentCoordinateSystem.cs:47
      · pointReal = point + upperPoint3D     ← 叠加轴的实际位置        DependentCoordinateSystem.cs:48

  X' = Distance.X + (x·cosθ − y·sinθ)
  Y' = Distance.Y + (x·sinθ + y·cosθ)
  Z' = Z + Distance.Z

Vm 分支（走海康标定）：                                            BaseCoordinateSystem.cs:96-107
  → TransformTool.GetCCalibTransTool(this.Name)                   TransformTool.cs:168
      · 路径 = StaticPara.CoordinateSystemPath + name + ".iwcal"    TransformTool.cs:174
      · CCalibTransTool.ImportCalibFile(path)                      TransformTool.cs:176
  → TransformTool.GetPoint3D(tool, value, this.CalibModule)        TransformTool.cs:241

      · result = CalculateMvdPointF(tool, value)
      · 返回 (center − result)                                     TransformTool.cs:256/261/265
  → point.Z = value.Z + this.Distance.Z                            BaseCoordinateSystem.cs:106
```

要点：

- **矩阵不是显式矩阵，而是海康算子 `CCalibTransTool`**。单应矩阵持久化在 `.iwcal`/`.xml` 里（实测 `.xml` 的 `CalibMatrix` 为 9 个 float，见 5.3），代码里从不显式读取矩阵，只把点喂给算子并取结果。
- `Distance.X/Y` 对 `Vm` 类型**不参与运算**：`ForwardConvertCoordinate` 的 `Vm` 分支完全由算子结果覆盖 `point`，只用到 `Distance.Z`（`BaseCoordinateSystem.cs:106`）。JSON 里相机系的 `Distance.X ≈ −1224`、`Distance.Y ≈ −1024` 是历史遗留值。
- 三个 `CalibModuleEnum` 分支（`AxisAndCameraIsTogether`/`CameraStaticUp`/`CameraStaticDown`）在 `TransformTool.cs:254-266` 中**代码完全相同**，只在 `RealisticCoordinateSystem`（`:243`）时跳过中心相减。
- 逆变换（机器→图像）对 `Vm` 类型**直接抛异常**：`BaseCoordinateSystem.cs:159` `throw new InvalidOperationException("不支持海康标定的逆运算")`。因此 `G0PosToSelf` 对相机系不可用。
- 反变换链：`GeneralCoordinateSystem.G0PosToSelf` 从链顶向下逐个 `BackConvertCoordinate`（`GeneralCoordinateSystem.cs:95-98`），纯解析式（`BaseCoordinateSystem.cs:144-156`）。

## 5. 关键实现细节

### 5.1 坐标系树的持久化格式（含 `$type` 风险）

- 路径：`Application.StartupPath/Settings/DeviceParams/MachineCoordinateSystem/MachineCoordinateSystem.json`（`StaticPara.cs:21-30` + `AKRS.Galaxy2.MachineSupport/Config/PathConfig.cs:94`）。实测本机文件：`bin/Debug/Settings/DeviceParams/MachineCoordinateSystem/MachineCoordinateSystem.json`，1,662 行 / 64,768 字节。
- 序列化器：`AKRS.Galaxy2.Infrastructure`（DLL，无源码）里的 `JsonFormatHelper<T>.ReadGenericObject` / `SaveGenericObject`（`MachineCoordinateSystem.cs:51` / `:88`）。
- **`$type` 元数据确实带程序集全名**，文件第 2 行：

```json
"$type": "AKRS.Galaxy2.CoordinateSystems.CoordinateSystems.MachineCoordinateSystem, AKRS.Galaxy2.CoordinateSystems"
```

  每个多态成员都带：`CoordinateSystems` → `System.Collections.Generic.List\`1[[...BaseCoordinateSystem, AKRS.Galaxy2.CoordinateSystems]], mscorlib`（第 4 行），每个具体坐标系是 `...GeneralCoordinateSystem, AKRS.Galaxy2.CoordinateSystems` / `...DependentCoordinateSystem, ...`（第 7 / 121 行），每个点还带 `AKRS.Galaxy2.Infrastructure.CommonModel.AKRSPoint3D, AKRS.Galaxy2.Infrastructure`（第 29 行）。**改 `AKRS.Galaxy2.CoordinateSystems` 的程序集名、根命名空间或 `CoordinateSystems` 子命名空间，都会让历史 JSON 反序列化失败**。
- `[JsonIgnore]` 的成员不落盘：`TransformTool`（`:54`）、`CCalibTransTool`（`:60`）、`UpperCoordinateSystem`（`:76`）。这解释了为何 JSON 里没有 `UpperCoordinateSystem`，而 `Init()`（`MachineCoordinateSystem.cs:72-81`）要在每次 `Load` 之后按 `UpperName` 重新把树接起来。
- JSON 中实际存在的坐标系（实测文件）：`G0`(General)、`TransportUniCoordinateSystem`、`TransportUnitCoordinateSystem`、`WaferCoordinateSystem`、`ToolBankCoordinateSystem`、`DispenseCameraCoordinateSystem`(Dependent)、`BondCameraCoordinateSystem`(Dependent)、`BondCoordinateSystem`、`UpLookCameraCoordinateSystem`(Dependent, CalibModule=2)、`WaferCameraCoordinateSystem`(Dependent, CalibModule=1, Z=27.442)、`WaferTableCoordinateSystem`、`TransportCoordinateSystem`、`DispenseCoordinateSystem`、`NullCoordinateSystem`。
- 注意 `TransportUniCoordinateSystem` 与 `TransportUnitCoordinateSystem` **两个近似重名项同时存在**（JSON 第 26 / 50 行），前者 X=200/Y=−300/Z=100，后者全 0 且 `IsEmpty=true`。类里也有两个同名近似的访问器 `DispesenSystem`（拼写错误，`:177`，查 `"DispenseCoordinateSystem"`）与 `TransportSystem`（`:185`，查 `"TransportCoordinateSystem"`）。

### 5.4 坐标系矫正的范围保护

`UpdateCoordinateSystem(oldPoint3D, newPoint3D, degree)`（`BaseCoordinateSystem.cs:204`）：

- 在**上层坐标系**里算子（`:209-215`）；
- 位移超 ±10 或角度超 0.2 rad 就抛异常（`:217-225`）；
- 然后旋转并累加 `Distance`/`Degree`（`:227-234`）。

`[Obsolete]` 的 `ElementCoordinate` 版本阈值不同（`|X|>5 || |Y|>5 || |Z|>2`，角度 0.2，`:246-254`）——**两个重载的 XY 阈值不一致（10 vs 5）**，是历史遗留差异。当前调用点：`BondModuleController.cs:142`、`TuService.cs:606`、`FrmTest.cs:507`（用的是 `AKRSPoint3D` 版本）。

**对 `Vm`（相机）坐标系调用 `UpdateCoordinateSystem` 是无效的**：它读写的 `Distance.X/Y` 不参与 `Vm` 分支的变换（见 4.1），只有 `Degree` 和 `Distance.Z` 会真正生效。

### 5.5 对焦的搜索策略与终止条件

- 唯一在用的 `AutoFocus`（`:215`）：**两阶段**——粗扫（等距 5 段全范围记录清晰度曲线）→ 精扫（`pulse` 递减 ×−0.5，最多 6 轮，`Round=6`）。终止靠 `T == Round`（`:303`）与粗扫的边界判断（`:240`）。`pulse` 无符号保护，`distance` 为 0 或负时行为未定义。
- `DoFocusing`（死代码，`:30`）：**三阶段** 6/6/8 点爬坡，最后用 MathNet `Fit.Polynomial(x, y, 2)` 二次拟合取顶点 `−b/(2a)`（`:122-127`）并移动到位。阶段步长几何递减：`(P−N)/5`、`/25`、`/125`。
- **步长、范围来源**：范围由调用方传入 `(Plimit, Nlimit)`（主程序传的是 Z 轴的两个绝对位置，如 `FrmTestAccuary.cs:2022` 传 `−6.9, −11.9`、`CalibController.cs:278` 传 `calibratePara.BMCVisionMachinePos.Z ± 2/3`）；`DoFocusing` 还会用 `AxisZ.GetSoftLimit()` 的 `IsEnable` 做前置检查（`:37-39`），未使能直接弹框返回 0。
- **回退策略**：`AutoFocus` 在方向判断错时 `pulse *= −1` 且注释明确写着"不是跑回原来的位置，而是更过去一些，节约时间"（`:287-288`）。

## 8. 注意事项与风险

**坐标系**

1. **`$type` 绑定程序集全名**（`MachineCoordinateSystem.json:2,4,7,121,29` 等）。改 `AKRS.Galaxy2.CoordinateSystems` 程序集名 / 命名空间 / `CoordinateSystems` 子命名空间，或把 `BaseCoordinateSystem` 的某个子类改名 ⇒ 历史 JSON 全部反序列化失败。且 `Load()` 无 `try/catch`（`MachineCoordinateSystem.cs:49-59`），失败会**静默退化为空表**，故障点推迟到业务层 `NullReferenceException`。
2. **`MachineCoordinateSystem` 是手写单例，`Singleton<T>` 被注释掉**（`:12`）。`GetInstance()` 用 `lock (Locker)` 保护初始化（`:33-44`），但 `Save()`（`:86-89`）**无锁**、`CoordinateSystems` 列表的 `RemoveAll`/`Add`（`:125-131`）也无锁 → 多线程下与 `GetInstance()` 的读并发不安全。
3. **`Refresh()` 会丢弃内存改动**（`:64-67`）：只置 `instance = null`，不落盘。
4. **`DeleteCoordinateSystem` 是假的**（`:151-155`）：方法体只有 `this.Save(); return false;` —— 先写盘、不删除、永远返回 `false`。全库无调用点。
5. **`DispesenSystem` 拼写错误**（`:177`，应为 `DispenseSystem`），且 `:177-187` 三个属性的 XML 注释全写成"Bond坐标系"（复制粘贴）；`BondCoordinateSystem`（`:169`）与 `DispesenSystem`（`:177`）**都不检查查找到的项是否为 `GeneralCoordinateSystem` 就强转**。
6. **`WaferCoordinateSystem` / `BondCoordinateSystem` / `DispesenSystem` / `TransportSystem` / `NullCoordinateSystem` / `WaferCameraCoordinateSystem` 六个 `[JsonIgnore]` 访问器全部直接强转 `Find(...)` 的结果**（`:161-217`）。JSON 里缺一个名字 ⇒ `null` 强转或后续成员访问直接崩，且崩在调用方而不是这里。
7. **`Init(List, List, ...)` 只写 `OwnPoint3D`/`UpperPoint3D`/`CalibModule` + 存标定文件，完全不更新 `Distance`**（`:299-315`）。所以 `Vm` 坐标系的 `Distance.Z`（如 `WaferCameraCoordinateSystem` 的 27.442）必须由调用方另行赋值，否则 Z 变换无补偿——这是一条**隐式的、无注释的调用契约**（`:306-314` 还留着被注释掉的 `Distance` 求平均代码）。
8. **`BackConvertCoordinate(AKRSPoint2D)`（`[Obsolete]`）的 `Vm` 分支什么也不做**，只是 `if (this.TransformTool == null) this.TransformTool = new TransformTool();`（`:189-192`），赋了值也不用，随后返回默认点 `(0,0)`。

33. `BaseCoordinateSystem.Init(List, List, ...)` 之后 `Vm` 系的 `Distance.Z` 由谁赋值（风险 7），需要在主程序标定流程里才能确认，超出本篇范围。
