# 全 trunk 动作耗时模拟开发与验收

目标：按照用户要求，从整个 trunk 核对 ZX2200 的全部业务动作，沿引用关系分析其他工程及包，完成源码模拟耗时统计并显示在 ARKS 的动作表格中。trunk 只读，不要求采集或导入，不执行设备程序，不把依赖包的公共方法当成设备工序。

## 完成条件

1. 全目录文件与工程清单可核对；编译中的业务源码、依赖源码、生成文件、未编译文件、未引用示例分别有依据。不能沿目录名字排除所有标定或界面文件后声称覆盖整个 ZX2200。
2. 所有业务动作有入口与稳定身份，包括节点、晶圆/翻转、流道/上下料、换料、吸嘴/真空/气缸、初始化/复位及可独立执行的标定/手动动作。界面包装和被调用子动作保留归属，避免重复相加。
3. 跨工程类型、partial、继承、重载、局部 var 和参数初值不串用；缺失依赖和无法绑定的调用明确记录。
4. 模拟按源码原 DryCycle 分支执行控制流；固定等待、信号轮询、固定/条件循环、提前返回、抛异常、后台任务与同步等待分开处理。启动线程耗时不能冒充其一次工作周期。
5. 运动由原位置、速度、加减速及同步关系建模，支持可计算的运动段与参数化计算；缺少起点/参数的部分保留条件与依据。超时不能当必耗时，后台与并行运动不能直接相加。
6. 用户页面继续采用“工位、动作、耗时、说明、详情”的简洁表格；已跳过、无法执行、部分可算与可算总时长能够区分。详细源码与覆盖信息按需展开。
7. 单元反例、真实全 trunk 分析、API 权限/源码变化、前端与浏览器验证覆盖以上范围；正式数据不混入测试，trunk 内容保持不变。修改提交并推送。

## 初始核对（2026-10-22）

- 16 个 C# 工程，排除生成文件后 1,026 个 C# 文件、6,499 个方法；ZX2200 中 816 个非生成 C# 文件、5,583 个方法，其中 901 个方法直接涉及运动/延时/等待。901 不是独立工序数量，包含界面包装、测试与子动作。
- 原加载器按 ZX2200 子目录及固定目录排除规则分析，没有读取依赖工程。原入口发现限于 ActionNode、Controllers 公开方法及少量换料函数。
- 包内 `AKRS.Galaxy2.Machine/Models/Signal.cs` 的 `Wait()` 在 do 循环中先 Sleep(5)，再等待信号；不能仅把外层 Wait 当成无固定组成的黑盒。
- `TransportTask.StartDryRun()` 包含两个后台交互循环，各有 Sleep(500)；上/下料任务 Start 在 DryCycle 下直接返回。
- `DipFluxActionDryRun()` 首句抛异常，后续运动源码不可达，不能给出成功模拟时长。
- 全目录存在多个同名类型（Program、MathService 等），不能只按短类型名合并。

## 第四阶段：动作执行中的参数状态

复核发现原模型在被调方法、属性或后台任务修改参数后，可能重新使用字段声明初值。例如初值5被Configure改为7后，旧模型仍把随后Sleep算成5 ms。已用反例先复现，并增加成员状态、静态成员和对象身份的传递。同一实例的this/隐式访问、新对象别名、对象参数、构造及getter/setter的后备字段共享相应状态；不同新对象分别处理，继承成员使用实际声明所属类型。ref/out写入回到调用者，无法解析的外部ref/out使旧值失效。

条件表达式、短路表达式及空条件访问合并各分支状态。后台委托尚未等待完成、循环次数或引用别名未确定时，传播参数失效，不能继续套旧初值；直接等待完成的委托可带回已确定的写入。相互引用的属性求值有递归边界，不使全工程分析栈溢出。运动参数对象的显式修改仍可进入包契约模型。此实现没有声称完成任意委托、数据竞争或完整C#运行环境的仿真。

## 第七阶段：委托任务与创建/启动边界
