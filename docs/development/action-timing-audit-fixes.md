## 实现

- 识别直接GTN、ETEL SDK调用，补入停止、补偿下载以及读取/配置/监视等辅助入口。SDK没有固定时间时仍标未定，并注明通信、文件内容或设备停止/下载完成反馈等具体缺项。
- 将`AssistantConfig`中包含实际动作调用的返回、下一步、完成回调，以及旧式`Thread`的工作体列为独立辅助入口；创建步骤或线程时不执行回调正文。向导名称取用户可读的步骤说明。此前复核将点胶向导第276行误写为`doneAction`，实际为`nextAction`，已按源码处理。
- 按当前`ControlService.cs`精确版本核对`UIActionAsync`派发，恢复两个全局标定按钮模拟分支各1,000 ms的后台等待；保留控件类型、互斥和排队条件，不能把它们当成按钮同步总耗时。
- 对循环次数未知或调用展开达到保护边界的入口，保留能够证明的条件/每轮等待组成。例如精度测试的三处30 ms保留为90 ms×点数×次数；固定10轮100 ms保留为1,000 ms。不可达正文不计入，未知次数不拿展开记录数代替。
- 详情显示运动契约已有的20 ms固定等待、加减速度、J及完成规则，明确固定等待与运动重叠，不能重复相加。
- 详情逐项说明缺少的延时当前值、点集/次数、轴起点/目标与有效运动参数、信号、门禁、SDK完成规则或尚未绑定的调用路径。已有V/A/D等请求值不再被笼统写成全部缺失。
- 主表继续保持动作、耗时、说明的简洁形式；缺少总时长但有可算组成时，显示条件或后台停留，完整条件与来源留在详情。导出沿用同一显示规则。
