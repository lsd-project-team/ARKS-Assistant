# 实验系统-具体实验实现（`AKRS.ZX2200/Experiment/` 下 5 个具体实验子目录）

> 以 WinForms 窗体为载体的、真实驱动机器的 13 个「专项实验」窗口：固晶精度、重复定位精度、精度、点胶测高、速度优化。
> 代码规模：13 个文件 / 9,810 行（不含 `*.Designer.cs` 与 `*.resx`）

## 1. 模块定位

本模块是**设备调试/验收期的真机实验窗口集合**，不是产线运行代码。每个窗体 = 一个实验：

| 实验 | 目录 | 测什么 | 是否驱动机器 |
|---|---|---|---|
| 固晶精度 | `Experiment/BondAccuracyExperiment/` | 取片/放片/模拟贴片/上下视定位/角度校正的重复性与偏差 | 是（完整取放片流程） |
| 重复定位精度 | `Experiment/RepeatPositionAccuracy/` | 同一拍照点的重复定位极差、温漂、震动 | 是 |
| 精度 | `Experiment/AccuracyExperiment/` | 相机连续拍照重复性、单轴全程走位精度、回中心精度 | 是 |
| 点胶测高 | `Experiment/DispenseMeasureExperiment/` | 点胶测高针（HeightSensor）读数稳定性 | 是（走 G0 位 + 触发测高） |
| 速度优化 | `Experiment/SpeedImprovementExperiment/` | 取片插补耗时、温漂/定位耗时 | 是（直插补运动） |

### 5.2 坐标系换算

三种写法混用，**同一个文件里也可能混用**：

1. **G0 系内做差**（主流）：`bondModuleController.ConvertMachineToG0Pos(...)` 把示教点转 G0，拍照后用 `system2Controller.GetBondVisionResultPos(match)` / `GetUplookVisionResultPos(match)` 直接得到 G0 坐标，两个 G0 点相减即偏差。见 `FrmSimulateBondTest.cs:582` `:1000`、`FrmAlignAngleAccuracyTest.cs:349`。
2. **像素→G0**：`bondModuleController.ConvertPixelToG0Pos(示教点, matchResult)`，用于「移到相机中心再拍一次」。见 `FrmSimulateBondTest.cs:383`。
3. **正变换矩阵**：`BondCameraCoordinateSystem.ForwardConvertCoordinate(pixelPoint)` / `UpLookCameraCoordinateSystem.ForwardConvertCoordinate(...)`，只在 `FrmAccuracyExperiment.cs:625` / `:675` 两处使用。

**误差分解**：本模块不做矢量分解，统一是「同一次循环里两次定位结果相减」，只有二维偏差：

- X/Y：`postBondRes = glassCenterPos - bMCCenterPos`（`FrmSimulateBondTest.cs:1000`），单位换算 `× 1000.0` 转 μm（`:1008-1009`）。
- θ：`CalibService.CalculateAngle(p2, p1)`（`FrmSimulateBondTest.cs:585,988`）或手写 `Math.Atan((y1-y2)/(x1-x2)) * 180 / Math.PI`（`FrmAlignAngleAccuracyTest.cs:537`）；结果 `postBondAngle = glassAngle - bMCAngle`（`FrmSimulateBondTest.cs:1001`）。

### 5.3 重复定位：往返次数与回原点策略

- `FrmRepeatPositionAccuracy`：**不回原点**。每个循环固定跑到同一示教点（`BMCVisionMachinePos` / `GlassUpLookVisionMachinePos`），中间插入一次 Y = `-21.3914` 的中转点（`:272,297,1241`）。X/Y/Z/ZBMC 四个方法各自用硬编码端点做往返：X 用 `-116.2496 ↔ 122.5`（`:485,502`），Y 用 `-142.438 ↔ 73`（`:687,708`），Z 用 `MoveZAxis(1)` 抬升 + `Sleep(3000)`「升温」再落回（`:892-898`），没有真正的回原点动作。
- `FrmXYAccurayTest`：起点/终点由操作员按 `BtnSetStartPos_Click` / `BtnSetEndPos_Click`（`:94,102`）现场标定，循环里 `MoveBondXYZWithoutSafe(ConvertG0ToMachinePos(startPos))` ↔ `endPos`（`:199,242`），也是 A↔B 往返，不回原点。
- `FrmUpLookMarkTest`：循环体里可选「每次都回温漂 Mark 点」(`ChkIsActiveZMove`，`:90-95`），否则原地连拍。

### 5.4 判据（多少算合格）

**只有 `FrmAccuracyExperiment` 有数值判据**，比较方式是「极差 vs 标准」：

- `FrmAccuracyExperimentResult` 构造函数（`FrmAccuracyExperimentResult.cs:40-70`）对每一列算 `GetMax - GetMin`，拼成文本显示在 `labelControl1`（`:69`）：`"{列名}: 极差为{value}。  标准为{standard}"`。
- **不自动判定合格/不合格**，只显示两个数字，靠人读。
- 各处的标准值：
  - `{0.5, 0.5, 0.05}`（X / Y / 角度）——`FrmAccuracyExperiment.cs:280,311,356,400,453,497,541,594,643,693,737,771`
  - `{0, 0, 0}`——`FrmAccuracyExperiment.cs:846`（相机来回实验）

**其余 4 个目录的实验完全没有判据**：`FrmSimulateBondTest` / `FrmPickupRepeatTest` / `FrmPlacementTest` / `FrmXYAccurayTest` 只把原始定位结果写 JSON/Excel；`FrmRepeatPositionAccuracy` / `FrmAlignAngleAccuracyTest` / `FrmDispenseMeasureHeightTest` 只写 Excel；`FrmUpLookMarkTest` 只存 bmp；`FrmSpeedImprovementExperiment` 只在弹窗里显示一次耗时。

## 8. 注意事项与风险

### 8.1 死循环 BUG 核查（本次重点）

**结论：本篇范围内（5 个目录、13 个文件）已全量核查，未发现 `for (int j = 0; j < …; i++)` 类循环变量写错的死循环。**

核查方式与证据：

- 范围内 `for (int j` 共 3 处，全部自增 `j`，无问题：
  - `AccuracyExperiment/FrmAccuracyExperimentResult.cs:53` `for (int j = 0; j < data[i].Count; j++)`
  - `RepeatPositionAccuracy/FrmRotateCenterAccuracy.cs:85` `for (int j = 0; j < intervalTimes; j++)`
  - `SpeedImprovementExperiment/FrmSpeedImprovementExperiment.cs:275` `for (int j = 0; j < 15; j++)`（外层是 `:273 for (int i = 0; i < 4; i++)`，正常嵌套）
- 范围内 `for (` 共 59 处，逐条核对自增变量与声明变量一致（`int i` 全为 `i++` / `i += 5` / `i += 10` / `i += 60`，`int row` 全为 `row++`，`int k` 为 `k++`）。
- 多行 `for` 头部（`FrmAccuracyExperiment.cs:333,378,475,519`）已展开确认，第三段均为 `i = i + 5`。

**⚠️ 但在范围外的 `CalibSystem/` 里，本项目确实存在同类死循环 BUG**（该目录归属其它文档，此处仅记录线索）：

### 8.2 机器安全：速度/行程保护

- **没有任何独立的速度上限校验**。`FrmAccuracyExperiment` 的速度来自 `SpSpeed` 百分比乘以轴参数（`FrmAccuracyExperiment.cs:91-95`），UI 上限由 Designer 决定，代码不夹紧。
- **行程保护只有一处，且是「用轴参数当循环边界」**：`FrmAccuracyExperiment.cs:333/378/475/519` 用 `AxisSetPara.NLimit + 1` / `PLimit - 1` 作为扫描范围。
- **「随机走位」靠拒绝采样**：`FrmAccuracyExperiment.cs:426-438`（及 `:567-579`）用 `if (x > PLimit || x < NLimit) { i--; continue; }`。这段代码**每轮 `new Random()`**（`:422`、`:563`），`Random` 的种子是 `Environment.TickCount`，紧循环内会反复取到同一种子 → 同一组 x/y；若该组恰好越界，就会不停 `i--` 空转到 TickCount 进位（约 15.6 ms）才可能换出新的随机数。**这不是严格意义上的死循环，但会空转烧 CPU，且实际采样点数/分布与设定值不符**（推断，未运行验证）。
- **`FrmSimulateBondTest` / `FrmPickupRepeatTest` / `FrmPlacementTest` 的取放片动作不受实验代码保护**，全靠 `BondAction` / `PickAction` 内部的到位与安全逻辑。

### 8.4 异常处理与「失败后机器状态」

- **catch 里只弹框、不做安全回位**：`FrmSimulateBondTest.cs:1054-1061`、`FrmPickupRepeatTest.cs:817-824`、`FrmPlacementTest.cs:901-908`、`FrmRepeatPositionAccuracy.cs:426-432`、`:620-626`、`:818-824`、`:1001-1008`、`:1185-1191`、`:1314-1320`、`:1628-1634` 都是「记日志 / 弹 MessageBox → `return`」，**没有一次 `MoveToSafePos()`**（`MoveToSafePos` 只在 try 正常路径的末尾调用，如 `FrmSimulateBondTest.cs:1052`）。异常抛出时焊头可能停在贴片高度、真空仍开着。
