# 回答质量与检索优化验收

## 2026-10-12 检索范围与输出完整性升级

- 分析模式可在“设置 → 模型 → 分析与回复完整性”配置。自动模式识别项目进度、整个项目及完整流程；普通预算默认 24 次，深度默认 64 次，总预算中预留 8 次关键源码复核。进入预留阶段停止广泛搜索；同版本源码复用不重复占用额度。
- `plan_source_checks` 保存核查范围；`read_source_batch` 每次最多 12 段，合并相邻范围，最多 1200 行并限制正文大小。超过正文额度只返回可容纳的前缀，剩余行明确列出；缺失文件不冒充成功读取。调整旧工具转存阈值，避免批量结果再次被转成单行临时文件。
- 深度分析默认回复上限 8192 tokens（受配置的上下文容量约束），保留原模型配置。记录供应商结束原因；明确因输出长度停止时最多自动续写两次，合并边界重复后再校验引用和结论。缺失结束原因且达到上限标为“可能截断”，不盲目续写。
- 运行状态和核查完整度分开：工具成功、预算未执行、真实失败、缓存复用分别统计；运行结束仍可能是部分核查完成、回答未完整或可能截断。`run_completion`、`analysis_plan`、`analysis_progress` 保存在原有事件数据库，不需要更改历史回答或数据库结构。
- 继续核查优先处理剩余范围，并复用同版本正文、引用核对和结论复核记录。文件变化或无法读取时不复用。独立复核器顺带读取的范围不能自动将未执行目标判为已完成；原问题随分析计划保留。
- 项目进度报告分清未实现/停用、待测试验证、待工艺确认、标定配置前置；方法局部短路不能推广到整个功能缺失，默认配置不能当作不可修改常量。缺少需求清单与验收记录时不编造整体完成率。

验收测试：`test_answer_completion.py` 覆盖正常结束、长度截断、缺少结束原因、最多两次续写及重复合并；`test_analysis_workflow.py` 覆盖分级预算、复核预留、批量截取、缓存失效；`test_analysis_runtime.py` 使用实际 Deep Agents 图验证来源复核、事件持久化、部分完成后的继续核查及批量正文直达模型。真实模型验收报告保存在 `output/analysis-upgrade-live-delivery/report.json`，使用独立数据目录，凭据只在内存中。

## 真实结果与边界

- 实际供应商为当前配置的 `DeepSeek-V4-Flash`，不是替身。报告保存于 `output/quality-evaluation/report.json`；入口顺序、取消后不调用 Start 且 finally 执行、多轮配置为 false 的安全门分支、两次连续压缩和真实 DeepWiki 调用均有原始事件。
- 初次“启动前检查”回答错误概括为所有返回点都在运动调用之前。旧回答没有覆盖；`output/quality-evaluation/source-review-negative.json` 记录真实模型识别出的反例。第六个 `return false` 位于当前源码第 252 行，晚于第 236/240/245 行的调用。
- `output/quality-audit/report.json` 保留完整复测：独立复核发现离线分支和六项检查名称的错误，自动修正后再次复核通过。引用校验仅证明当前路径/定位范围/版本/读取覆盖；AI 复核通过不证明设备已经运动或外部程序集的实际机制。
- 实际自然语言记忆矛盾复核已通过；`memory-compatible.json` 记录“维护模式”和“生产模式”条件不同，被判为兼容。模型建议不自动覆盖已有记忆。自动项目记忆缺少本轮当前源码依据时进入待复核，失效记忆不会被 Agent 自动重新启用。
- 当前 DeepWiki 服务没有给出索引提交，本地 trunk 也不能冒用应用仓库的提交号。界面显示版本未知，具体结论仍由本地文件 SHA256 和片段复核。
- Roslyn 静态读取项目配置，不执行业务项目的 MSBuild 导入、包还原或构建。条件配置、缺失项目、DevExpress 和外部硬件程序集可导致 partial；接口候选实现不等于运行时实际分派。
- 主项目包含 1,137 个被索引文件。首次冷分析约 28.49 秒，重复约 3.04 秒；另一次记录为 4.89 秒 → 2.66 秒，后次零文件重解析、零项目重建。记录在 `output/roslyn-performance.json` 和真实问答报告中。每次仍读取文件计算版本，不能宣称无成本。
- 单轮工具检索预算为 24 次，达到预算后要求按已有资料收尾，未读实现保留未知。供应商延迟和额外复核会增加回答耗时；实际用量包含这些请求。无法核实的结论在回复正文及上下文显示，不会把有效链接等同于完整事实证明。
- 大型 C# 文件曾触发原生 Tree-sitter 崩溃。现在优先 Roslyn 语法解析，备用解析放在独立子进程，解析失败不影响读取原始源码或主服务。
