# 基础设施核心层（`AKRS.ZX2200/Infrastructure/`，不含 `Controls/`）

> 全项目共用的非 UI 底座：数据库访问、路径常量、参数反射绑定、AOP 切面、报警落库、UI 线程抽象、数学/几何算法、Excel 导出、固高与 ETEL 驱动直连。
> 代码规模：59 个文件 / 11,677 行（不含 `*.Designer.cs`；不含 `Infrastructure/Controls/` 的 70 个文件）

## 1. 模块定位

`Infrastructure` 是 `AKRS.ZX2200` 内部被引用最广的命名空间。它不属于任何业务域，却几乎被所有业务域引用：

## 5. 关键实现细节

### 5.1 `DBService`：单例 + 连接复制 + 全量吞异常

- 单例：`private static readonly Lazy<DBService> instance = new(() => new());`（`Service/DBService.cs:27-28`），`public static DBService Instance => instance.Value;`（`:73`）。
- **连接串硬编码**（`Service/DBService.cs:43-44`）：
  ```csharp
  private const string ConnectionString = //"Data Source = localhost;Initial Catalog = ZX2200;User Id = sa;Password = sa123456";
  "Server=localhost;Database=ZX2200;Trusted_Connection=True;";
  ```
  上一行的 SQL 账号密码方案被注释保留。**没有配置文件兜底，改库只能改源码重编译。**
- 所有静态 CRUD 都 `Instance.db.CopyNew()` 出一个新连接（`:88`、`:108`、`:128`、`:353`、`:371`），保证线程安全——但**每条语句都新建连接**。
- **所有方法都是 `try { ... } catch (Exception ex) { LogHelper.Post(...) }`**：写入失败、查询失败、建表失败、更新失败一律吞掉，查询失败时返回空列表（`:116`、`:137`）。调用方无法感知数据库不可用。
- `GetScalar(string queryStr)`（`Service/DBService.cs:369-375`）：
  ```csharp
  public static object GetScalar(string queryStr)
  {
      using SqlSugarClient db = Instance.db.CopyNew();
      return null;              // ← 无条件返回 null

      return db.Ado.GetScalar(queryStr);   // ← 不可达
  }
  ```
  **该方法是死的**。3 处调用者（`SupportFeature/Statistics/StatisticsService.cs:154`、`:161`、`:185`）因此全部失效：`GetMaxMTBA()` 里 `o == null` 恒成立直接 `return 0`（`StatisticsService.cs:156-159`）；`GetTotalAlarmSeconds()` 本身也在 `StatisticsService.cs:183` 提前 `return 0`。**MTBA 与报警时长两项统计指标恒为 0。**
- 建表用 `db.CodeFirst.InitTables<T>()`（`:148`），包在 `try/catch` 里，失败静默。因此**表结构由 C# 实体类决定**，`libs/ZX2200.sql` 只是初始脚本。

### 5.2 `MethodAopAttribute`：本项目**实际**的鉴权判据

这是任务书特别要求核实的点。本项目中的**真实**判据是（`AOP/Module/MethodAopAttribute.cs`）：

| 步骤 | 代码位置 | 内容 |
|---|---|---|
| 1 | `:30-33` | `if (arg.Arguments.Length != 2) return;` —— **方法必须恰好有 2 个参数**才进入任何逻辑。`(object sender, EventArgs e)` 这类标准事件签名正好是 2 个 |
| 2 | `:36-37` | 只认 `arg.Arguments[1] is ItemClickEventArgs` 且 `itemClickEventArgs.Item is BarButtonItem` |
| 3 | `:39` | 所需权限 = `(RoleEnum)(int)barButtonItem.Tag`；**`Tag == null` 时默认按 `RoleEnum.Engineer`（工程师）** |
| 4 | `:41` | 当前权限 = `(RoleEnum)Machine.GetInstance().CurrentRoleLevel` |
| 5 | `:44` | **`role.CompareTo(currentRole) < 0 && MachineSoftwareConfiguration.GetInstance().IsPermissionOpen`** → 判为权限不足 |
| 6 | `:46-53` | 弹 `AKRSMessageBoxExt.ShowWarn(...)`，然后 `arg.FlowBehavior = FlowBehavior.Return;` —— **静默拦截，方法体不执行** |
| 7 | `:56-58` | 鉴权通过 → `StatisticsService.SaveEntity($"点击了主界面按钮：{barButtonItem.Caption}", RuntimeProvider.CurrentLoginUser?.Name)` |

配套事实：

- `RoleEnum` 取值 `Admin = 1, Engineer = 2, Operator = 3`（`Models/Enums/CommonEnum.cs:56,62,68`）。**数值越小权限越高**，故 `CompareTo < 0`（所需值小于当前值）即「要求比当前更高」→ 拒绝，语义正确。
- 当前权限来自 `Machine.GetInstance().CurrentRoleLevel`（`Main/Machine/MachineSupport/Machine.cs:85`），其实现 `GetCurrentRoleLevel()`（`Machine.cs:115-124`）：未登录时 `level = 3`（等于 `Operator`），登录后 `level = RuntimeProvider.CurrentLoginUser.RoleID`。
- 总开关 `MachineSoftwareConfiguration.IsPermissionOpen` 默认 **`true`**（`Main/Machine/MachineSupport/MachineSoftwareConfiguration.cs:115`），即鉴权默认生效。
- `Tag` 不是枚举而是 `object`，运行时强转 `(int)`；**若某按钮的 `Tag` 被填成非整数类型会抛 `InvalidCastException`**，且该异常发生在 AOP 织入的入口处（未经 `UIExceptionHandlerAttribute` 兜底）。
- 其余三种分支（`:60` `FocusedNodeChangedEventArgs`、`:69` `ImageListBoxControl`、`:84` `SimpleButton`）**只记操作日志，不做任何鉴权**。
- `OnExit` 为空实现（`:98-100`）；`OnException` 只记一条「界面操作异常发生」（`:106-111`）。

### 5.3 编译期 AOP：Fody + PostSharp **两套并存**

`FodyWeavers.xml`（项目根）启用两个织入器：
```xml
<PropertyChanged />        <!-- PropertyChanged.Fody 4.1.0 -->
<MethodBoundaryAspect />   <!-- MethodBoundaryAspect.Fody 2.0.145 -->
```
`packages.config` 同时引用了 `PostSharp` 与 `PostSharp.Redist`（`AKRS.ZX2200.csproj:4105,4108`，`libs/PostSharp.dll` 存在）。

| 切面 | 织入器 | 依据 |
|---|---|---|
| `MethodAopAttribute`、`PropertyAopAttribute`、`S1/S2SingleStepAop`、`UIExceptionHandlerAttribute` | **Fody** | 继承 `MethodBoundaryAspect.Fody.Attributes.OnMethodBoundaryAspect` |
| `LogRecordMethodAttribute` / `LogRecordPropertyAttribute` / `LogRecordButtonAttribute` | **PostSharp** | `Models/CommonModels/LogRecordAttribute.cs:18-20`（`[PSerializable]`、`using PostSharp.Aspects`） |

两者行为（`FlowBehavior`、`OnEntry` 语义）不通用：Fody 版用 `FlowBehavior.Return`/`Continue`、PostSharp 版用 `FlowBehavior.Continue`。

**`LogRecord*` 三个特性在本项目中从未被任何方法/属性标注**（全库 grep 只命中定义本身），且它们写的是**另一个数据库**（见 §7），因此这三个类实际上是完全未启用的历史遗留。

### 5.7 双线性补偿（`BilinearCompensator`）

三级结构（`Models/CommonModels/BilinearCompensator.cs`）：

```
BilinearCompensator (补偿器)
  └─ List<RegionCompensator> (区域 + 名称 + Priority)    :228
       └─ BilinearCompensationRegion (网格)              :17
            └─ List<List<KeyValuePair<Coords2D, Coords2D>>> compensationRows
                 // Key = 轴坐标(AxisX,AxisY)，Value = 补偿量(ScanAxisX-AxisX, ScanAxisY-AxisY)   :54-56
```

- 网格由标定数据构造，按 `WorldY` **四舍五入到 6 位小数**分组为行（`:51`），行内按 `WorldX` 升序（`:53`）；**构造函数要求标定点 ≥ 4 个**，否则抛 `ArgumentException("标定数据不足")`（`:45-48`）。
- 查找：`FindInterpolationCell`（`:62`）双层遍历网格四边形，用「同侧叉积」判点在四边形内（`IsPointInQuad` `:155`、`SameSide` `:169`，容差 `-1e-10`）。
- 插值：`BilinearInterpolation`（`:119`），先按 X 两行线性插值（`:135-136`），再按 Y 合并（`:137`）；分母 `(x2-x1)*(y2-y1)` 绝对值 `< 1e-10` 时抛 `InvalidOperationException("网格顶点异常")`（`:130-133`）。
- 命不中任何区域返回 `new(0,0)`（`:305`），**不报警**。
- 区域按 `Priority` 降序遍历、取**首个**命中并 `return`（`:297-302`）。由于 `RegionCompensator.Contains` 内部已调用过一次 `TryInterpolate`（`:216`），实际每次插值会**重复计算两遍**（见 §8.7）。
