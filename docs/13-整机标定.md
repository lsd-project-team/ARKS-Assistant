# 标定系统·算法与数据模型说明（`AKRS.ZX2200/CalibSystem/GlobalCalibration`、`GlobalCalibrationEnd`、`Models`、`Services`）

> 整机标定负责把「相机像素坐标 ↔ 运动轴物理坐标」以及「各工位坐标系之间的相对关系」一次性测出来并落盘，是后续所有贴片/点胶动作的几何基准。
> 代码规模：20 个文件 / 9,805 行（不含 `*.Designer.cs`；含 Designer 共 13,863 行）

本文件只覆盖上述四个目录。标定相关的**界面与测试**（`CalibSystem/Controls/`、`Test/`、`TestControls/`、`CalibSystem/` 根目录文件）见 `14-标定系统界面与测试.md`；`Experiment/` 下的精度实验见 `16`/`17`。

---

## 1. 模块定位

整机标定的产物分成三类，分别由三套互不相通的机制承载：

| 产物 | 载体 | 消费方 |
|---|---|---|
| 坐标系链（相机像素 → 轴坐标） | `MachineCoordinateSystem.json` + 每相机一个 `.iwcal` | 运行期的 `BondModule`、`UpLookModule`、`DispenseController` 等 |
| 标定参数（视觉走位点、偏移量） | `CalibratePara.json` | `CalibrateTask` 自身、各 `Controls/Assistant` 示教界面 |
| 二维映射补偿表 | 直接写入**驱动器**（ETEL `DownloadMapping` / 固高 `CompensateX/Y`），另有 JSON 副本 | 运动控制器固件 |

模块在整机流程中的位置：开机后由操作员点击「自动标定」，`CalibrateTask` 依次驱动 Bond 头、上视相机、晶圆台走位并取像，把 `MachineCoordinateSystem` 中的若干坐标系重新 `Init` 一遍，最后 `calibratePara.Save()`。运行期贴片时，各模块从 `MachineCoordinateSystem` 取坐标系做正/反变换。

- **上游**：`System2Domain`（运动/IO 门面）、`HardwareRepositoryService`（相机）、`VisionEntityRepository`（PR 模板）、`BondDevicePara`（测高结果）。
- **下游**：`AKRS.Galaxy2.CoordinateSystems`（坐标系框架，本项目内**有源码**，位于仓库根 `AKRS.Galaxy2.CoordinateSystems/`）、各运动驱动（ETEL / 固高 / 雷赛）。

## 4. 核心流程

### 4.1 自动标定主链（唯一「正确顺序」的来源）

```
操作员点「自动标定」
  → UcMainSystem.BtnStart_ItemClick           Main/Controls/Ucmain/MainControls/UcMainSystem.cs:1340
      Machine.AllAxisGoHome()  →  Task.Run(...)  (系统2 分支 :1355)
  → CalibrateTask.StartAutoCalib()            Models/CalibrateTask.cs:2275
      ── 仅靠 AKRSXtraMessageBox 弹窗确认，无任何前置校验 ──
      OK   → StartBondCalibTask()                       :2303  (Bond 相机标定 + 测高)
      OK   → StartBondToCamCalibTask1()                 :2325  (旋转中心标定)
      OK   → StartUpLookCalibTask()                     :2330  (上视相机标定)
      OK   → StartBondToCamBySameMarkTask()             :2350  (Bond/上视同 Mark 对齐，可跳过)
      ──  → StartUpLookMachinePosTask()                  :2357
      OK   → StartWaferTableCalibTask()                 :2372  (晶圆台左右 Mark 间距)
      OK   → StartWaferNPointCalibTask()                :2377  (晶圆台 N 点标定)
      → calibratePara.Save()                            :2392
      → new FrmCalibResult().Show()                     :2397  (结果表格)
```

每个 `Start*Task()` 内部失败时返回 `false` 并弹窗，`StartAutoCalib` 用 `if (!...)` 判断后**整体中止**（:2303、:2325、:2330、:2350、:2372、:2377）。注意 :2357 的 `StartUpLookMachinePosTask()` 判断独立成块，其失败**不会**中止后续（见第 8 节）。

### 4.2 单步标定（诊断菜单）

`UcMainSystem.Diagnosis.cs:101/111/129/148/159` 分别调用 `OnlyDispenseCameraCalib()` (`CalibrateTask.cs:1073`)、`OnlyBondCameraCalib()` (:1162)、`OnlyBondToCameraOffsetCaib()` (:1817)、`OnlyUpLookCameraCalib()` (:1257)、`OnlyWaferCameraCaib()` (:1712)。这些方法与自动链共用底层代码，但**部分分支存在实质差异**（见 4.4）。

### 4.4 自动链与单步链的行为差异（重要）

`StartUpLookCalibTask()` 中 `BondRotateCenterToCamOffset.X/Y -= bondOffset` 的补偿被**注释掉**（`CalibrateTask.cs:605-606`），而在单步版 `OnlyUpLookCameraCalib()` 中**是激活的**（:1662-1663）。也就是说自动标定与单步标定出来的 `BondRotateCenterToCamOffset` 不是同一个值。

## 5. 关键实现细节

### 5.1 坐标系框架（`AKRS.Galaxy2.CoordinateSystems`）

框架源码在本仓库内（**不是** DLL）：`AKRS.Galaxy2.CoordinateSystems/CoordinateSystems/` 下 `BaseCoordinateSystem.cs`(344)、`MachineCoordinateSystem.cs`(238)、`TransformTool.cs`(383)、`GeneralCoordinateSystem.cs`(134)、`DependentCoordinateSystem.cs`(63)、`ElementCoordinate.cs`(61)。

- 根坐标系是 `G0`；`MachineCoordinateSystem` 是单例根容器，`FilePath` 指向 `StaticPara.MachineCoordinateSystem`（`StaticPara.cs:30`，基于 `Application.StartupPath`，**无硬编码绝对路径**）。
- 每个坐标系有 `Type`：`CoordinateSystemTypeEnum { Vm=0, General=1 }`（`BaseCoordinateSystem.cs:332`）。
- `ForwardConvertCoordinate`（`BaseCoordinateSystem.cs:84`）：
  - `General`：`X = Distance.X + (x*cos(Degree) - y*sin(Degree))`，`Y = Distance.Y + (x*sin(Degree) + y*cos(Degree))`，`Z = z + Distance.Z`（:90-94）。
  - `Vm`：惰性加载 `TransformTool.GetCCalibTransTool(this.Name)`，再走海康 `CCalibTransTool`；返回值是 `center(1224,1024) - result`（`TransformTool.cs:241-266`）。
- `BackConvertCoordinate`（`BaseCoordinateSystem.cs:140`）只支持 `General`；`Vm` 直接 `throw new InvalidOperationException("不支持海康标定的逆运算")`（:159）。
- 单位：`Distance` 用 `AKRSPoint3D`（mm），`Degree` 用**弧度**（`UpdateCoordinateSystem` 里角度阈值 0.2 对应约 11.5°，见 5.5）。

`MachineCoordinateSystem.CreateCoordinateSystem`（`MachineCoordinateSystem.cs:104`）的行为是：`CoordinateSystems.RemoveAll(it => it.Name == selfName)`（:125）后追加新对象，再 `Save()`（:88）。上层坐标系缺失且非 `G0` 时 `throw new InvalidOperationException("上层坐标系丢失")`（:121）。`DeleteCoordinateSystem`（:151）**只保存不删除**，永远 `return false`。

### 5.2 坐标系落盘清单

运行期 `bin/Debug/Settings/DeviceParams/MachineCoordinateSystem/` 下实测 14 个坐标系（`MachineCoordinateSystem.json`，64,768 字节）：
`G0`、`TransportUniCoordinateSystem`、`TransportUnitCoordinateSystem`、`WaferCoordinateSystem`、`ToolBankCoordinateSystem`、`DispenseCameraCoordinateSystem`、`BondCameraCoordinateSystem`、`BondCoordinateSystem`、`UpLookCameraCoordinateSystem`、`WaferCameraCoordinateSystem`、`WaferTableCoordinateSystem`、`TransportCoordinateSystem`、`DispenseCoordinateSystem`、`NullCoordinateSystem`。
`CalibModule` 分布：12 个 `0`(`AxisAndCameraIsTogether`)、1 个 `1`(`CameraStaticUp`)、1 个 `2`(`CameraStaticDown`) —— 与代码中晶圆相机设 `CameraStaticUp`、上视相机设 `CameraStaticDown` 一致。

每个 Vm 相机坐标系除 JSON 外还各有一组同名文件：`BondCameraCoordinateSystem.{iwcal,prc,xml}`、`DispenseCameraCoordinateSystem.*`、`UpLookCameraCoordinateSystem.*`、`WaferCameraCoordinateSystem.*` 以及 `DispenseCoordinateSystem.*` 和 `标定.prc`(181,488 B)。`.iwcal` 由海康 `CNPointCalibTool.ExportCalibFile` 生成（`TransformTool.cs:321-322`），**换相机/换镜头后必须重新生成，且不可跨机型复制**。

### 5.3 N 点标定与点数约束

`CalibService.NPointTrans`（`CalibService.cs:202`）调用 Halcon `HOperatorSet.VectorToHomMat2d`（:224）求仿射矩阵；配套 `HomMat2dToAffinePar` 拆成 scaleX/scaleY/phi/slant/xTrans/yTrans。上游 `TransformTool.CalcTransMatrix`（`TransformTool.cs:335`）有硬约束：

- 相机点数 ≠ 轴点数 → `throw new ArgumentException("相机点数和轴点数不一致")`（:338-341）
- 点数 `< 4 || > 32` → `throw new ArgumentOutOfRangeException(..., "标定点数需要设置在4~32个范围内")`（:344-347）

### 5.4 二维映射补偿模型

`GlobalCalibrationDomain`（`GlobalCalibrationDomain.cs:22`）用**网格 + 双线性插值**：
- 网格参数 `StartPoint3D`/`ColumnSpacing`/`RowSpacing`/`ColumnCount`/`RowCount`（:30-50），实测 `ColumnSpacing=RowSpacing=2.0`、`ColumnCount=180`、`RowCount=134`、`StartPoint3D≈(-31.63,-224.69,-1.654)`。
- 补偿值以**定点整数**存储：`CompensateX/CompensateY` 为 `int[,]`（:70/:75），写入时 `* 10000.0`（`FrmGlobalCalibration.cs:1248-1250`），读取时 `/10000`（:141-142）。所以 JSON 里的 `64` 表示 0.0064 mm。

2025 实验版 `GlobalCalibrationDomainEx`（`:21`）改用「多区域 + `BilinearCompensator`」：`ScanData` 为 `List<GlobalCalibrationData>`（:76），`BilinearCompensator Compensator`（:88），区域按 `priority` 排序后插值。`ScanCompletedFlag`（:82-83）判定标准是 `ScanAxisX/ScanAxisY` 中为 0 的个数 < 3。

### 5.5 有效性校验现状（关键）

标定结果的「体检」非常稀疏，逐条列全：

| 校验点 | 位置 | 阈值/行为 |
|---|---|---|
| 坐标系矫正量 | `BaseCoordinateSystem.cs:217-220` | `|ΔX|>10 \|\| |ΔY|>10 \|\| |ΔZ|>10` → `throw new Exception("坐标系矫正XYZ超出范围，矫正失败")` |
| 坐标系矫正角 | `BaseCoordinateSystem.cs:222-225` | `|degree|>0.2`（弧度）→ `throw` |
| 补偿超出行程 | `GlobalCalibrationDomain.cs:96-100` | 超出网格范围 → `throw new Exception("补偿范围超极限")` |
| 补偿值过大 | `GlobalCalibrationDomain.cs:144-147` | `|插值X|>1 \|\| |插值Y|>1`（mm）→ `throw new Exception("补偿值过大")` |
| ΔX/ΔY 关系表 | `BCOffsetRelationModel.cs:155-159` | `ΔX>1 \|\| ΔY>1` → 弹窗并返回 `(0,0)`；**只判正不判负** |
| 定心像素容差 | `CalibController.cs:161-215` | 重试 `maxRetry` 次仍超出容差 → 弹窗 + `return false`；**调用方普遍忽略返回值** |
| 相机-顶针拟合 | `OffsetFitter.cs:33-34`、:89-90 | 点数 < 2 → `throw ArgumentException`；`|varX|<1e-10` → `throw InvalidOperationException` |
| 点数范围 | `TransformTool.cs:344-347` | 4~32 点 |
| 扫描点数（Ex） | `FrmGlobalCalibrationEx.cs:419-423`、:1514-1524 | `ScanData.Count < 3` 时仅弹警告 |

**没有校验的地方**（重点）：
1. `CalibService.NPointTrans`（`CalibService.cs:202-225`）把视觉给的任意点直接喂给 Halcon，**不检查残差、不检查点数下限、不检查仿射行列式**。
2. `CalibrateRunPara` 所有走位点默认 `new AKRSPoint3D()` = `(0,0,0)`；漏做某一步时下游会**静默使用 0**（例：`BondRotateCenterToCamOffset`，`CalibrateRunPara.cs:81`）。
3. `CalibController.LocateAndMoveToTargetPixel`（`CalibController.cs:161`）失败时只弹窗并 `return false`，`CalibrateTask` 中 15 处调用**全部忽略返回值**，标定照常继续并在结果里写入按失败点算出的偏差。
4. `MachineCoordinateSystem.CreateCoordinateSystem`（`MachineCoordinateSystem.cs:125`）遇到同名坐标系直接 `RemoveAll` 覆盖，**无备份、无确认**。

### 5.6 安全与碰撞相关

范围内**没有软限位、没有防撞检查、没有速度上限校验**。仅有的「安全」手段是走位顺序与硬编码插补参数：

- `CalibController.MoveDispenseToMachinePos`（:47）先抬 Z 到 0（:56），再走 XY，最后落 Z（:58）—— 唯一成体系的避撞顺序。
- `MoveDispenseZToSafePos()`（:91）抬 Z 到 0。
- `FrmGlobalCalibration.MoveXY`（:825）ETEL 分支硬编码一整套插补参数：`ipolTanVelocity(0.05)`、`ipolTanAcceleration(0.5)`、`ipolTanDeceleration(0.5)`、`ipolTanJerkTime(0.01)`、`ipolLine(x/1000.0, y/1000.0)`、`ipolWaitMovement(100000)`（:839-849），源码自带注释 `// 设置抖动时间，不知道什么意思`（:843）。
- **反例**：`FrmBondCompensateCalibration.MoveToPos`（:376）把 XY 与 Z 拆成两次独立绝对运动，**无互锁**；其 `Pick`/`Bond`（:387/:411）使用硬编码力控 `ForceControlSet(50, z, 100)` 与 `ForceControlReset(z, 10)`，无吸嘴/力控状态前置检查。

## 8. 注意事项与风险

### 8.1 顺序依赖与「静默错误结果」

- **顺序只靠弹窗约束**。`StartAutoCalib()`（`CalibrateTask.cs:2275-2403`）没有任何「前置标定是否已完成」的程序化判断，全靠操作员按提示点 OK。跳步不会报错——`CalibrateRunPara` 缺失字段默认 `(0,0,0)`（如 `BondRotateCenterToCamOffset`，`CalibrateRunPara.cs:81`），下游拿到 0 后会算出**物理上说得通但实际错误**的结果，且没有任何告警。
- `StartAutoCalib` 中 `StartUpLookMachinePosTask()` 的失败分支（`:2357`）与其他步骤写法不同，其失败不会中断后续晶圆台标定，会继续用不完整的 `GlassUpLookVisionMachinePos` 往下算。
- 单步标定（`Only*` 方法）**不检查任何前置条件**，可从诊断菜单任意顺序执行；重复执行会通过 `CreateCoordinateSystem` 的 `RemoveAll`（`MachineCoordinateSystem.cs:125`）**直接覆盖**上一次的良好结果。

### 8.2 硬编码与机型耦合

- **硬编码绝对路径（本项目范围内共 9 处）**：
  - `FrmGlobalCalibration.cs:1310` → `D:\二维补偿数据\二维补偿数据{HHmmss}`

  - `FrmGlobalCalibrationEx.cs:888`、`:933` → `D:\2025二维标定数据采集\新数据采集带补偿{HHmmss}`
  - `FrmGlobalCalibrationEx.Designer.cs:741` → 同一目录写进了 ToolTip 文案
  - `GlobalCalibrationEnd/BCOffsetRelationCalib/FrmCalibration.cs:482` → `D:\MoveTestPR.xlsx`
  除 `FrmGlobalCalibration.cs:1310` 外，`D:\` 盘不存在时这些代码会直接抛 `DirectoryNotFoundException`（未捕获）。

- `FrmGlobalCalibrationEx.cs:459-460` 与 `:1559-1560`：`double colSpace = Convert.ToDouble(this.SpRowSpacing.EditValue);` —— `colSpace` **读的是行间距控件**（应为 `SpColumnSpacing`）。

- `FrmGlobalCalibration.OpenStage` 的 ETEL 分支（:454）先调 `ETelDrive.Close2DCompensate`，与 `CloseStage`（:415）中的调用相同——是否为「先复位再开」的有意设计未能确定。

- `FrmCalibration.BtnStartCalibration_Click` 的内层 `xNum` 循环抛异常时只 `break` 内层并弹窗（:336-340），**外层继续**，可能保存部分数据。
