# 支撑特性一：测高、运动规划与监控（`AKRS.ZX2200/SupportFeature/` 下 8 个子目录）

> 本模块是「辅助功能层」：测高（水平/焊头平面度）、取片安全区运动规划、加热设置、传感器扫描、日志与调试窗体，外加两套并存的参数编辑 UI。
> 代码规模：66 个源文件（65 个 `.cs` + `Logs/Log4Net.config`）/ 13,001 行（不含 `*.Designer.cs`、`*.designer.cs`，另有 34 个 `.resx` 与 34 个 Designer 文件）

---

## 1. 模块定位

本模块**不参与固晶主流程的实时控制**，而是提供三类能力：

1. **测高（LevelMeasurementSystem）** —— 在换型/保养后测量治具与焊头的**平面度**，给出高度极差（`Range` / `MaxDifference`）供工程师判断。测量动作本身由 `BondSystem`/`DispenseSystem` 的控制器执行（`BondHeadController.MeasureHeight`、`DispenseMeasureHeightController.DispenserHeightMeasurementG0`），本模块只负责**示教点位、遍历点位、收集结果、着色展示**。
2. **运动规划（MotionPlan）** —— 保存「取片安全区域」四角点，并据此计算取片时焊头的**避让路径**（直线段 + 抛物线段）与**分段加减速参数**。
3. **监控与配置（HeatingSettings / SensorCheckScan / RealTimeDisplay / Logs / Parameters / Calibrate）** —— 加热温度设定、后台传感器扫描报警、实时高度曲线、日志与设备调试窗体、参数树编辑、标定示教入口。

上游：`Main/Machine`（后台监控线程调用 `NeedScanSensorPool`）、`Main/Controls/Ucmain`（菜单打开各窗体）。
下游：`BondSystem`（焊头/模组控制器）、`DispenseSystem`（点胶测高）、`TransportSystem`（加热器）、`WaferSubSystem`（顶针/晶圆台）。

> **力控相关代码不在本篇**：本模块唯一与力控的接触点是 `Parameters/ObjParameter/ParameterManage.cs:12`、`:38` 引入了 `AKRS.ZX2200.BondSystem.BondForce.*`，并在 `:178-200` 把 `ForceConfig`、`LargeForceConfigItemList`、`SmallForceConfigItemList` 挂成参数树节点（`TreeGroupChildNodesEnum.ForceCalibrate / ForceControl / SmallForceControl`）。力控本体见第 12 篇。

## 5. 关键实现细节

### 5.1 测高结论

- **测高原理**：系统1 用点胶测高传感器（`System1MeasHeightToolEnum.HeightSensor`）；系统2 用焊头 TD 传感器（`HeightMeasurementFunctionEnum.WithTDSensor`），**可选激光测高**（`IsSystem2ConfigLaserMh` 时为 `S2DispenseController.LaserMeasureHeight()`）；焊头平面度用 `WithTDSensor`。**本模块内没有任何 LVDT / 影像测高调用**，唯一 LVDT 痕迹是 `FrmBondLevel.cs:199` 的注释。
- **采样与滤波**：本模块**没有滤波算法**。滤波/采样全部下沉在 `BondHeadController.MeasureHeight`（`BondSystem/Controllers/BondHeadController.cs:640` / `:665`），本模块只传「搜索位置、搜索距离、搜索速度」（如 `10, 2`、`10, 0.5`，见 `FrmSystem2FlatLevelMeasure.cs:172`、`FrmBondLevel.cs:154-155`）。**这是本文档范围内最需要注意的边界**：测高算法不在本模块。
- **多点遍历**：点位列表、名称、`ZG0Pos` 一起存在 `BaseDsSetting` 子类的 JSON 里；测量时逐点 `MoveToG0Pos` + 一次 `MeasureHeight`，**每点只采一次，不做重复采样/取平均**。
- **结果参与后续动作的方式**：结果**不写回任何参数**，只显示（`FrmLevelMeasureResult` / `FrmBondLevelMeasureResult`）并可导出 `*.xls`（`FrmLevelMeasureResult.cs:35-62`）。也就是说，测高是**纯人工判读工具**，不会自动补偿固晶动作。
- **展示着色**：`FrmLevelMeasureResult.cs:79-107` 与 `FrmBondLevelMeasureResult.cs:81-109` 用 `GetMinMaxValue()` 在 `CustomDrawCell` 里把最小值行标 `YellowGreen`、最大值标 `OrangeRed`、其余 `AliceBlue`；比较用 `Math.Abs(diff) < 0.000001`。
- **坐标系**：测高值统一转成 **G0 坐标**后再比对（`ConvertMachineToG0Pos`，见 `FrmSystem2FlatLevelMeasure.cs:181`、`FrmBondLevel.cs:165-166`）。

### 5.2 运动规划实现

`MotionPlanDomain` 的全部算法都在一个文件里：

- **安全区域**：4 个 `AKRSPoint3D`（`PickSafeAreaPoint1..4`，`:35-50`），由 `FrmAssistantPickArea` 分 4 步示教写入（`FrmAssistantPickArea.cs:212-232`），存 JSON（`:29` → `ZX2200PathConfig.MotionPlanDomainPath`）。
- **半径**（`:58-92`）：把「起点→取片点」的 XY 线段与安全区矩形求交（`GetIntersection`，`:209-256`，依次试 4 条边），半径 = 取片点到交点的 XY 距离；最后取 `Math.Min(半径, |Δz|)`（`:91`）。若安全区缺角抛异常；若取片点在矩形外抛异常。
- **加减速**（`:100-165`）：按两点 XY 距离分 11 档查表，只调 `Acc/Dec`（10000→15000 mm/s²）与 `Jerk`（0.1→0.02）；返回 `MovePara`（`AKRS.Galaxy2.Drive.MotionControllerDrive.MotionPara`）。**没有真正的速度曲线（S 曲线/梯形）生成**，只是常数分档。
- **路径**（`GetMoveLine`，`:265-326`）：返回 21 个点 —— 前 11 个是「起点 → 交点」的**直线等分**（`:307-310`），后 11 个是「交点 → 取片点」的**抛物线段**：`z = ratio * step²`（`:299-322`），其中 `ratio = distancePoint.Z / distance²`，即让 Z 与 XY 位移成二次关系，形成「抬升/下压」的弧形避让。这**不是圆弧插补**。
- **与 ETEL `DsaIpolGroup` 的关系**：**本模块内没有任何 ETEL / `DsaIpolGroup` / 插补调用**。`MotionPlanDomain` 只产出 `List<AKRSPoint3D>` 给调用方，由调用方决定怎么下发。
- **实际使用情况**：`GetMoveLine` 唯一调用方是实验代码 `Experiment/SpeedImprovementExperiment/FrmSpeedImprovementExperiment.cs:66`（硬编码坐标）；`GetRadius`、`GetMoveParaByDistance`、`PickSafeAreaPoint1..4` 在生产代码中**无任何调用方**（仅 `Experiment/TestFunction/FrmTest.cs:691-696` 手工赋值 + `Save()`）。

### 5.3 加热设置与温控

## 8. 注意事项与风险

### 8.1 确认的缺陷

1. **NaN 判断恒为假** —— `FrmSystem2FlatLevelMeasure.cs:194`
   `if (heightInMachine == double.NaN)` 永远不成立（`NaN == NaN` 为 `false`）。激光测高失败返回 `NaN` 时**不会**弹出「测高失败」，`NaN` 会被 `ConvertMachineToG0Pos` 与 `result.Add` 一路带进结果表。应改为 `double.IsNaN(heightInMachine)`。
2. **`NozzleshelfPara.NozzleName7` 的 setter 写错索引** —— `NozzleshelfPara.cs:132`
   `set { this.NozzleShelf.NozzleShelfSlots[0].NozzleName = value; }`，槽位 7 的写入落在槽位 1（正确应为 `[6]`）。通过参数树编辑槽位 7 会**悄悄覆盖槽位 1**。
3. **`FrmMachineDebug` 的时间节流分支永不触发** —— `FrmMachineDebug.cs:69`
   `(this.lastDateTime - DateTime.Now).Milliseconds > 100`，被减数在前、减数在后，得到负 `TimeSpan`，`.Milliseconds` 为负 → 条件恒假。日志刷屏只由 `allMessage.Length > 500` 兜底（`:69`），原设计的「100ms 一次」从未生效。
4. **`FlatLevelMeasureResult.GetMinMaxValue()` 把未示教的点位当成 0 参与比较** —— `FlatLevelMeasureResult.cs:70-78`
   固定构造 `{Height1..Height10}` 十个值。若只示教 3 个点，`min` 恒为 0 → `FrmLevelMeasureResult.cs:94-97` 的「最小值绿底」高亮**永远不会出现**（无单元格等于 0），工程师会误以为没有最小值。`Range` 由调用方另行计算（`FrmSystem2FlatLevelMeasure.cs:316`），不受影响。
5. **`FrmLevelMeasureResult.cs:92` 的排除列名是从焊头版本拷贝来的** —— `cellInfo.Column.FieldName != "MaxDifference"`，但平面度结果类的对应属性叫 `Range`（`FlatLevelMeasureResult.cs:64`）。结果是 `Range` 列也会进入「最大/最小着色」分支，`MaxDifference` 这个列名在平面度表里根本不存在。
6. **`FrmLogInfo.ControlRows` 的裁剪逻辑可疑** —— `FrmLogInfo.cs:138-149`
   `Array.Copy(lines, curLines, lines, 0, maxLine)` 把 `maxLine`(200) 个元素从 `curLines` 位置复制回数组头，但源数组从 `curLines` 起只剩 `maxLine` 个元素，语义上是「保留最后 200 行」的**自我覆盖**写法，边界依赖 `lines.Length > maxLine` 才安全；`FrmMachineDebug.cs:53-63` 是同一份代码的复制。建议改为 `Skip/ToArray`。
7. **参数树搜索的备用实现直接返回 `null`** —— `ParamCacheService.cs:58-61`
   `SearchParamByMatchName` 方法体是 `return default;`。其唯一消费者 `FrmParamManager.PastSearchMethod`（`:717-772`）是死方法（未被任何事件绑定），所以暂时不炸；一旦有人接上就会 `NullReferenceException`。

### 8.2 新旧参数系统并存 / 未接线

- `FrmParamManager` + `ParamService` + `UcBaseEditor` 系（约 2,300 行）**在本版本中功能不完整**：`[ParamInstanceAttribute]`、`[ParamInstanceSourceAttribute]`、`[ParamVisibleConfigAttribute]`、`[PositionParamBindingAxesAttribute]` 在**整个解决方案中零使用**（只在本目录的 4 个特性定义文件与 `ParamService` 的读取处出现）。因此 `cacheParamMappings` 恒为空，参数明细列表恒为空。`ParamService.ReloadAssembly()` 每次都要 `Assembly.GetExecutingAssembly().GetTypes()` 全量反射（`ParamService.cs:46`），在 `FrmParamManager_Load` 里以 `Task.Run` 承担（`FrmParamManager.cs:58`），选型上有性能代价。**维护前务必确认要改的是旧 UI（`UcProgramArgs`，实际在用）还是新 UI（`FrmParamManager`，半成品）。**

### 8.4 线程与 UI 风险

- **加热窗体每个 Timer tick 阻塞 UI 线程约 100ms**：`Timer_Tick`（`FrmHeatingSettings.cs:69-85`）依次调用 `GetHeaterTemperature()`（内部 `lock + Thread.Sleep(50)`，`BondSubSectionController.cs:895-903`）与 `IsHeaterOpen()`（同样 `Thread.Sleep(50)`，`:849-865`）。这是**串行两次 50ms 睡眠**，刷新期间界面卡顿。`BondSubSectionController` 的所有加热访问方法都有同样的 50ms 睡眠 + 静态 `obLock`（`:868-870` 定义），是跨模块的系统性问题。
- **`FrmLogRecord` 使用 `Thread.Abort()`**（`:48`、`:84`），在 .NET 上属已被否决的强制中止方式，可能造成资源/锁泄漏。
- **`UcProgramArgs.BtnSearch_Click` 在 `Invoke` 里操作 TreeList**（`:1800-1802`），但 `Search()`（`:1742`）与它都在 UI 线程上由 `EditValueChanged`/`Click` 触发，`Invoke` 属于无意义包装（写法混乱）。
- `FrmLogInfo` 的 Dataflow `ActionBlock` 在构造时订阅（`:34`）、**从不 `Unlink`/解除**；窗体若被反复创建会累积订阅者。当前它是死代码，风险暂不暴露。
- `UcRealTimeHeight.AddHeightData` 用同步 `Invoke`，若在生产节拍（逐颗固晶）调用，会把产线线程**同步阻塞**在一个「全量重建 200 点图表」的操作上。

### 8.5 数值/几何逻辑的可疑点

- **`MotionPlanDomain.FindIntersection` 只校验了交点的 X 是否在 X 区间内，没校验 Y**（`:195-198`）。两条线段在延长线上相交时，若 X 落在区间而 Y 不在，会返回一个**落在矩形外的伪交点**，进而让 `GetRadius` / `GetMoveLine` 用错误的交点算轨迹。
- **`GetMoveLine` 的抛物线段 Y 坐标取了负号**（`:322`）：`new AKRSPoint3D(x + intersection.X, -y + intersection.Y, -z + intersection.Z)`，而 `x/y` 由 `distancePoint.X/Y` 与 `cos/sin(theta)` 组合而来（`:314-316`），`theta` 又由同一个 `distancePoint` 求得（`:301）。这一段「先算模长比例、再乘 cos/sin」的写法把方向信息用了两次，`-y` 与 `-z` 的符号来由在代码与注释中**无法解释**，我判断这里很可能存在符号错误，但**无法在无现场数据的情况下确认**（见 8.6）。
- **`GetMoveParaByDistance` 的分档表**（`:108-162`）：`distance < 10` 与 `else` 给出**完全相同**的 `(10000, 0.1)` / `(15000, 0.02)`，`< 90` 与 `< 100` 也都是 0.02。档位是凭经验整定的魔数（12 组字面量），机型变更时必须整表重调。
- **`FrmBondLevel.Measure` 的 ±17mm 偏移是硬编码**（`:115-116, 128-129, 141-142`），代表焊头旋转中心到测高点的距离；换治具/换机型需同步改。
- **`FrmSystem2HeightTeach.cs:72` 提示语写死「高度置于测高点上方 3mm 处」**，而实际搜索距离参数在 `FrmSystem2FlatLevelMeasure.cs:172` 传的是 `10`（搜索距离）与 `2`（搜索速度）。文案与代码是两套数字。
- **`FrmHeatingSettings.SpHeaterTemperature_EditValueChanging` 的解析方式怪**：`e.NewValue.ToString().Replace(".", "")`（`:181`）把小数点去掉再 `int.TryParse`——输入 `20.5` 会变成 `205`，从而**误触发 >200 的拦截并关闭加热器**。
- **`FrmHeatingSettings.cs:83` 用 `(DateTime.Now - HeatingCompleteTime).Minutes`**（0-59 分量）而非 `TotalMinutes`；预热时间超过 60 分钟时显示会从 59 跳回。
- **`FrmHeatingSettings.cs:188` 用的是 `XtraMessageBox`**（DevExpress 原生），与同窗体其它分支的 `AKRSXtraMessageBox`（`:49, :61, :145, :158, :170`）不一致。

### 8.6 命名空间与目录不一致

- `HeatingSettings/FrmHeatingSettings.cs:19` 声明 `namespace AKRS.ZX2200.Infrastructure.HeatingSettings`，但物理位置在 `SupportFeature/HeatingSettings/`。
- `LevelMeasurementSystem/Models/FlatLevelMeasure/System2Related/System2FlatLevelMeasureSetting.cs:3` 声明 `namespace AKRS.ZX2200.LevelMeasurementSystem.Models.FlatLevelMeasure`（**少了 `SupportFeature`**），而同目录的 `System2FlatLevelMeasureRepository.cs:1` 用的是 `...SupportFeature.LevelMeasurementSystem.Models.FlatLevelMeasure`。其余窗体因此同时 `using` 两个前缀（如 `FrmSystem2FlatLevelMeasure.cs:12,14`；`FrmBondLevel.cs:11,17`）。由于 C# 会为 `A.B.C` 隐式建立父命名空间，`using AKRS.ZX2200.LevelMeasurementSystem.Models;` 能编译但为空——**极易误导后来者**。
