# 问题识别与查询路由

2026-10-30 起，开启“问题与经验”只表示允许使用对应工具，不再让每个问题都自动搜索问题库。主模型先结合当前问题和对话前文，判断是否与当前项目相关。

| 判断 | 路径 |
| --- | --- |
| 与当前项目无关 | 直接回答，不检索项目源码或问题与经验 |
| 项目故障处理、调参、历史办法 | 优先查询问题与经验 |
| 当前代码实现、执行流程、分支、程序参数定义 | 优先读取源码 |
| 同时询问工艺经验和软件实现 | 分别查询所需部分，按各自依据回答 |

2026-11-01，补齐“是否足够回答”的停止规则：结果已支持当前问题的主要答案时直接回答，不为凑齐来源补查。信息不足时，仅围绕影响答案的具体缺口查询其他可能有用的来源；可用来源仍无法支持的部分明确无法确认，不编造。资料不足不影响与项目无关的日常问题正常回答。

普通问题不再通过“设备词＋怎么/如何”或“方法”等关键词强制进入源码核查。主模型的本轮工具选择决定是否启用源码专项规则，查询源码后仍校验实际源码引用；选区、深度分析和继续既有源码核查的明确要求保留。重新生成时复用的历史已读片段不会单独触发强制源码检索。

经验已对当前正文完成复核、且答案只依赖经验时，程序可结束该回答，不因曾查询过未采用的源码而要求补充源码引用。该范围标记与正文摘要绑定，正文变化即失效；它表示已复核，不表示内容全部正确，也不能绕过真实源码链接的路径、范围和版本检查。混合回答的经验复核同时获得本轮源码上下文；经验试验结论对照选定经验，源码引用由程序独立核查。

这通常称为**意图识别**或**查询路由**，当前提示词只判断与项目相关或无关。没有增加固定关键词白名单，也没有在每个问题之前额外调用一次分类模型。主模型第一次响应可以直接给答案，也可以提出工具调用；检索、记录加载和核查只在需要时发生。较长回复的续写和长对话压缩仍可能增加模型调用。

## 运行与来源

“问题与经验”关闭时不提供对应查询工具；开启时只装配工具定义，问题库快照延迟到第一次查询或引用核对时建立。同轮后续调用共享该快照，避免检索、读取和核查混用不同版本。并行工具调用只建立一份快照。

检索得到候选后，先在工具内部单独调用模型，按当前问题的设备、日期、阶段和事项选择相关原文片段。筛选只返回记录与片段编号，程序从同轮固定版本取回原文；候选正文和未选中的标题、引用不会进入回答模型的工具结果。无候选时不调用筛选模型；同轮重复读取已经筛选过的版本复用结果，并行调用共用缓存。

搜索和按编号读取都经过这个边界；追问复用前文引用也先核对编号、版本并筛选，无须重复相似度搜索。筛选失败、超时、协议无效或输入超限时不回退候选原文，明确说明处理未完成。有效筛选的空结果则只说明本轮没有选中适用内容，不能据此宣称全库没有记录，也不允许用通用知识补造历史结果。普通问题被判为不依赖历史记录时仍可正常回答。

回答模型根据选定内容生成答案，最后保留独立事实核查，不重复做相关性筛选。核查使用已经选定的片段，以及这些选中记录的完整正文，检查数值、日期、条件、结果和引用；完整正文仅供核查模型使用，避免把片段遗漏误说成原记录没有。筛选判断“哪些资料有用”，事实核查判断“回答是否忠实于资料”；例如资料中的42被回答误写成43，前面的筛选无法检查尚未生成的错误。

2026-11-02起，事实复核改为只读：通过时原答不变、不添加文字；有具体问题时最多补一句简短说明，原有正文、表格、代码和图表不改写。补句放在正文末尾、来源之前，来源仍由前端集中展示在最后。模型只返回`verdict`和`note`，即使额外返回替换答案也不会采用。一次有效核查结束，不再生成修订稿、终审稿或摘录降级；协议无效仍沿用最多一次JSON重试。超时、失败或无法完成核查只记入运行详情，不追加泛泛提醒。

源码引用保留路径、行号、版本和源码目录检查；发现能定位的具体引用问题时，按同一规则补一句说明，不自动补查、改稿或删除原引用。缺少可定位引用仅记入运行结果，不重现固定核对尾注。当前源码聊天仍未开启额外的模型结论复核。混合回答优先展示事实问题，其次引用问题，最多一句，详细检查结果留在运行档案。验收见[只读核查](../verification/readonly-review-20261102.md)。

经验匹配状态和缺项只供内部判断，不要求用户逐项核对设备、版本、模块和工况，也不在答案末尾追加泛泛的历史经验或现场验证提醒。生成阶段只保留会改变处理办法、参数或适用范围的具体条件，紧邻对应内容且只说一次；如参数单位未知或存在明确条件冲突，须说明具体影响。复核不重复已说明的条件。匹配筛选仍保留冲突原因，不将条件不符的记录当作当前可直接套用的方案。

经验专用规则在启用该来源时进入系统提示一次，搜索和按编号分页读取不再重复返回整段 `display_hint`。通用回答表达与来源位置由主提示负责；经验提示仅保留匹配字段、历史状态、原图及引用协议规则。事实复核是独立模型调用，仍保留其核查职责，不额外增加整理或删提醒的模型调用。

“上下文”和运行档案只为本轮筛选后实际提供的记录登记来源，检索候选和未选中记录不冒充已带入。旧运行的自动带入快照继续按原档案显示；没有重写历史对话或历史工具结果。

账号全局 `agent.md`、当前对话历史和长期记忆沿用各自设置；本次没有改变记忆生成、账号权限、项目隔离或已有记录。普通问题仍可使用账号的回答偏好。

模型可能误判是否需要工具。工具权限、上下文预算、源码证据和经验事实核查继续保留；路由选择不是事实验证。实际验收见[查询路由验证](../verification/query-routing-20261030.md)。

2026-10-30补齐连续追问语境：记忆与经验筛选，以及最终经验事实核查，共用当前有效分支在本题之前的有限近期对话、项目名称和选区路径。背景最多12条消息、6000字符，每条最多1200字符并标记截断；不复制整块选区，不带入其他聊天或重新生成位置之后的消息。记忆本地召回也补入近期对象线索，筛选仍以当前明确问题和最新更正为准，切换话题不沿用旧对象。不增加独立的问题改写模型调用。运行过程见[回答依据与耗时](run-evidence-trace.md)。
