# 当前对话历史与摘要筛选

2026-10-30起，主模型回答前先为较早历史生成本轮上下文视图；原始消息、工具档案和保存的摘要不被筛选结果覆盖。原生历史压缩继续负责上下文容量，筛选在压缩后的有效历史上执行，全局agent.md随后独立带入。

## 保留与筛选

| 内容 | 处理 |
| --- | --- |
| 有效历史中的近期六轮，含本轮问题 | 保留原消息及本轮工具调用、返回；长对话先受原生上下文压缩与总预算约束 |
| 较早用户消息 | 区分持续要求与普通旧问题；持续约束、禁止项、偏好、未完成目标、纠正及取消/替代状态必须选入，已结束且无关的旧问题可不带入 |
| 系统消息 | 保留原文 |
| 摘要中的目标、用户要求与约束、待办、待确认项 | 保留原文，不让相关性判断删掉未完成目标或冲突 |
| 较早助手回复和工具资料 | 由AI筛选，完整工具链作为一组选择；选中回复时自动带回对应用户问题，避免丢失条件 |
| 结构化摘要的已确认结论、源码依据 | 按原文行选择与当前问题有关的内容，程序组装原文及出处 |
| 自由格式或未知结构的纠正摘要 | 保守保留，避免误删无法可靠分离的用户约束 |

筛选器结合当前问题、近期对话、受保护的摘要约束及候选原问题，理解“它、这个方案、继续”等指代；除与本题相关的事实，还选择维持任务连续性必需的持续要求、未完成目标、最新纠正、冲突及完成/取消/替代状态，防止旧目标被重新当作待办。回答仍须以当前明确要求为准，不能仅因旧用户消息还在上下文就重新执行旧请求。

模型只返回候选编号，不改写事实、目标、引用或完成状态。用户要求可独立保留，不强行附带同轮无关旧回复。选中旧回复时程序补入其原问题，两类选择取并集且只带入一次。程序校验字段、编号和类型，不接收候选以外的内容。持续要求的识别由模型承担，仍可能漏选；原消息、摘要与回查工具保留。

## 调用与失败

短对话、没有较早候选、摘要事实段只有“无”时不额外调用筛选模型。同一轮后续工具请求复用相同旧历史的筛选结果；历史或摘要被纠正后重新筛选，不跨运行或账号共享缓存。输入按预算分批，任何一批失败都不会把部分选择当作完整结果发送给回答模型。

协议错误允许一次结构修复；供应商失败、超时或预算不足会明确返回可重试错误，原始消息和摘要保留，不回退未筛选的旧事实。用户取消不会被转成普通筛选失败。

`recall_conversation`、`read_conversation_message`继续读取当前聊天原始消息和选区。遗漏内容可以按需回查；没有带入不代表原文没有，也不代表所有工作已完成。

运行中记录`history_selection`计数及实际模型用量，不向聊天正文输出筛选JSON。上下文预算使用筛选后最后实际请求的估算，不用完整检查点档案重新覆盖这个值。上下文页面保留完整摘要用于查看、纠正，摘要展示内容不等于本轮回答模型实际收到的全部内容。

相关实现位于`agents/context/history_plan.py`和`history_selection.py`。检索来源的前置筛选及最终事实核查继续沿用[查询路由](query-routing.md)，本功能不改变来源开关、全局指令、账号权限或长期记忆生成。实际验证见[验收记录](../verification/history-context-selection-20261030.md)。
