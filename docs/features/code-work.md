# 代码工作：隔离修改与验证

2026-10-29 按用户要求移除项目首页的“代码工作”入口，项目首页直接展示对话列表。已有隔离修改、验证档案及聊天中的代码修改能力保留。下文中“代码工作页”的手动操作描述对应移除入口前的页面；当前项目首页不再提供这些操作。

隔离修改和命令验证的运行日志不计入交接工作台的任务统计。

## 设备业务问答的源码优先顺序

当前项目关联 ZX2200 源码时，设备业务问题先在 `trunk/AKRS.ZX2200/` 查找业务入口、操作界面、任务流程和前置条件，再沿已核对的调用关系读取其他工程。工具路径相对于当前源码根；根目录是 `trunk/` 时使用 `AKRS.ZX2200/...`，根目录已是主工程时直接从根检索。用户指定文件或附带选区先核对，未找到相关实现时说明已查范围后再扩展检索。

例如“我想做设备标定，输出标定流程”，应先定位主工程中的标定业务，再追查其调用的坐标转换、视觉或补偿实现。标定、校准、固晶、点胶、晶圆、取片、回零等业务问法已纳入源码证据核查，不需要用户额外写“源码”或文件名；未读取当前源码或缺少定位引用时，会触发补核对，仍未满足则提示缺少依据。

该优先顺序由系统提示指导模型执行，不是阻止读取其他工程的权限限制，也不代表真实模型每次都遵循了顺序。规则仅适用于当前项目的关联源码，其他项目不套用 ZX2200 路径；真实模型输出质量和设备流程仍需另外验收。

实现与回归范围见[主工程优先规则验收](../verification/device-source-priority.md)。

## 隔离修改

用户明确要求实现或修复时，聊天 Agent 可创建隔离修改；也可在代码工作页手动创建、编辑并查看差异。原业务源码保持只读。

副本位于应用数据目录的 `scratch/code-changes/`，按项目和修改身份隔离。系统保存基线、工作副本、文件版本和验证档案，修改前检查文件哈希及唯一旧内容上下文。原件变化时报告冲突。界面可下载补丁或显式丢弃副本；不会自动把补丁合并到原件。

当前使用受约束副本，无需业务源码本身有 Git。复制排除生成目录并限制为1 GB、30000个文件；有附加源码根的项目暂不支持隔离修改，需使用仅关联主目录的项目。路径越界、链接和系统保留名称被拒绝。创建时可记录验收标准、约束和相对 glob 修改范围；越界编辑及验证产生的范围外修改不能交付。副本本身仅隔离文件；进程权限由下面的执行环境决定。

## 验证与修复

管理员在“系统配置 → 项目验证命令”选择项目，显式配置验证名称、JSON格式的命令参数数组和超时。普通用户在项目的代码工作页选择执行。模型只能选择已配置的命令，不能自行创建任意命令。初始没有命令，也不会自动启动设备程序。

新建配置默认隔离容器，必须指定固定 sha256 镜像身份，管理员可手动探测节点与镜像。Linux 执行通道不挂载宿主目录、凭据或 Docker socket，固定关闭网络、只读根文件系统、限制 CPU/内存/进程数和工作空间，目标命令以非 root 身份执行。只使用本项目准备的可信协议镜像，不执行业务仓库的 Dockerfile，不自动拉取依赖或回退宿主运行。回传逐项验证普通文件和路径，再交换工作副本。

管理员仍可显式选择“可信宿主（非沙箱）”执行受信任命令；迁移前的旧配置也明确保留为非沙箱。该方式使用服务进程权限，不应用于不可信代码。默认资源策略不允许它作为沙箱交付依据。

命令使用参数数组，不拼接 shell 字符串。系统保存日志、退出码、超时、取消及中断状态，单次日志到达项目上限时终止，界面另限制展示长度。修改后旧的通过状态失效；验证记录绑定对应源码、修改版本、配置版本和实际执行镜像证明。

管理员可要求先运行原版本基线。基线在一次性副本运行，不能改不可变快照，也不会把工作副本标为通过。当前版本验证通过且满足验收标准、范围、有效基线和执行策略后，用户才可审核此版本并下载 ZIP 交付包。包内有可应用/反向应用的补丁、固定版本、基线和验证结果、审核身份与操作说明。新编辑或配置变化令旧审核失效。原草稿补丁导出仍保留。

进程结束、超时或取消时清理所属进程组；Windows 使用 Job Object 管理后代进程，服务意外退出时也不会让后台子进程继续运行。聊天默认文件工具按对话隔离，不能从共享临时目录读取其他项目的副本。

上述 Windows Job Object 仅用于显式可信宿主命令，不能当作操作系统安全沙箱。Windows容器协议3适配已接入独立节点、Hyper-V隔离、受信32位退出码桥和停止态传输，尚未在真实Windows容器节点验收。ZX2200仍需要Windows节点、目标SDK及私有依赖并完成实际构建；不能把Linux容器通过算作ZX2200构建通过。见[Windows适配边界](../architecture/windows-executor.md)。

旧副本可在详情的“编辑需求约定”补齐验收标准、约束和路径。保存绑定当前源码与需求两个版本；改变需求后需重新验证和审核，旧窗口不能覆盖新约定或审核未展示过的需求。编辑副本文件也同时核对读取时的文件与需求版本。

原始用户要求由服务端单独保留，后续修订只追加记录。聊天中“修复代码”不授权模型更改验收或扩大范围；明确要求修订验收、约束或路径时，只允许改变对应字段。仅修订约定也不会开放文件写入或命令执行。模型填写的初始约定属于草稿，仍需对照原始要求核对；旧副本缺少原始要求时保持未知。实际边界与测试见[需求绑定与修订授权](../verification/request-binding.md)。

同一用户消息重试创建或中断恢复时沿用已有副本，不按重复创建参数重置约定、文件或验证；已丢弃副本需要新的用户修改请求。新问题和页面人工创建保持独立。见[创建重试验收](../verification/change-creation-retry.md)。

聊天工具把失败结果回传给现有 Agent，允许根据错误继续修改和重新验证；每轮最多3次验证、20次代码工作调用。源码检索有独立额度，检索耗尽后仍可完成已经授权的副本验证。停止时明确报告剩余未核查内容和未完成修改。

环境未安装、依赖缺失、编译失败、测试失败和未执行需要根据真实日志说明，不能统一推断为代码缺陷。测试通过只代表配置命令在该版本上通过；设备动作、联锁、工艺效果和现场回归仍需实际验收。

## 经验回流

当前修改验证通过且版本有效时，可以显式“记录调试经验”。用户填写问题、条件、原因、措施及实际验证结果，系统关联项目、修改版本、验证ID，写入现有版本化调试问题库。重复提交同一验证只产生一条记录。后续新对话可检索固定版本，并核对设备、软件版本和工况。

不会从失败日志或模型猜测自动生成已解决事实；命令通过也不会自动将问题标为已解决。原问题库的归档、修订和适用性规则继续生效。

## 实现位置

- `backend/app/modules/source_analysis/reading/models.py`：仅供旧数据库与备份兼容的历史表结构。
- `backend/app/modules/code_changes/`：副本、编辑、补丁、命令配置及执行档案。
- `backend/app/agents/tools/engineering.py`：Agent工具及有界修复。
- `backend/app/modules/projects/code_experiences.py`：用户提交的调试经验关联。
- `frontend/src/features/projects/`：项目内的代码工作页。

隔离修改接口沿用项目分派 `/api/p/{project_id}/code-changes`，认证、CSRF与项目归属由既有边界保护。独立对话不开放项目修改入口。迁移0020保留旧档案，增加需求/审核、执行配置与项目资源策略、按 UTC 日预留/结算记录。

验证运行时不能改绑、归档或删除项目。备份沿用现有数据库与 `scratch` 归档机制，运行中的验证须先停止，避免数据库和副本版本不一致。旧阅读任务的历史状态不再阻挡备份和项目管理。

## 构建前置、隐私与资源

代码工作页只读检查 `.sln`、项目声明、框架、配置、包和直接依赖；不求值 MSBuild 条件、不加载 targets、不读取根目录外文件。扫描结果中的 `buildable` 始终为未知，须实际跑基线才能判断构建结果。当前 ZX2200 扫描为16个传统4.8工程、2个解决方案，存在7处根外及1处缺失依赖声明；静态缺项不等于功能缺陷。

项目管理员可设置临时空间、最低剩余磁盘、单次日志、并发验证、保留期及每日模型 token 额度。聊天、源码复核和项目调试录入共享项目 UTC 日额度；调用前按输入估计、工具和输出上限预留，供应商实报后结算，未知或取消的用量保守保留。该额度不等于供应商账单或价格上限。独立对话不计入某个项目。

清理先预览，实际操作只删除到期已丢弃或已交付的临时文件。运行中、未交付和交付后再被修改的副本保留，审核和验证档案继续可读。保留期不会自动删除工作。

出站模型上下文隐藏常见密钥、密码、Bearer 和私钥，尽量保持源码行号；原消息、资料和源码保持原值。脱敏也覆盖摘要、工具参数、独立源码/记忆复核与调试录入，仍不能保证识别所有商业秘密。使用外部模型前需按公司要求选择允许接收源码的供应商；不要把脱敏当作资料可以任意外发的证明。

公司 Linux 部署与 Windows 构建的准备清单见 [执行环境说明](execution-readiness.md)。真实模型理解/生成质量、全仓通读和设备验收仍需另外执行，不能由自动化工具链测试替代。
