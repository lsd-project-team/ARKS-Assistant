# 独立代码副本、验证与合并

更新日期：2026-11-05。

聊天在每个对话的独立 ZX2200 工程副本中修改业务 C#。编译、需求断言和原桌面界面流程都使用副本新生成的 Simulation 程序；写回原工程另经三方预览、候选重验和管理员确认。开发验收始终只读用户原 trunk，合并试验只写隔离测试工程。

## 入口和工程位置

管理员在“系统配置 → 代码修改 → 编译与仿真环境”设置可信的原工程 trunk 和本机 MSBuild。普通用户点击聊天输入框的“代码修改”，或发送 `/修改代码 具体需求`。已有对话可以先创建副本；新对话由 Agent 准备。

“工程位置与来源版本”显示原工程、副本绝对路径和来源指纹，支持复制路径、本机打开目录。副本实际位于 `data/scratch/cw/<对话哈希>/source`，文件夹不是对话 UUID。新副本保存来源路径，更换全局配置不会替换已有副本。旧副本未记录路径时会显示提示，合并前须核对目标。

普通用户在此查看、修改、验证副本和生成合并预览。管理员从“AI 问答记录 → 对话详情 → 代码副本与合并”进入同一面板，审查并确认写回；后台入口不发送聊天请求。

## 差异与历史

回答正文下方、反馈等操作按钮上方显示实际修改摘要。新回复默认展示本轮实际编辑的快照，可以切换“全部待合入”；旧回复版本只展示其自身记录。旧版没有逐轮记录的修改继续支持累计差异，不伪造历史。

“改动”支持带行号、C# 高亮的统一差异和左右对照。文件或修改块撤销均基于当前版本并要求确认。选中同一侧的行号范围，或点击“反馈此处”，可将路径、版本、轮次、行范围及代码带入聊天草稿，已有草稿保留；实际修改前仍须重读当前代码。

“历史”保存逐轮前后内容，不随后续编辑、合入或回退变化，并可读取每次验证的日志、断言和截图。快照只读，不能通过历史视图撤销当前代码。

## 验证

固定流程依次编译和运行虚拟驱动检查、以 `Configuration=Simulation` 编译修改后的主工程、运行原程序 `--simulation-self-test`。当前真实工程是16项驱动检查和69项原工程集成检查。构建与报告来自本次新目录，编译失败不运行旧输出。

“验证”可保存具体需求的 C# 方法体，使用原业务对象和虚拟硬件，必须实际执行 `Check(条件, 说明)`。Agent 修改本轮代码后需配置需求断言；同一轮首次验证后固定测试和桌面范围，最多三次验证，根据真实失败日志修复业务代码。停止后本轮不自动重新启动。测试是否充分仍须审查，调用次数和业务状态等具体反例比单纯 `Check(true, ...)` 有意义。

副本准备、读取、修改和验证独立于来源检索额度，来源查询结束仍可继续工作流；同一缓存范围连续反复读取且无新内容时会退出重复检索。需求方法体保存前检查C#语法及CountCalls常见误用，错误会反馈修改，尚不会冻结测试。宿主提供点胶Models/Modules/Controllers类型上下文；计数函数返回本次Action中的实际调用次数，必须接收结果且执行待测操作。反例与修复使用同一预期断言，原版实际多调用时应由该断言失败，不能同时要求修复后仍满足旧行为。

新副本默认启用原桌面流程：加载原 MainForm、复位、启动、暂停、继续、示例生产、停止。独立 STA 进程执行原按钮事件和回调，检查虚拟轴复位、实际运行状态、点胶/贴装产出及停止后的任务状态，共7步、14项断言。每步保存真实截图，空白截图视为失败。窗口在屏幕外运行，避免抢占当前桌面；面板提供缩略图、原图及报告。

验证结果绑定副本修订、代码指纹、启用的测试和验证宿主版本。改代码、改用例或更新宿主后，旧通过结果不能作为当前版本通过。报告和图片保存哈希，读取时核对。每个副本保留最近两次大型构建输出，历史报告和截图独立保存。

## 合并回原工程

1. 在“合并”选择待合入文件，点击“生成合并预览”。系统比较创建副本时的基线、原工程当前内容和副本修改；保留非重叠编辑，重叠内容必须处理。
2. 冲突文件可以保留原工程、采用副本或手动编辑结果，然后重新预览。未选择文件若存在同步冲突，需纳入本次处理。
3. 点击“验证合并结果”。候选是独立工程，按相同测试和桌面流程重新编译验证；副本此前通过不能替代候选验证。
4. 管理员核对原工程绝对路径和文件，勾选确认后点击“确认应用到原工程”。后端再次核对原工程、副本及候选版本，有变化即拒绝旧预览。聊天工具没有写回入口。
5. 系统先保存恢复材料，再写所选业务源码；新增 C# 同时补入经典项目 Compile 项。成功后更新副本基线，未选择修改继续保留为待合入，需重新验证。

合入记录支持回退最近一次未回退的操作。原工程文件已被人工继续修改时拒绝覆盖回退；副本编辑保持待合入，不以回退删除编辑成果。

写回中断或服务重启时按持久化日志恢复。如果某个原文件已有后续人工修改，保留该文件、恢复其他安全文件与副本，在面板显示恢复冲突并阻止后续修改。管理员查看差异，按所查看的精确版本确认保留当前原文件后，才能重新预览；结束恢复本身不改写原文件。

## 范围和数据

可编辑主工程业务 C#；入口 Program.cs、Properties、Simulation 驱动及任意工程配置不向聊天开放。新增文件在验证时通过固定导入项编译，合并时才补充项目编译项。当前复用已有依赖 DLL 和离线 NuGet 缓存，尚非全解决方案重建。

仿真覆盖软件状态和示例业务流程，不代表真实视觉、测高、力控、运动精度、连续插补、标定或设备安全验收，也未覆盖每个界面按钮的所有分支。本机以 Windows 用户权限运行，属于工程副本隔离，不提供操作系统安全沙箱；不使用 Docker，Linux 不能直接运行此 .NET Framework 4.8/WinForms 流程。

创建上限4GB/30000文件，至少5GB可用空间；验证至少1GB。对话移入回收站保留副本，永久删除时清理其所属目录。全量备份保存 C#、基线、逐轮内容、验证报告/截图、合并记录及恢复材料，排除大型依赖、候选源码和编译输出。恢复后需配置同版本来源重新准备依赖，指纹不符拒绝重建并保留修改；同版本来源迁移成功后更新固定路径并清除旧当前验证。

本机路径和编译器配置在 `code-work.local.json`，不随备份迁移。其他账号不能通过已知项目、对话或报告标识越权，管理员保留既有审查权限；验证和备份互斥。

## 实现和验收

实现位于 `backend/app/modules/code_work/`、`agents/tools/code_work.py`、`agents/runtime/code_work_repair.py` 和前端 `features/chat/code_work/`。对话 API 在 `/api/p/{project}/threads/{thread}/code-work`，涵盖状态/文件/摘要/差异/撤销、需求/桌面配置、验证/停止/报告、合并预览/验证/应用/回退及恢复确认。全局环境接口仍为 `/api/settings/code-work`。
