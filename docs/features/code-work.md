# 项目阅读与代码工作

“项目 → 代码工作”集中提供项目阅读、隔离修改和命令验证。交接工作台的任务统计不接收这些运行日志。

## 项目阅读

创建任务时建立逐文件快照，记录源码版本、排除项和无法读取的项目。启动后按分块实际读取并调用已配置模型，保存职责摘要、入口、依赖、未知事项和实际读取范围。阅读会调用模型并消耗对应供应商额度。

聊天中须明确要求通读、开始或继续阅读，才会启动任务。询问功能原理、用法、费用或能否满足需求，只进行说明，不触发阅读调用。

- 已索引表示建立文件清单；已读取表示读到了文件正文；已分析表示模型完成对应片段的结构化分析；已复核表示用户评审了当前成果。这些状态都不等于设备验证，也不能保证 AI 完全理解所有业务。
- 每次启动默认分析最多64块，可暂停、继续；每块独立保存。模型失败、预算耗尽或服务重启后保留已经完成的进度，不把未完成内容标为完成。
- 刷新比较源码版本，只重新处理变化文件和已识别的关联依赖。问答读取成果前也核对当前版本；过期成果不进入当前知识上下文。
- 附加源码目录使用已有稳定路径前缀。被排除的生成目录、二进制或不支持文件有记录，不计入已理解。
- 成果是辅助资料。分析具体问题或新需求时仍需读取当前源码，结合 Roslyn 调用关系和历史调试问题核对证据。

模型可能遗漏业务语义和依赖。没有源码的外部组件、设备实际状态和未说明的工艺规则仍是未知；评审需要结合实际项目。

## 隔离修改

用户明确要求实现或修复时，聊天 Agent 可创建隔离修改；也可在代码工作页手动创建、编辑并查看差异。原业务源码保持只读。

副本位于应用数据目录的 `scratch/code-changes/`，按项目和修改身份隔离。系统保存基线、工作副本、文件版本和验证档案，修改前检查文件哈希及唯一旧内容上下文。原件变化时报告冲突。界面可下载补丁或显式丢弃副本；不会自动把补丁合并到原件。

当前使用受约束副本，无需业务源码本身有 Git。复制排除生成目录并限制为1 GB、30000个文件；有附加源码根的项目暂不支持隔离修改，需使用仅关联主目录的项目。路径越界、链接和系统保留名称被拒绝。副本只是文件隔离，不是操作系统进程沙箱。

## 验证与修复

管理员在“系统配置 → 项目验证命令”选择项目，显式配置验证名称、JSON格式的命令参数数组和超时。普通用户在项目的代码工作页选择执行。模型只能选择已配置的命令，不能自行创建任意命令。初始没有命令，也不会自动启动设备程序。

命令以副本为工作目录直接执行，不拼接 shell 字符串。系统保存完整日志、退出码、超时、取消及中断状态，界面展示限定长度输出并提供完整日志下载。修改后旧的通过状态失效；验证记录绑定对应修改版本。

进程结束、超时或取消时清理所属进程组；Windows 使用 Job Object 管理后代进程，服务意外退出时也不会让后台子进程继续运行。聊天默认文件工具按对话隔离，不能从共享临时目录读取其他项目的副本。

聊天工具把失败结果回传给现有 Agent，允许根据错误继续修改和重新验证；每轮最多3次验证、20次代码工作调用。源码检索有独立额度，检索耗尽后仍可完成已经授权的副本验证。停止时明确报告剩余未核查内容和未完成修改。

环境未安装、依赖缺失、编译失败、测试失败和未执行需要根据真实日志说明，不能统一推断为代码缺陷。测试通过只代表配置命令在该版本上通过；设备动作、联锁、工艺效果和现场回归仍需实际验收。

## 经验回流

当前修改验证通过且版本有效时，可以显式“记录调试经验”。用户填写问题、条件、原因、措施及实际验证结果，系统关联项目、修改版本、验证ID，写入现有版本化调试问题库。重复提交同一验证只产生一条记录。后续新对话可检索固定版本，并核对设备、软件版本和工况。

不会从失败日志或模型猜测自动生成已解决事实；命令通过也不会自动将问题标为已解决。原问题库的归档、修订和适用性规则继续生效。

## 实现位置

- `backend/app/modules/source_analysis/reading/`：阅读快照、断点、成果和新鲜度。
- `backend/app/modules/code_changes/`：副本、编辑、补丁、命令配置及执行档案。
- `backend/app/agents/runtime/project_analyzer.py`：阅读模型适配。
- `backend/app/agents/tools/engineering.py`：Agent工具及有界修复。
- `backend/app/modules/projects/code_experiences.py`：用户提交的调试经验关联。
- `frontend/src/features/projects/`：项目内的代码工作页。

接口沿用项目分派 `/api/p/{project_id}/project-reading` 和 `/api/p/{project_id}/code-changes`，认证、CSRF与项目归属由既有边界保护。独立对话不开放项目修改入口。数据库迁移0019只新增六张档案表，保留现有对话、资料、账号和调试记录。

阅读或验证运行时不能改绑、归档或删除项目。备份沿用现有数据库与 `scratch` 归档机制，运行中的阅读或验证须先停止，避免数据库和副本版本不一致。
