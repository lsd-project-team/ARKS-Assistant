# 独立代码副本与 Simulation 验证

更新日期：2026-11-04。

第一版支持在聊天的独立副本中修改 ZX2200 主工程业务 C#，随后编译该副本并运行原工程已有的虚拟驱动与 Simulation 自检。原源码目录及已经运行的桌面程序不写入、不替换。2026-10-29 移除的旧需求约定、预设命令、审核交付及旧档案接口继续停用。

## 使用

1. 管理员在“系统配置 → 代码修改 → 编译与仿真环境”设置包含 `AKRS.ZX2200` 的原工程 trunk，以及本机 `MSBuild.exe`。必须使用带 `OFFLINE_SIMULATION` 实现的版本。
2. 普通用户点击聊天输入框的“代码修改”图标，或发送 `/修改代码 具体需求`。已有对话可先创建副本；新对话发送需求后由 Agent 准备副本。
3. Agent 先读取副本及文件版本，再修改业务代码，调用固定编译和自检流程。面板展示文件清单、增删差异、验证版本、检查数和日志。
4. 修改后重新验证；旧版本通过不会展示为当前代码通过。单个文件可以确认撤销，也可下载包含修改文件、统一差异与验证状态的 ZIP。

每个对话固定一份来源快照。管理员更换来源目录不会替换已经存在的副本；需要使用新来源时新建对话。聊天没有任意 Shell 命令或写回原源码工具。业务文件可新增，但入口 `Program.cs`、Properties、Simulation 驱动和工程配置不可编辑。新 C# 文件由固定的构建导入项纳入本次编译，原项目文件不改。

聊天底部自动显示当前副本的修改摘要，包括文件数、总计和逐文件增删行数。默认展示前3个文件，可以展开全部；点击文件或“查看变更”进入差异详情，点击文件会直接定位。行数与详情使用同一份真实差异，撤销后更新、刷新后恢复。卡片表示当前副本累计修改，不是某条历史回复的独立修改快照，也不表示已通过验证。

## 验证含义

依次编译虚拟驱动检查、运行驱动检查、以 `Configuration=Simulation` 编译修改后的主工程、运行新生成程序的 `--simulation-self-test`。构建和报告必须来自本次新目录；退出码非零、缺少 PASS 报告、超时或停止均不能判为通过。编译失败后不运行旧程序。

本机已用真实模型完成业务方法修改，并实际通过16项驱动检查和69项原工程集成检查。检查涉及示例配置、原控制器动作、暂停/继续/停止及两片示例载具的生产流程。依赖项目复用已有 DLL 和本机离线 NuGet 缓存，尚非全解决方案重新构建。

现有检查是基础回归，每项新需求仍需对应的验证。模型可能选错同名方法，必须核对实际差异与修改范围；编译和基础自检通过不代表符合全部需求。真实视觉、测高数值、力控、运动精度、连续插补、标定及设备安全未由这组检查验收。原界面能够启动也不等于按钮的所有业务分支均已覆盖。

副本在本机 Windows 用户权限下执行，属于源码副本隔离，**不提供操作系统安全沙箱**。管理员应选择可信的原工程和依赖。当前不使用 Docker；Linux 服务器不能直接执行此 .NET Framework 4.8/WinForms 仿真流程。

## 版本、停止与数据

- 文件编辑和撤销使用文件哈希避免覆盖较新修改；每次实际保存增加副本修订号。正在验证的副本禁止继续编辑。
- 同一服务串行执行验证，可排队、停止；超时和取消终止本次持有的进程树。重启后的未完成任务标记为未完成，不根据旧 PID 操作进程。
- 副本位于 `data/scratch/cw/<对话哈希>/`，创建上限4GB/30000文件，至少需要5GB可用空间；验证至少需要1GB空间。每个对话保留本次和上次构建输出。移入回收站保留修改，永久删除对话时清理所属副本。
- 全量备份保留来源指纹、C#、修改基线和状态，排除可重新生成的大型依赖及编译输出。恢复后先配置同版本原源码和依赖，验证时重新准备；指纹不一致时保留修改并拒绝重建。此时仍可查看、撤销及下载已保存修改，旧通过状态不作为可用验证。
- 编译器路径和本机源码路径保存在 `code-work.local.json`，不包含模型密钥，也不随全量备份迁移。验证中的独立任务和备份互斥。

## 实现与接口

`backend/app/modules/code_work/` 负责副本、编码、环境、固定执行及对话权限；`agents/tools/code_work.py` 将工具绑定到当前对话。前端面板位于 `features/chat/code_work/`，环境配置也接入管理员系统配置页。

全局管理员接口为 `GET/PUT /api/settings/code-work`。对话接口均位于 `/api/p/{project}/threads/{thread}/code-work`，包含创建/状态、`summary`、`file`、`diff`、`revert`、`verify`、`cancel`、`export`。`summary` 仅返回当前累计修改的文件与行数，不触发副本创建或编译。下载请求带修订号，其他账号不能通过已知项目或对话 ID 读取、修改或执行。

真实模型脚本、回归与实际页面结果见[第一版验收](../verification/code-work-v1-20261104.md)，摘要展示见[代码修改摘要卡片](../verification/code-change-summary-20261104.md)。旧流程的历史状态见[移除记录](../verification/remove-legacy-code-work-20261029.md)。
