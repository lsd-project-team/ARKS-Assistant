# AI 自主回答格式

2026-10-30 起，对话、源码检索、引用核对与回答展示沿用现有基础链路，回答格式由 AI 根据问题和用户要求决定。

## 回答与展示

- 普通 Markdown 和现有 `rich-content` 结构化组件均可使用，不按“流程”“步骤”等词强制转换为卡片，不设置主阅读区字数上限。
- 后端不再自动拆段、去掉长加粗、把参数组合转换成列表，也不额外调用模型压缩或重组流程稿。
- 前端解析并渲染模型选择的格式，保留正文、强调、来源段落和引用标签，不合并来源段落或删除展示文字。字体、间距、代码高亮及组件交互仍由前端控制。
- 用户要求纯 Markdown、原文或保留格式时，模型遵从对应要求。

## 检索与核对

主模型结合当前问题和对话选择是否调用源码工具。搜索定位与实际读取分开记录，读取的文件、行号、版本形成证据；源码保持只读。

引用覆盖、版本核对、源码结论语义复核及必要的事实纠正继续执行。源码证据相关回答在核对结束后发布最终正文，普通聊天继续流式显示。校验失败时保留核对提示和原有引用停用机制。

新增 `answer_format_validation` 事件，验证模型选择的结构化协议，包括未知类型、版本、非法字段和未闭合围栏。格式校验不触发排版改稿，也不改写正文；前端沿用原文降级展示。供事实核查使用的 Markdown 投影不作为排版结果发布。

输出截断后的续写、引用规范化及事实错误修正继续保留，它们用于恢复完整回答和核对证据，不用于统一回答风格。

## 数据与范围

本次不修改数据库结构，不清空或迁移正式账号、对话、资料、问题与经验及长期记忆，不修改 `trunk/`。问题与经验和长期记忆沿用现有来源开关，本阶段不重做其检索机制。

旧回答正文和运行档案保持原样；前端统一按保存的内容渲染，因此历史引用标签中的版本和原有独立来源段落可以重新显示。

真实模型验收只向当前已配置供应商发送合成问题与临时 C# 源码：

```powershell
backend/.venv/Scripts/python.exe scripts/verification/autonomous_answer.py --live
```

结果写入本机忽略的 `output/autonomous-answer/`，正式配置只读入内存，不复制密钥，不向正式数据库写入验收对话。实际检查结果见[本轮验证](../verification/autonomous-answer-20261030.md)。
