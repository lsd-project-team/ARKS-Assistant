# 聊天附件与依据文档修改代码

聊天输入框的“＋”支持多文件上传。上传并解析后显示附件卡片，点击可以分页查看正文并下载原件；发送前可以移除。每个文件独立处理，部分失败后继续上传后续文件，重试仅处理失败项。上传过程中可继续输入，解析完成后才能发送。

上传文档后，在输入框说明“请根据附件修改某个功能”。助手可以读取文档、核对现有业务代码，使用现有独立 Simulation 副本工具完成修改、差异检查、需求断言、编译与仿真。上传本身不触发编辑，普通分析请求继续按分析处理。原工程写回仍使用既有合并面板。

## 格式与范围

| 类型 | 扩展名 | 读取方式 |
| --- | --- | --- |
| Word | `.docx` | 正文及表格文字，按段落定位 |
| PDF | `.pdf` | 按页提取文本，无文字页使用本地中英文 OCR，保留页码和 OCR 标记，最多 300 页 |
| Excel | `.xlsx` | 各工作表的非空单元格，保留地址、公式原式及已有缓存值 |
| 表格文本 | `.csv` | 保留行号、列顺序、空值和引号中的换行 |
| 源码、说明与配置 | `.txt`、`.md`、`.cs`、`.cpp`、`.c`、`.h`、`.json`、`.yaml`、`.yml`、`.xml`、`.ini`、`.log` | 以行号定位，兼容 UTF-8、UTF-16 和 GB18030 |
| 文档与源码包 | `.zip` | 读取包内 PDF、DOCX、XLSX、CSV 及上述文本格式，保留完整路径和各自的位置标记，不解压到业务工程 |

单文件最大 32 MB，每条消息最多 10 个附件。提取正文最多 100 万字符，超过时拒绝并提示拆分，不静默截断后用于改码；ZIP 按所有已读取文件的合计正文检查。Excel/CSV 单表最多 20000 行、2000 列；Excel 单表范围不超过 100 万格，工作簿最多 10 万个非空格。压缩格式沿用 64 MB 展开体积、2000 项和安全路径检查；ZIP 内 DOCX/XLSX 的内部展开体积及条目同样计入整个包的累计预算，累计超限时拒绝整个 ZIP。

旧版 `.doc`、`.xls`、加密文件未接入；Word 的内嵌图片、对象、页眉页脚和 Excel 图片、图表不解析。Excel 不执行宏、外部链接或公式重算；没有缓存值时明确保留为未知缓存。ZIP 内单个源码/配置文本最多 2 MB，PDF、DOCX、XLSX、CSV 各最多 32 MB；嵌套 ZIP 不递归读取。损坏、加密、OCR 后仍无文字、空文件、单文件大小超限或不支持的格式会逐项记录包内路径与原因，其余文件继续读取，整个附件标记部分可读；全部文件不可读时上传失败。

### 扫描 PDF 与 OCR

聊天附件使用 PDFium 渲染与 RapidOCR/ONNX Runtime 本地识别；标准 `Setup.ps1` 的锁定依赖安装同时提供模型，处理文档时不下载模型或调用外部视觉服务。单独 PDF、ZIP 内 PDF 和同时包含文字页与扫描页的 PDF 共用同一条解析流程。文本页直接读取，只有未提取到文字的页面进入 OCR；已有文字页中的嵌入图片不另做识别。

OCR 正文保留 `[第 N 页] [OCR 识别]`，按识别行保存，不重建表格结构或解释图片含义。识别行置信度低于 0.5 时不采用，保留行中有低于 0.8 的结果时标记部分可读。识别失败或仍无文字的页面保留原因；其他已读页面继续可用，整个文件标记部分可读。ZIP 继承各 PDF 的低置信、缺失页和识别失败状态。

每个附件累计最多 OCR 50 页、等待及识别累计最多 120 秒，ZIP 内所有 PDF 共用这两个额度；超限时拒绝整个附件并提示拆分。每个后端进程最多同时运行 2 个 OCR 子进程，页面最长边最多渲染为 2500 像素，并在识别后释放图像；超时会终止子进程。OCR 依赖或本地模型缺失时给出重新运行 `Setup.ps1` 的说明，不把未识别页面当作可读内容。

识别文字随附件固定版本保存，原件下载返回上传文件。旧附件不自动重写解析结果，需要重新上传后使用 OCR。以上 OCR 入口限聊天附件，交接资料原有导入行为保持。

## 消息、权限与恢复

- 消息和待发问题保存服务端生成的附件编号、原文件 SHA256、文件名和解析状态，客户端不能提交正文来冒充已上传文档。
- 附件随草稿保存到当前账号的本地工作区；异步上传完成时仍写回原草稿。发送失败时草稿及附件保留。
- 消息历史、问题编辑、恢复运行、重新生成、等待队列、分支和对话移动保留固定附件版本。问题编辑未提供附件列表时继续使用原附件，显式空列表表示移除本轮附件。
- 附件接口校验账号及项目归属。对话跨项目移动后，已绑定附件随消息继续可读。模型工具进一步限制为当前有效对话的附件，不能通过已知编号读取其他对话或被替换问题的文档。
- 长文档使用 `search_chat_attachment` 定位，再用 `read_chat_attachment` 分页读取；每次最多 12000 字，并返回后续偏移。运行记录保留实际读取的文件版本和范围。
- 文件保存在 `data/scratch/chat-attachments/`，解析正文保存在 `chat_attachments` 表；完整备份同时包含两者。删除草稿卡片只解除草稿附加；已发送文件受引用保护。彻底删除对话时，仅清理不再被其他消息、分支或队列引用的原件。

数据库迁移 `0030` 为旧消息和待发问题添加默认空附件列表，保留原始内容、账号、引用和历史版本。
