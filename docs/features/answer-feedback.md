# 回答反馈（2026-11-04）

用户可在聊天中的具体回答下点击“反馈”，填写说明并提交。问题类型选填，支持内容错误、答非所问、内容不完整、来源有误、显示异常、其他；说明必填，最多2000字。

## 使用与范围

- 提交时显示“正在提交…”并禁用表单操作；成功提示“反馈已提交”后关闭弹窗。
- 提交失败显示原因并保留输入，未修改内容时重试复用提交编号，避免响应丢失后重复落库。
- 反馈绑定打开弹窗时的项目、对话和回答消息；重新生成、版本切换不会将反馈转移到新版回答。
- 管理员在“AI 问答记录”查看反馈数量，并可勾选“仅看有反馈”。详情在相应回答下显示反馈人、时间、类型和原文，换行保留，内容作为文本显示。
- 用户端仅提供提交入口，没有反馈回显、修改、撤回；后台没有处理状态或回复流程。反馈不自动进入模型提示、经验库或长期记忆。

## 保存与权限

新增 `answer_feedback` 表及迁移0029，保存回答消息、原问题、运行记录、实际提交人快照、时间、类型和说明。账号与关联由服务器从登录身份及持久化消息确定，拒绝客户端伪造字段。

提交接口为 `POST /api/p/{project}/threads/{thread}/messages/{message}/feedback`。请求包含 `submission_id`（UUID）、`content` 和可选的 `category`。复用原项目/对话归属、CSRF及账号校验；用户不能向其他账号、其他项目或回收站中的回答提交反馈。

历史分支复制的回答没有运行记录时，关联该分支中的对应问题，运行编号保持空值。回收站保留反馈，永久删除对话时随原回答清理。原问题、原回答及全部回答版本不改写。

管理员接口沿用 `/api/admin/questions`，新增 `has_feedback` 筛选及 `feedback_count`。详情接口按当前消息页返回 `feedback`，加载后续消息时一并读取对应反馈。普通用户没有管理端读取权限。
