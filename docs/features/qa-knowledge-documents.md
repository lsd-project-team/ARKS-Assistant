# 问题与经验的问答文档

2026-10-30，按用户确认的三个示例将问题与经验正文统一为问题、答案、关键词。原六项结构及旧字段仍可读取历史修订，新增和编辑使用新结构。

## 正文与metadata

每条记录的payload为`question`、`answer`、`keywords`、`metadata`四项。页面的主要录入和阅读区域只显示前三项；问题是自然的问句，答案用完整句子表达处理办法、必要条件、关键参数、结果及尚未确认的事项，关键词支持相关叫法与检索词。现有记录编号、标题和固定版本引用保留。

原记录人、原记录时间、事项日期、实际录入人、原始描述、来源对话、类型、处理状态和有序原图引用存入metadata。必要的业务日期、适用工况和参数仍在答案中说明；录入身份等管理信息不混入答案。页面的“记录信息”默认折叠，原文和原图仍可查看。录入账号、来源、原文和图片关联由服务端维护，客户端不能伪造这些metadata。

未解决的问题不因改写而变成已解决，工作进展和资料归档也不虚构解决办法。旧修订按原版本读取，修改后新增修订；原作者、原文和原图不因编辑答案而覆盖。旧草稿和旧客户端提交沿用兼容转换，新页面只提交新的问答结构。

## 检索与回答

`modules/knowledge/documents.py`将记录构造成LangChain `Document`。`page_content`只有问题、答案和关键词，metadata保存来源、固定版本、作者和日期等信息。现有本地关键词与语义混合检索只对问答正文建索引，不将原始导入JSON、文件名、录入人和图片哈希拼入向量文本；没有增加独立向量数据库服务。

设备、版本、模块和工况继续使用metadata核对。普通问答默认只收到筛选后的问题、答案和关键词片段；明确查询记录人、日期或逐字原文时才展开对应metadata。引用和原图仍按真实编号、固定修订定位。

回答模型用资料组织答案，可以归纳、比较和解释建议理由；处理经验已覆盖的工艺问题不再默认要求展开源码排查。源码实现和参数计算仍须核对源码。经验事实核查及失败标记继续保留，本次没有通过跳过核查来改善显示。

## 整理与发布

维护工具为`scripts/maintenance/curate_debug_documents.py`，按`snapshot → draft → audit → 人工核对 → apply`执行。草稿和真实业务内容只保存在本机忽略目录，不提交Git。供应商配置只读入内存，不复制密钥；模型错误只记录类型。

发布前必须有每条草稿的审阅哈希。工具先校验全部记录集合、版本和原文指纹，再在同一事务内写入全部新修订；并发编辑、草稿变化或校验失败会中止整批发布。备份、原文、旧修订及有序原图均保留。用户此次已明确授权整理全部现有记录，无需额外确认。

本轮共整理82条问答，保留21处原图引用。整批转换首先在数据库副本验证，逐项对比metadata、全部旧修订和原图字节。真实模型与隔离页面验证情况见[验收记录](../verification/qa-knowledge-documents-20261030.md)。
