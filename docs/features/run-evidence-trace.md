# 回答依据与运行耗时

2026-10-30起，聊天内展开“运行详情”及上下文资料窗口显示“本轮依据与耗时”。概况从实际保存且经过当前账号可见性过滤的运行事件生成，不展示模型内部逐步推理，不增加解释过程的模型请求。

- 长期记忆：本地召回并送入筛选的候选数、选中数、阶段耗时。
- 较早对话：用户消息、答复工具链及摘要事实的候选/选中数；近期保留消息数、筛选前后消息 token 估算、同轮缓存复用次数。选中回复自动带回的原问题也计入选中数。
- 问题与经验：本轮接触到的不同固定版本记录数、已选记录数、筛选阶段耗时及缓存。失败不冒充没有资料，候选原文不会因为展示概况而进入回答。
- 来源原文：查看选中的记忆快照；点击经验标题打开固定版本原文；源码条目沿用目录、版本和引用检查打开。
- 核查：显示实际记录的经验事实核查、源码引用检查和源码结论复核结果；未核查、失败、已修正和通过分开显示。
- 耗时：执行时间与排队时间分开；按目的累计模型请求次数和耗时，并显示已记录的失败调用。工具耗时是保存的开始/返回事件之间的经过时间，可能包含并行等待，不能当作精确的函数 CPU 时间。

模型请求、筛选和工具区间可能重叠，不能相加当作执行总耗时。旧运行缺失的数据显示未记录，不补零、不推测通过。短对话无需旧历史筛选、未启用来源和本轮未检索分别说明。

在详情展开时读取概况，活动运行每秒刷新，完成后停止。资料原文仍按用户展开/点击时读取，不因加载概况自动读取所有记录。关闭详情不继续轮询。

其他账号查看共享聊天时，个人记忆正文、筛选统计及对应模型调用记录不可见；其他可见来源继续按原有账号和项目权限读取。概况不会写回原消息、摘要、记忆或知识记录，不需要数据库迁移。
