# 通用代码工作区（就地修改）

更新日期：2026-11-11。

聊天可以直接读写管理员为本项目配置的本地工作目录，按 Codex 方式修改代码、执行构建与测试。不再创建独立工程副本，也没有三方合并或写回确认步骤；安全边界改为“工作目录限制 + 命令白名单 + 逐条审批 + 写前快照”。

## 入口与配置

- 管理员在“系统配置 → 代码工作区”设置工作目录、命令白名单、是否自动批准白名单命令，以及审批/命令超时。
- 配置保存于 `data/workspace-work.local.json`，按项目区分；换目录后旧对话不能继续使用同一份修改记录，需新建对话。
- 工作目录必须是本机已存在的绝对路径，不能与助手 `data/` 目录互相包含，不能是链接。
- 用户在聊天中直接描述需求；对话标题栏的 `</>` 按钮打开右侧“代码工作区”，查看修改、命令输出和待审批请求。

## 文件操作

- 读取：`read_workspace_file` 返回带行号的文本、当前版本哈希和总行数，单次最多 2000 行，单文件不超过 2 MB。
- 写入：`write_workspace_file` 必须带最近一次读取的版本；新增文件版本为空。编码、BOM 和换行按原文件保留。
- 编辑：`edit_workspace_file` 替换唯一匹配的原文，匹配不唯一直接拒绝，避免改错位置。
- 批量：`apply_workspace_patch` 一次提交最多 50 个文件修改，先全部校验版本和匹配，再逐个写入；任一失败整批不落盘。
- 查找：`search_workspace` 在当前工作区文本中搜索，返回路径与行号；`.git`、`node_modules`、`bin`、`obj`、`dist`、`__pycache__` 等目录不参与。

## 命令执行与审批

- 只接受参数数组，`shell=False`，不拼接命令字符串。
- 程序名与参数前缀必须命中白名单；未命中直接拒绝并提示管理员配置。
- 默认每条命令都等待用户在右侧面板批准；开启“自动执行”后白名单命令直接运行。审批超时（默认 120 秒）按拒绝处理。
- 单条命令超时（默认 300 秒）会终止整个进程树；输出上限 4 MB，超出后终止并标记截断。
- 命令记录保留参数、工作目录、退出码、状态和输出末尾，在面板中展开查看。

## 快照与还原

- 每次写盘前把文件当前内容按哈希存入对话快照目录；同一文件的多轮修改共享第一次改动前的基线。
- 面板可还原单个文件或本对话的全部修改；还原后该文件退出“待审查”列表。
- 快照位于 `data/scratch/ww/<对话哈希>/`，只保存被修改文件的内容，不复制整个工作目录。

## 范围与边界

- 直接修改真实文件，不提供操作系统级沙箱；权限等同于当前 Windows 用户。
- 工作区工具不限制语言，但命令白名单、编码保持和差异展示按文本文件设计。
- 未接入远程仓库、容器、后台常驻进程和交互式终端；长时间构建受命令超时限制。
- 不自动 commit 或 stash；git 只作为用户自己的版本管理手段。
- 真实设备、视觉、力控、标定等仍需另行验收；聊天中的仿真或测试通过只能说明当次命令结果。

## 实现位置

- `backend/app/modules/workspace_work/`：配置、路径与编码、命令执行、快照日志、服务与 HTTP 接口。
- `backend/app/agents/tools/workspace_work.py`：聊天工具与工作区提示词。
- `frontend/src/features/chat/workspace_work/`：右侧面板、差异渲染、审批操作与管理员配置。
- 接口：`/api/workspace-work`（管理员配置）、`/api/threads/{对话}/workspace-work`（状态、文件、差异、搜索、补丁、还原、命令、审批）。

## 验收

- 后端：工作区读写、版本锁、批量补丁原子性、路径越界、还原、白名单拒绝、审批同意/拒绝、命令超时。
- 前端：差异按行分类渲染、面板结构与类型检查、生产构建。
- 数据：测试只写临时目录；`trunk/` 与正式数据目录不被写入。
