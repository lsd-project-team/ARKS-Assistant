# AI 回答的层次阅读样式

回答由 `AnswerMarkdown` 的 `answer-reading` 容器统一设置阅读样式，普通 Markdown、结构化内容、历史回复、流式回复及未完成回复使用同一套色阶。样式位于 `frontend/src/features/chat/styles/answer-reading.css`，在原有回答与富内容样式之后加载。

## 视觉层级

- 标题和加粗文字使用强调字色，正文使用柔和字色；来源、文件附加信息使用次级字色。
- 正文默认 17px、1.85 倍行高，窄聊天面板为 16px、1.8 倍行高；结构化卡片、步骤说明和描述正文使用同一阅读字号，章节、段落和列表保留原间距。
- Markdown 二、三级标题使用细强调边，引用块使用浅强调底色。仅作用于原有结构，不把普通段落或关键词自动转换成标题、提醒或结论。
- 行内代码使用暖色文字与底色；代码块为 14px，区分工具栏和代码表面，语法 token 继续使用现有高亮主题。回复内 Markdown 代码的选择器优先于按需加载的项目壳样式，避免被旧 12px 字号覆盖。
- 普通与结构化表格为 15px，共享表头、细分隔线和淡隔行底色，保留原数字对齐和横向滚动。
- 来源仍在原有页尾位置。源码来源使用 13px 灰绿色文件标签与独立行号块，纯白/灰绿使用淡绿底，深色使用墨绿底；悬停行号时加深并显示下划线，键盘焦点保留轮廓。全部行号不可用的文件标签及不可用行号保持灰色；同一文件混合状态时，只将不可用行号置灰。颜色仅表示可点击性，不代表业务验证通过，引用定位、版本与权限边界不变。
- 工具的成功、跳过、失败颜色只读取已有 `data-state`，不根据回答文字推断执行结果。

纯白和深色分别配置色阶，灰绿外观使用原主题的语义颜色。配色限制在回答内，不更改用户提问、源码编辑器、图表数据系列或全局布局。

左侧导航按用户追加要求同步统一字号：品牌、主要功能、最近/回收站、项目名及对话名为 16px，分组标签、展开提示及底部辅助信息为 13px。字号变量限定在工作区左栏，主题样式读取同一变量；保留原有列宽、折叠、滚动和长标题省略，不调整导航配色。实现位于 `sidebar-navigation.css` 及 `theme-interface.css`。

## 交互与数据

继续使用原 Markdown/富内容解析器和组件，不修改模型提示、后端回答流程或消息正文。保留流式增量渲染、代码复制/换行/展开、工具折叠、表格滚动、引用定位/预览、公式、图表、流程图和思维导图的既有交互。

容器内顺序仍为回答正文、原有补充、来源；不拆分长段落、不移动引用位置、不生成新的摘要或状态。历史回答重新渲染即可应用，不迁移或重写数据库。

仅发布前端资源，沿用先复制资源与清单、最后原子替换首页的方式，复用现有后端及登录会话。
