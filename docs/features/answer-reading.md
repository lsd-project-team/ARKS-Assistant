# AI 回答的层次阅读样式

回答由 `AnswerMarkdown` 的 `answer-reading` 容器统一设置阅读样式，普通 Markdown、结构化内容、历史回复、流式回复及未完成回复使用同一套色阶。样式位于 `frontend/src/features/chat/styles/answer-reading.css`，在原有回答与富内容样式之后加载。

## 视觉层级

- 标题和加粗文字使用强调字色，正文使用柔和字色；来源、文件附加信息使用次级字色。
- 正文在宽栏和窄栏均为 16px、26px 行高；Windows 中文优先使用微软雅黑 UI（`Microsoft YaHei UI`），英文沿用系统界面字体，其他平台按系统字体回退。字体规则仅限定在 AI 回复容器，结构化卡片、步骤说明和描述正文同步；章节、段落和列表保留原间距，深浅外观沿用既有色阶。
- Markdown 二、三级标题使用细强调边，引用块使用浅强调底色。仅作用于原有结构，不把普通段落或关键词自动转换成标题、提醒或结论。
- 行内代码使用暖色文字与底色，并保留调整前的宽窄栏字号；表格及来源中的行内代码继续按各自字号计算。代码块保持 14px、1.75 倍行高，代码工具栏沿用原界面字体与行高，区分工具栏和代码表面，语法 token 继续使用现有高亮主题。回复内 Markdown 代码的选择器优先于按需加载的项目壳样式，避免被旧 12px 字号覆盖。
- 普通与结构化表格为 15px，共享表头、细分隔线和淡隔行底色，保留原数字对齐和横向滚动。
- 来源仍在原有页尾位置。源码来源使用 13px 灰绿色文件标签与独立行号块，纯白/灰绿使用淡绿底，深色使用墨绿底；悬停行号时加深并显示下划线，键盘焦点保留轮廓。已读引用和本轮成功搜索命中的引用共用正常绿色及点击入口，不增加分类标签。全部行号不可用的文件标签及不可用行号保持灰色；同一文件混合状态时，只将不可用行号置灰。颜色仅表示可点击性，不代表业务验证通过。
- 工具的成功、跳过、失败颜色只读取已有 `data-state`，不根据回答文字推断执行结果。

纯白和深色分别配置色阶，灰绿外观使用原主题的语义颜色。配色限制在回答内，不更改用户提问、源码编辑器、图表数据系列或全局布局。

左侧导航按用户追加要求同步统一字号：品牌、主要功能、最近/回收站、项目名及对话名为 16px，分组标签、展开提示及底部辅助信息为 13px。字号变量限定在工作区左栏，主题样式读取同一变量；保留原有列宽、折叠、滚动及导航配色。项目名称和对话标题超长时保持单行，末尾 24px 逐渐变透明，不显示截断省略号；未溢出的短名称不渐隐，侧栏宽度、名称及字体加载变化后重新判断。悬停仍查看完整名称，文件夹、置顶、运行图标和操作菜单不参与遮罩；品牌沿用原省略规则。两者共用 `OverflowText.tsx`，样式位于 `sidebar-navigation.css` 及 `theme-interface.css`，顶栏项目名和导航外界面保持原样。

## 交互与数据

继续使用原 Markdown/富内容解析器和组件，不修改模型提示、后端回答流程或消息正文。保留流式增量渲染、代码复制/换行/展开、工具折叠、表格滚动、引用定位/预览、公式、图表、流程图和思维导图的既有交互。

容器内顺序仍为回答正文、原有补充、来源；不拆分长段落、不移动引用位置、不生成新的摘要或状态。历史回答重新渲染即可应用，不迁移或重写数据库。

引用优先使用原有已读证据及版本、来源身份、连续范围校验。缺少已读证据时，前端从已有运行上下文的成功 `search_source` 结构化结果中匹配完整路径和引用范围内的实际命中行；不读取工具参数、不猜同名文件、不补造读取记录或文件版本。搜索历史没有原始文件版本，因此点击定位当前源码；已知版本变化、不可读、版本或目录冲突以及显式版本引用不能通过搜索降级。未匹配的来源仍不可用。打开时复用原有源码身份、权限、路径及当前行数校验，不增加模型调用、自动补读或回答后核查。

仅发布前端资源，沿用先复制资源与清单、最后原子替换首页的方式，复用现有后端及登录会话。
