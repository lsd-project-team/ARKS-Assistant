# 晶圆系统调度与服务（`AKRS.ZX2200/WaferSubSystem/{Controllers,Tasks,Modules,Services}`）

> 晶圆侧的**运行时执行链**：两个长驻工作线程（`WaferSubSystemTask` 搜晶、`FlipTask` 翻转）+ 5 个无状态控制器 + 5 个硬件模组容器 + 3 个静态服务类。
> 代码规模：15 个文件 / 7,211 行（不含 `*.Designer.cs`；本范围内无 Designer 文件）

## 1. 模块定位

晶圆子系统在整机中扮演**被动的取料服务方**：它自己不决定「什么时候取哪颗芯片」，而是由固晶侧（`BondSystem`）通过信号池（`SignalPool`）下达「需料」指令，晶圆子系统完成**搜晶 → 摆位 → 开真空 → 举起顶针 → 通知可取**这一串动作，然后等待固晶侧取走并回报。

职责边界：

- **本范围负责**：晶圆台的 XY 定位、扩晶环升降、晶圆夹取放料、Magazine 上晶圆 Z 轴、顶针架旋转/顶针升降/顶针台升降、翻转台 T 轴；以及驱动这些动作的两个工作线程。
- **不在本范围**：芯片阵列的**遍历算法本体**（在 `WaferSubSystem/Models/Entities/SearchChip/Block*.cs`，由 `10-晶圆系统数据模型.md` 覆盖）、界面层（`WaferSubSystem/Controls/`，由 `08-晶圆系统界面层.md` 覆盖）、数据模型与配置文件（`WaferSubSystem/Models/`）。

上下游：

- **上游（下命令）**：`BondSystem/Models/ActionNodes/BPActionNode/PickActionNode.Provider.cs:633 SendSignalToWaferTable()`、`BondSystem/Controllers/System2Controller.Assistant.cs`、`System2Controller.AutoCali.cs`、`FlipTask` 自身。
- **下游（硬件）**：`WaferSubModule`（5 个模组）→ `HardwareRepositoryService.GetHardware<T>("字符串名")` → `AKRS.Galaxy2.LogicHardware` → 运控（ETEL / 固高 Googol / 雷赛 DMC）。
- **横向**：`WaferSystemDomain`（`Models/WaferSystemDomain.cs:66`）作为门面持有 `WaferSubSystemTask` 与 `FlipTask` 实例；`WaferSubController`（`SingletonNoSave`）持有 5 个控制器实例。

## 5. 关键实现细节

### 5.1 遍历序列本体在哪

**本范围内没有遍历算法**。`WaferSubSystemTask` 只是调用 `Block.NextDie()`（`Tasks/WaferSubSystemTask.cs:162`），分发逻辑在 `Models/Entities/SearchChip/Block.cs:335`：

```csharp
public bool NextDie()   // Block.cs:335
{
    if (SearchMode == Single)   return SearchSingle();     // Block.SearchSingle.cs
    if (SearchMode == Nine)     return SearchNine();       // Block.SearchNine.cs
    if (SearchMode == WaferMap) return SearchMapping();    // Block.SearchMapping.cs:46
    if (SearchMode == Box)      return SearchDieBox();     // Block.SearchDieBox.cs
    throw new Exception("No exist the Search Mode!");
}
```

其中 `WaferMap`（晶圆图）模式的序列由外部组件 `AKRS.WM.WaferMapInterfaceImplementer`（字段 `Block.WaferMapII`，`Block.SearchMapping.cs:592`）产生，本项目只负责喂参数：

- `StartAsyncSeekingPath(false, UsableType.ValidAndVoid, ReferablePointType.LocatedChip)`（`Block.SearchMapping.cs:209`）—— 异步寻路，**允许「有效+空」晶粒参与路径**。
- `JumpInterval`（= `WaferMapDataConfig.JumpStep`，`Block.SearchMapping.cs:725-728`）—— 跳片间隔。
- `SetStrategyUserDirection(UserDirection)`（`Block.SearchMapping.cs:735`）—— 逐行/逐列/蛇形由这个枚举决定。
- `SetSelectedChipTypes`（`Block.SearchMapping.cs:753`）—— 参与取片的芯片类型集合。
- 取下一颗用 `GetNextPositionInfoAndForwardTo()` / `PreGetNextPositionInfo()`（`Block.SearchMapping.cs:453-491`），跳过条件在 `while (this.currentDieInfo.IsSpringboard || isSkip)`（`Block.SearchMapping.cs:121`）。

**结论**：逐行/逐列/蛇形、跳片（`IsSpringboard` 跳板晶片）、坏点跳过（`isSkip` + `countBlankNum`）都由 `AKRS.WM` 库与 `UserDirection`/`JumpInterval` 决定，本范围内只是「调用 + 传参」。细节请以 `10-晶圆系统数据模型.md` 为准。

坏点跳过的判据在本项目可见的部分：`Block.cs:221` 用 `IsBlankDieAutoSkip` 与 `BlankDieAutoSkipMaxTimes`，连续空晶计数 `countBlankNum`（`Block.cs:310`），超限则弹「定位失败」对话框（`Block.cs:200-296`，选项为 `Ignore/Retry` 等）。

### 5.2 并发模型

- **两个长驻线程**（都是 `LongRunning` Task）：`WaferSubSystemTask`（搜晶）、`FlipTask`（翻转）。**无定时器驱动**。
- **共享可变状态**：`Services/Static.cs` 是纯静态类，字段被两个线程读写：
  - `Static.IsComponentOnFlipTool`（`Services/Static.cs:64`）—— `WaferSubController.cs:602` 置 `true`、`WaferSubController.cs:548`（`CloseFlipTableVacuum` 后）在 `Throw()` 路径置 `false`（`FlipTableController.cs:249`）、`FlipTask.cs:96/205` 读写。**无锁**。
  - `Static.WaferSystemStopwatch`（`Services/Static.cs:59`）—— `RecordTime`（`:71-80`）里先读时差再 `Restart()`，两线程共用同一个 `Stopwatch`，**日志耗时数据会互相污染**。
- **异步委托**：`WaferTableController` 用 `BeginInvoke/EndInvoke`（`PreChangeTablet`，`Controllers/WaferTableController.cs:616-637`）在**线程池线程**上并发跑「晶圆台去换料位」+「扩晶下行」，再在 `PlaceWaferInSlot`（`:1007`/`:1017`）或 `RemoveWaferFromSlot`（`:1089`/`:1091`）里 `EndInvoke` 汇合。委托字段挂在控制器实例上（`:73-98`）。
- **单步模式**：每次轴运动前调 `WaferSystemDomain.SingleStep()`（`Models/WaferSystemDomain.cs:141`），内部等 `SignalPool.System2SingleStepSignal`；失败抛 `"等待单步信号失败！"`。注意 `EjectController.MoveEjectToLiftPosition` 用的是另一个入口 `System2Domain.GetInstance().WaitSingleStep()`（`Controllers/EjectController.cs:232`），该入口失败时**静默 `return`（顶针不顶起）而不抛异常**（`BondSystem/Models/System2Domain.cs:777-788`）——两者等的是同一个信号，但失败语义不同。

### 5.4 停止语义

**不用 `CancellationToken`、不用事件、也不用轮询 `IsStop()` 作主判据**。实际判据是**信号对象内部的 `MachineStateModel.MachineState` 检查**：

- `Signal.WaitStart()`（`AKRS.Galaxy2.Machine/Models/Signal.cs:202`）：`MachineState == Stop` → 返回 `false`；`MachineState == Pause` → 每 20ms 自旋阻塞（`:217-225`）。
- 两个线程的外层循环都以它为闸门：`while (Signal.WaitStart())`（`Tasks/WaferSubSystemTask.cs:69`、`Tasks/FlipTask.cs:62`）。所以**停止是在循环边界生效的**，外层不是 `while(!IsStop())`——与固晶侧 `BondTask` 的风格不同，晶圆侧用的是 `Signal.WaitStart()`。
- `Signal.Wait()`（`Signal.cs:116-145`）：先 `WaitStart()`，再进 `do { if (MachineState == Stop) return false; Thread.Sleep(5); } while (!signalEvent.WaitOne(recycleTime));`。因此**任何一次 `XXX.Wait()` 都是一次隐式的停止检查**，检查周期是 5ms 自旋 + `recycleTime`（本范围信号均为 100ms 超时）。`WaferSubSystemTask.cs:80` 的 `IsBondNeedChipSignal.Wait()` 返回 `false` 时会 `goto WaitBondNeed`（`:82`）回到 `while (Signal.WaitStart())` 从而退出循环。
- 本范围内唯一的**显式** `Machine.GetInstance().IsStop()` 出现在 `Tasks/FlipTask.cs:176`——在 `notifyWafer` 内那个 `Task.Run` 自旋里（每轮 `Thread.Sleep(10)`，`:181`）。`Block.cs:1497` 另有一处（不在本范围）。

- **线程无法被主动中止**：`AbortWaferSubThread()`（`Tasks/WaferSubSystemTask.cs:1430`）方法体**全部被注释掉**，是空方法。

### 5.7 取放料（料夹）流程

`PlaceWaferInSlot()`（`WaferTableController.cs:964`）与 `RemoveWaferFromSlot(int targetIndex, bool isOnlyAction=false)`（`:1059`）是**唯一同时改硬件与持久化**的两个方法：它们会更新 `MagazineAllocationsProgram.CurrentAllocationsConfig.TabletArray[...]`、`CurrentTablet`、`MagazineDevicePara.CurrentLayerNo` 并调用 `MagazineAllocationsConfigRepository.Save()` / `WaferSubDevicePara.Save()`（`:1046-1050`、`:1141-1147`）。

`RemoveWaferFromSlot` 的时序：`PreChangeTablet()`（归还顶针→异步去换料位→异步扩晶下行）→ `EndInvoke` 汇合 → 按 `IsManualChangeTabletMode`（`:1728`）决定人工/自动 → `MagazineController.SlotScan(targetIndex)`（实际只移动）→ 自动时可选 `ActionPushCyc()`（`:400`，推料气缸）→ `ActionWaferClampRemoveWaferFromSlot()`（`:723`）→ 抬夹持气缸 → 写记忆 → 若是 `WaferTablet`：热吹风上料（`ActionHotBlowerOfLoad`，`:595`）或直接异步扩晶上行 → 去准备位。

`ActionWaferClampRemoveWaferFromSlot` 里的**慢速寻料**：`IsNeedSlowTravel` 时先走 `SlowDistance` 快移，再用 `MoveWaferClampAxisYToG0PosWithCommand(..., SlowFeedrate)` 慢速走余量，中途 `WaferClampCheckSensor.WaitSignal(true, DelayClampCheckSensor, ref isCancelWait)` 遇信号即 `StopMove(false)`（`:738-765`）。非慢速路径同样有 `WaitSignal` 分支（`:766-793`）。`isCancelWait` 是控制器上被 `[JsonIgnore]` 标记的字段（`:56-57`）。

## 8. 注意事项与风险

**结构性遗留**

1. `MagazineController.SlotScan(int index)`（`:333`）在 `:357` 有一句裸 `return;`，其后的料层一致性校验（`:359-394`）和局部函数 `CheckMagazine()`（`:340-355`）**全部不可达**。也就是说自动换料时**不再校验传感器与程式记忆是否一致**。注释写着「增加料盒感应判断」，功能实际被禁用。
2. `WaferSubController.FlipFromWaferTable` 的「翻转吸嘴堵塞判断」被 `if (false)` 短路（`Controllers/WaferSubController.cs:523`）。注释掉的 `IsComponentOnFlipTool()` 调用就在上面一行。当前「翻转吸嘴是否已有残留芯片」这件事**只在 `FlipTask` 里通过 `Static.IsComponentOnFlipTool` 这个静态标志判断**（`Tasks/FlipTask.cs:96`），**不做硬件真空检测**。
3. `WaferSubSystemTask.AbortWaferSubThread()`（`:1430`）整体被注释，是空方法；`waferSubSystemWorkThread` 字段也已注释（`:1472`）。线程一旦启动只能靠 `MachineStateModel.MachineState` 置 `Stop` 让它自然退出。
4. `FlipChipActionDryRun` 中 `prePickPos = pickPos + 3`（`Controllers/WaferSubController.cs:423`）——**硬编码 3mm** 抬高量，注释只写「取片位抬高3mm」，无参数化。
5. `WaferSubSystemTask` 里大段被注释/绕过的分支：`:90-111`（空跑次数切换芯片名）、`:176-187`（旧版找不到芯片提示）、`:266-267`/`:284-286`（`StaticWaffle` 分支）、`:673-712`（"TODO 自动更换晶圆图、确认位置"）、`:966-981`（Adapter 的 `AutoRunWithDieMode` 判断）。阅读时容易误判分支可达性。
6. `Services/CoordinateSystemHelper.cs` 三个扩展方法在本仓库内**无任何调用者**，是死代码。

**异常与线程**

7. `EjectController.CheckEjectionAxisZAtReadyLiftPosition()`（`:1010`）在 `:1018` 直接解引用 `EjectDevicePara.CurrentSlotConfig.EjectionConfig`，**没有空判断**（同文件其它方法如 `MoveEjectToReadyLiftPosition` 在 `:194-198` 有空判断）。若 `IsShieldEjectModule` 为 `false` 而 `CurrentSlotConfig` 为 `null`（例如 `ReturnEjection()` 或 `InitCurrentSlotConfig()` 清空之后），会抛 `NullReferenceException`。调用点：`WaferTableController.cs:1452`。
