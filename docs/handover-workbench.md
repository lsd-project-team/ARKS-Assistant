# 交接工作台开发与验收记录

交接工作台采用第一版布局，新增独立入口和六个页签。PRD 用于业务参考，先落实文本访谈、普通 DOCX 和文本 PDF、固定源码快照、人工确认与手动日期；暂不依赖录音转写、OCR、实时 Git/Issue 同步或企业审批系统。

## 模块边界

新业务代码全部位于 `backend/app/handover` 与 `frontend/src/handover`。数据库仅新增四张交接表，附件包含在 SQLite 中，跟随现有备份恢复。

既有文件的必要接入清单：

- `backend/app/main.py`：注册独立路由、恢复和关闭独立 AI 作业。
- `backend/pyproject.toml`、`backend/uv.lock`：仅添加 pypdf 解析依赖。
- `frontend/src/App.tsx`：增加独立页面挂载与显示切换。
- `frontend/src/components/WorkspaceNavigation.tsx`：增加交接入口及选中状态。
- `backend/tests/test_backup_restore.py`：数据库最新修订断言由 0012 更新为 0013。

聊天、源码、流程图谱、功能说明、项目管理、配置和备份的原有业务实现保持不变。不得修改原始源码或既有知识资源。

## 持久化和确认规则

记录编辑、确认、归档、恢复均递增乐观版本。旧版本冲突不覆盖服务器内容；页面保留本机草稿，可逐项比较后合并。草稿按项目和记录隔离。

AI 没有工具或设备操作权限，只对选定数据生成候选。来源 ID、版本和逐字引文必须匹配保存的证据。运行失败、取消和服务中断均记录真实状态，模型未成功时不返回伪造结果。供应商仅有结构放置错误时，适配器移动已知字段而不改写值；冲突和未知字段继续严格拒绝。

DeepSeek 的交接摘要请求单独使用 [JSON 输出模式](https://api-docs.deepseek.com/guides/json_mode/) 和[非思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)，保留用户设置的输出预算和超时。现有聊天调用及模型配置不变。

人工确认是本机工作流程元数据，记录姓名、职责、意见和时间；不声称具备企业身份认证。设备操作仍按实际设备规程与责任人的判断进行。

源码文本或文件哈希仅证明内容存在，不证明软件正确。基线须注明源码覆盖范围；固件、SDK、配方、标定、配置必须填写实际版本或明确不适用，未知条件不能确认。设备层级验收要求相同基线下的已确认设备通过记录，不能由编译、发布检查或作者陈述代替。报告归档后相关验收重新复核，验收意向及过期验收不会显示为已验收。

捕获源码同时保存目录身份；项目关联目录变化时，即使文件内容相同，也不能把旧引用打开为另一目录的文件。资料换版保留旧原件，并使关联内容待重新复核。历史版本地址包含版本号，刷新和后退仍读取固定修订。

交接包固定生成时各记录版本；后续更正不会改写旧包的内容。包内明确显示未确认内容、缺项、未知条件和来源。
