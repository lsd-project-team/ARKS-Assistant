## 缺陷证据：损坏 JSON 可改变启动结果

1. TU 的非法 `SafeHeight` 数字字符串位于前部时，后续示教状态未成功读入，保留默认 UnAble 并拒绝启动；移到末尾时，已读 Able 保留，原启动方法继续运行。
2. 已教单焊点的非法 `VisionExposure` 数字字符串放在焊点对象前部时，实际 SDK 读取丢失该焊点记录。TU 仍为 Able，空焊点列表的原汇总返回通过，两条原启动方法均进入空焊点实体树、五次回零和真实供晶启动。这将先前独立数据探针中的现象推进到原启动方法的受控执行证据。
3. 不兼容的 Name 对象使实际产品读取失败并回退默认产品；空焊点汇总虽通过，默认 TU 为 UnAble，原启动方法拒绝启动。

两份 SDK 的预期错误回调各产生 20 条诊断，原样保存在运行结果中。上述结论来自实际 SDK 与原配置/原启动方法的组合，不表示已在实际窗口、部署配方或设备上复现。生产源码未修改；回退数据是否可启动已经记录为需处理的缺陷，不计为验收完成。
