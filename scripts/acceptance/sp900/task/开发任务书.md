# SP900 点胶机通信系统 —— 开发任务书（可直接投喂给编码助手）

> 使用方式：把本文件整份贴给助手。建议分两轮：第一轮只做「协议层 + 回放测试」，
> 跑通后再做第二轮「界面」。每轮结束要求它编译通过并给出验证结果。

---

## 一、目标

开发一个 Windows 桌面工具，通过 RS-232 与 **SP900 系列气动脉冲式精密点胶控制器**通信，
完成：连接、通信自检、点胶参数读写、设备信息读取、待机/活塞设置、报警读取、维护操作。

技术栈固定：**C# / .NET 8 / WinForms / System.IO.Ports 8.0.0**，不得引入第三方 UI 库或图表库。

---

## 二、运行环境与构建

- Windows 10/11 x64，Visual Studio 2022（17.8+）或 .NET SDK 8/9
- 项目类型：`WinExe`，`net8.0-windows`，`RuntimeIdentifier=win-x64`，`UseWindowsForms=true`
- 项目文件里 **`EnableDefaultCompileItems=false`**，每个 `.cs` 必须显式写
  `<Compile Include="Xxx.cs" />`，否则新文件不参与编译且不报错。
- 依赖：`<PackageReference Include="System.IO.Ports" Version="8.0.0" />`
- 构建：`dotnet build`。发布自包含单文件：
  ```
  dotnet publish -c Release -r win-x64 --self-contained true ^
    -p:RuntimeFrameworkVersion=8.0.33 -p:PublishSingleFile=true ^
    -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true ^
    -o publish\win-x64
  ```
  `RuntimeFrameworkVersion` 必须写死为本机 NuGet 缓存里实际存在的补丁版本，
  否则离线环境会报 `NETSDK1112 未下载运行时包`；发布前可用
  `dotnet restore -r win-x64 -p:RuntimeFrameworkVersion=8.0.33 --source %USERPROFILE%\.nuget\packages` 验证。

## 三、通信协议（务必逐字实现，这是踩过坑的地方）

### 3.1 物理层

| 项 | 值 |
|---|---|
| 接口 | RS-232C，半双工 |
| 速率 / 数据位 / 校验 / 停止位 | 9600 / 8 / None / 1 |
| 流控 | 无（Handshake.None） |
| 字符集 | ASCII |
| DTR / RTS | 均不置位 |

### 3.2 帧格式

- 发送：`>` + 指令 + `0x0D 0x0A`
- 应答：以 `>` 开头，以 `0x0D 0x0A` 结束
- **解析前必须剥掉前导 `>` 和尾部 CRLF**；忘记剥 `>` 会导致所有应答判定失败（真实踩坑）
- 接收超时默认 3000 ms；单帧上限 4096 字节

### 3.3 反馈包（ACK）

只有"没有数据包返回"的指令才回反馈包。

- **实机格式：`>ER:` + 文本 + `.`**，例如 `>ER:None.`
- **说明书写作 `>ERNone`（无冒号无句点）** —— 两种都要兼容：
  去掉前导 `>` 后，若以 `ER` 开头，再 `Trim`、去首字符 `:`、去尾字符 `.`、再 `Trim`，然后**不区分大小写**比较。
- 成功判定：文本等于 `None`
- 错误文本（出现任意一条即失败，需翻译成中文提示）：
  - `Channel number error` → 通道号不存在
  - `parameter error` → 参数超范围
  - `parameters cannot be modified` → 当前参数不可修改（通道处于补正模式）
  - `parameters cannot be read` → 数据无法读取
  - `Invalid command` → 无效指令（检查设备「系统设置 → 通信协议」是否为 RS232）

### 3.4 指令表

> 单位：压力 kPa；时间 ms；真空 0.01kPa（0~500 即 0~5.00 kPa）；模式 0=手动 1=定时。

| 指令 | 作用 | 发送 | 应答 |
|---|---|---|---|
| `R?` | 读当前通道 4 个参数 | `>R?` | `>R` + `压力^时间^真空^模式^` |
| `R` | 写当前通道 4 个参数 | `>R压力^时间^真空^模式^` | `>ER:None.` |
| `C` | 调用通道 | `>Cn`（无 `^`） | `>ER:None.` |
| `DI` | 点胶控制（手动：一次开始、二次停止；定时：一次执行一次） | `>DI` | `>ER:None.` |
| `DR` | 读当前通道全部参数 | `>DR` | `>D` + D1…D17 + `^` |
| `DW` | 写指定通道全部参数 | `>DW` + D1…D12 + `^` | `>ER:None.` |
| `M?` | 读补正开关 | `>M?` | `>M` + D1（无 `^`） |
| `M` | 开/关补正 | `>M1` / `>M0` | `>ER:None.`（开启会吐胶采样 5 次，**超时要给足**） |
| `WB` | 写 α/β/空管/满管补正 | `>WBα^β^空管^满管^` | `>ER:None.` |
| `BP` | 读胶液余量 | `>BP` | `>BP` + D1（0~200，单位 %，无 `^`） |
| `BA` | 读统计 | `>BA` | `>BA` + `计数^实际时间^供气压力^实际真空^` |
| `FA` | 读报警位 | `>FA` | `>FA` + `0bxxxxxxxx` |
| `S` | 传感器校准（约 10 s） | `>S` | `>ER:None.` |
| `WZ` | 点胶计数清零 | `>WZ` | `>ER:None.` |
| `WT` | 设待机时间 | `>WT0`~`>WT5` | `>ER:None.` |
| `WH` | 开/关活塞补正 | `>WH1` / `>WH0` | `>ER:None.` |
| `WQ` | 读待机与活塞设置 | `>WQ` | `>WQ` + `待机^活塞^` |

**DR 字段（D1→D17）**：通道号 1~500、点胶气压 30~500、真空 0~500、补正功能 0/1、
胶液材质 0~12、点胶模式 0/1、点胶时间 20~999999、胶筒 0~8、适配器 0~2、
剩余量检测 0~100%、检测次数 0~10、气源压力 200~600、α补正 -10~10、β补正 0~500、
空管补正 -50~100、满管补正 -50~100、机种名（≤10 字节，可为空，部分批次才有）。

**DW 字段（D1→D12）**：同上取前 12 项；D4 补正功能只允许 0；D13~D16 可省略（设备按 0 处理，
**可能清掉已设的补正参数，需在文档中提示**）。

**WT 选项**：0=无待机、1=5 分钟、2=10、3=15、4=30、5=1 小时。

**FA 位定义**：b0 供气压力错误、b1 点胶气压过高、b2 点胶气压过低、
b3 真空压力过高、b4 真空压力过低、b5 排气超时、b6/b7 预留。

### 3.5 协议没有提供的能力（不要尝试实现，只能让用户在设备屏幕上操作）

机组设置、自动递增、自动斜坡、温度控制、余量补正、真空测量、针头高度、
语言切换、版本信息、系统参数、LOCK 键。

`J` 指令（气源/材质/胶筒/适配器）可用 `DW` 覆盖，可不实现。

## 四、功能需求

### 4.1 必须实现

1. 串口枚举、打开/关闭、连接状态显示
2. 通信自检（只发 `>R?`，不切通道、不写参数）
3. 点胶参数读写：通道号 + 气压 + 时间 + 真空 + 模式；写入后**自动回读核对**，不一致报错
4. 执行点胶（`DI`）
5. 设备信息：一次读取 `DR` + `BP` + `BA`，结果写入日志（`BP` 失败单独捕获，不中断）
6. 报警读取（`FA`，按位解释）
7. 待机时间 / 活塞补正：写入 `WT` + `WH`，再用 `WQ` 回读核对
8. 点胶计数清零（`WZ`）、传感器校准（`S`）：均为破坏性/耗时操作，**必须二次确认**

### 4.2 行为约束

- 写入类操作成功后必须回读校验，不能只看 ACK
- 连接成功后自动读一次 `WQ`；若固件不支持（回 `Invalid command`）只记日志，不影响其他功能
- 通信超时后置"需重连"状态，提示用户断开重连，**不要自动重发命令**（半双工下迟到应答会被下一条命令误读）
- 同一时刻只允许一条命令在途（`lock`）
- 通道号范围 1~500，所有参数在本地先做范围校验，超范围直接报错不发帧

### 4.3 日志

每条命令一行，包含时间戳、方向、ASCII 与 HEX，例如：

```
[15:20:24.556] 发送 R?                        HEX: 3E 52 3F 0D 0A
[15:20:24.579] 接收 >R100^1000^0^0^
[15:20:25.001] 错误：设备拒绝 R：当前参数不可修改…
```

日志按类型着色：发送=深蓝、接收=深绿、错误=深红、其他=深灰。

## 五、界面要求（重要，之前的版本被多次打回）

**风格定位：工业设备控制软件**，不是互联网产品风。

必须避免（会被判定为"AI 味"）：
- 圆角卡片、投影、渐变按钮、胶囊标签、大字留白
- 大面积主色块、插画式空状态

要求：
- 原生 Windows 标题栏（不要 `FormBorderStyle.None` 自绘标题栏）
- 顶部一条浅色标题条：产品名 + 协议摘要 + 版本
- 下方标签页：**参数设置 / 设备功能**
- 标签页下是**功能区**：左侧随标签切换的大图标按钮（32px 图标 + 下方文字），
  右侧常驻"串口下拉 + 刷新 + 连接状态灯"
- 工作区是**淡水蓝渐变背景 + 带标题的框线模块**（框线 1px，标题压在框内左上角）
- 布局固定用 `TableLayoutPanel` 按行高排布（52/30/96/剩余），不要依赖 Dock 顺序
- 每类信息只出现一次：协议参数只在标题条，连接状态只在功能区右侧，版本只在标题条
- 页面里只放表单，动作按钮全部集中在功能区
- 日志区带"清空 / 复制"和颜色说明

## 六、代码结构

```
Sp900SerialClient.csproj
Program.cs                 入口
Sp900SerialClient.cs       协议层（核心，全部指令）
SerialPortConnection.cs    ISp900Connection 抽象 + SerialPort 适配器
Icons.cs                   GDI+ 画的 16x16 单色图标，按时传入 size 等比缩放
UiParts.cs                 RibbonButton / FramePanel / GradientPanel / TransparentPanel
MainForm.cs                界面与交互
```

要点：
- 协议层通过 `ISp900Connection` 抽象串口，便于用脚本化假串口做离线回放测试
- 界面所有通信都放在 `Task.Run`，避免阻塞 UI；异常统一 `MessageBox` + 日志
- 启用 `Nullable`，不留可空警告

## 七、必须做的验证（第二轮结束前）

写一个控制台自测工程，`<Compile Include="..\Sp900SerialClient.cs" />` 引入协议层源码，
用脚本化连接按序回放应答，至少覆盖：

1. `>R100^1000^0^0^` → 解析为 压力100/时间1000/真空0/模式0
2. `>ER:None.` → 判定成功
3. `>ERNone` → 判定成功（说明书写法兼容）
4. `>ER:Channel number error.` → 抛出"通道号不存在"
5. `>R...` 在期望反馈包的位置 → 抛出格式错误
6. `>WQ3^1^` → 待机 15 分钟、活塞开
7. 写入后回读不一致 → 抛错
8. 字段数不足 → 抛错

全部通过后，再手工在真机上按「测试通信 → 读取参数 → 设置参数」顺序验证一次。

## 八、已知坑清单（实现时逐条自检）

| # | 坑 | 对策 |
|---|---|---|
| 1 | 应答帧带前导 `>`，直接按 `R...` 解析必失败 | 解析前先剥 `>`，并校验它存在 |
| 2 | 实机 ACK 是 `>ER:None.`，说明书是 `>ERNone` | 去掉可选 `:` 前缀和 `.` 后缀后比较 |
| 3 | `Control.BackColor = Color.Transparent` 在 `SetStyle(SupportsTransparentBackColor)` 之前赋值会抛异常 | 先 SetStyle 再设背景 |
| 4 | 自绘按钮用父容器颜色清屏，父级透明时渲染成黑块 | 用自身 `BackColor` 清屏 |
| 5 | 透明面板与相邻框体区域重叠，会盖掉对方标题 | 页面与下方框体不要重叠，或统一给不透明底色 |
| 6 | `DW` 省略 D13~D16 可能清零 α/β/空管/满管补正 | 写入后如需保留补正，另用 `WB` 重设并在文档提示 |
| 7 | `M1` 开启补正会采样 5 次吐胶 | 超时按 5×点胶时间 + 余量动态计算，不要写死 60 s |
| 8 | 补正模式通道拒绝改参数 | 捕获 `parameters cannot be modified` 并提示去屏幕退出补正 |
| 9 | 机种名可能含非 ASCII 字节 | 该字段单独按 GBK 解码，其余保持 ASCII |
| 10 | 串口被其他程序占用 | 打开失败给出明确提示，不要静默重试 |
